# v1.43.0 RFC — Lexicon source loader: distribution format + composition

**Status:** APPROVED (2026-07-14)
**Author:** file-observer Claude · **Date:** 2026-07-14
**Version axes:** SCANNER 1.42.0→1.43.0 · LOGIC UNCHANGED (1.22.0) · SCHEMA UNCHANGED (1.23)

---

## 1. Motivation

The bring-your-own-lexicon observer (v1.38, extended v1.41) counts a consumer-supplied,
category-tagged term list in a file's body + metadata and reports per-category counts — the
guardrail-risk pre-screen a consumer runs *before* handing a file to an AI. But the way a consumer
**sources** that lexicon has not moved since v1.38: `--lexicon PATH` loads exactly **one flat JSON
file** (`parse_lexicon` → `{lexicon_id, categories:{cat:[terms]}}`, hashed to `dictionary_id`).

That single-blob model does not match how risk/blocklist term lists are actually distributed and
maintained. Today a consumer cannot:

1. **compose** several lists (e.g. a shared community list + a private overlay);
2. **maintain** terms in an ergonomic, human-curatable form (a JSON array is hostile to a long
   hand-edited list);
3. carry a list's **version / source / license** provenance;
4. detect **staleness or corruption** beyond the raw content hash.

This is the same split the ad-block / hosts-file ecosystems solved a decade ago (uBlock, EasyList,
StevenBlack): a *subscription* layer that composes many maintained lists, feeding a *matcher* that
consumes already-fetched local text. fo is the matcher. This RFC gives fo the loader half of that
split, **without** fo ever becoming the fetcher.

## 2. Measure-first — what a real distribution format carries

Characterizing EasyList/Adblock, uBlock, and hosts-file (StevenBlack/Pi-hole) distribution, five
threads recur; each maps to a concrete requirement (R) here:

| Real-format thread | Requirement |
|---|---|
| A metadata header (title, version, date, source/homepage, license, count) | **R1** a machine-parseable header on a text list |
| One entry per line + line comments | **R2** an ergonomic text term-list format |
| Categorization (per-file or in-file sections) | **R3** category sections in one file |
| Composition / subscription (an index of member sources) | **R4** compose N sources → one resolved lexicon |
| Versioning + integrity (version string + count/checksum) | **R5** load-time staleness/corruption signal |

**The load-bearing observation:** in every one of these systems the *matcher engine consumes
already-fetched local text* — the fetch/update lives in a separate subscription layer (uBlock's
engine never downloads; a subscription manager does). That is exactly the seam fo sits on: fo reads
local files deterministically; fetching/updating stays outside fo. R5's integrity need is *already*
half-met by fo's `dictionary_id` (a content hash → drift/tamper detection since v1.38).

## 3. Design

### 3.1 Two accepted formats (D1 = Both), one internal shape

Both formats normalize into the **existing** internal `{lexicon_id, categories:{cat:[terms]}}` — so
everything downstream (the matcher index, `dictionary_id`, the vector, the manifest) is unchanged.

- **JSON (canonical, machine)** — the v1.38 schema, extended with **optional** load-time-only header
  keys: `version`, `source`, `license`, `description`. These are read for load-time reporting and
  **do not enter the manifest and do not feed `dictionary_id`** (§3.4).
- **Text (EasyList-style, human-curated)** — chosen by content sniff / `.txt`/`.lexicon` extension:
  ```
  ! Title: my-lexicon          ← lexicon_id (also ! Lexicon-Id:)
  ! Version: 2026.07           ← load-time only
  ! Source: internal-curation  ← load-time only
  ! Description: ...
  [profanity]                  ← category section header
  banana
  cherry
  [secrets]
  placeholder-key
  ```
  Rules: `!` (and `#`) begin a comment; `! Key: value` in the header block populates load-time
  metadata; `[category]` opens a section; every other non-blank line is one term (verbatim, then the
  same normalization JSON terms already get — trim, dedup, sort). Literal terms only (no patterns) —
  preserving the ReDoS-safe matcher (v1.30.2 discipline). A term before any `[category]` → an error
  record (never silently bucketed).

### 3.2 Composition (D2 = multi-flag + index; defer `!#include`)

- **Multiple `--lexicon` flags** (`argparse action="append"`) — the safe primitive: fo loads each,
  then **unions** them into one resolved lexicon. Same category across sources → term sets merged +
  deduped. Union is **order-independent**: the resolved (sorted, deduped) set is identical regardless
  of source count or order, so `dictionary_id` is composition-stable.
- **An index file** (`--lexicon-index PATH`) — the "subscription": a small file listing member
  source paths (JSON `{lexicon_id, sources:[...]}` or a text `! index` with one path per line),
  resolved relative to the index file's own directory, each honoring `--root` when set (MCP). fo
  loads + unions the members exactly as multiple flags would.
- **Deferred: in-list `!#include <path>`** — it puts a filesystem path *inside* a list file (a
  traversal / cycle surface); the two explicit mechanisms above cover composition without it. Revisit
  on demand.

The composed lexicon still has **one** top-level `lexicon_id` (consumer-chosen for the whole; from
the first source's id, or an explicit `--lexicon-id`), one `dictionary_id`, one vector — identical in
shape to today.

### 3.3 What crosses into the manifest (D3 = provenance out)

**Nothing new.** Only the composed `lexicon_id` + `dictionary_id` reach the manifest, exactly as in
v1.38–v1.42. Per-source titles/versions/paths are **load-time only** (stderr summary + the CLI's own
diagnostics), never the manifest. Rationale: a list's *title* can itself signal intent (e.g. a list
named for the risk it screens), so keeping source identity out of the manifest is both a
contract-freeze win **and** the values-neutral / no-leak posture. This is the choice that keeps
LOGIC/SCHEMA frozen.

### 3.4 Versioning & integrity (D4)

- `version` / `date` / `source` / `license` are **load-time metadata only**. They are reported to
  stderr on load (`loaded lexicon 'my-lexicon' v2026.07 · 3 sources · 412 terms · dictionary_id ab12…`)
  and never enter the manifest.
- **`dictionary_id` stays content-anchored** — it hashes only `lexicon_id` + the sorted term set. A
  version bump with an identical term set produces the **same** `dictionary_id` (version is metadata,
  not identity); a term change moves it (drift/tamper detection, unchanged from v1.38).
- **Integrity check:** if a header declares an entry `count` that mismatches the parsed term count,
  fo emits a **stderr warning** — never a failure (deterministic; observe-don't-enforce).
- **No `expires` enforcement** — fo has no clock-based behavior (determinism). An `expires` header, if
  present, is surfaced to stderr and otherwise ignored; staleness is the subscription layer's job.

## 4. Versioning

A **loader upgrade**: the resolved lexicon (category→sorted deduped term set) and the `dictionary_id`
computation are behavior-identical for an equivalent term set. Therefore:

- A scan whose composed lexicon resolves to the same terms as an equivalent v1.42 JSON blob →
  **byte-identical manifest, identical `dictionary_id`.**
- No-lexicon scans are already byte-identical (gated feature).
- The existing single flat JSON still loads identically.

→ **LOGIC frozen (1.22.0), SCHEMA frozen (1.23), SCANNER 1.42.0→1.43.0** — the loader-ergonomics /
front-door precedent (v1.26 `scan()`, v1.39 MCP threading). The `--schema` surface is unchanged (no
new manifest field); the text/index formats are input contracts, documented in PUBLIC_CONTRACT but not
part of the manifest contract.

## 5. Bounds & safety (the new parser earns the v1.8.1 bar)

The text + index loaders are new input paths over consumer-controlled files → bounded / never-crash
from commit one:

- **Bounded file size** (reuse the lexicon file-read cap), **bounded line count and line length**,
  **bounded category count** (existing `LEXICON_MAX_CATEGORIES`) and **bounded total terms**.
- **Bounded composition** — a cap on member-source count; the index resolves paths within `--root`
  when set; no `!#include` → no cycle/traversal surface.
- **Literal terms only** — no regex/pattern terms, so the matcher stays ReDoS-safe (v1.30.2).
- **Fail-loud, never crash** — a malformed list / term-before-category / oversize input → a clear
  load error (CLI: message + nonzero exit, the v1.30 fail-loud precedent; MCP: a tool error), not a
  traceback and not a silent empty lexicon.
- **Values-neutral** — all fixtures use benign placeholder terms only; no real sensitive term is ever
  generated or committed (the standing lexicon discipline).

## 6. Testing (falsify-first, `test_v1_43.py`; benign lexicon only)

1. **Format equivalence** — a text list and a JSON blob describing the same terms → identical
   `dictionary_id` **and** byte-identical manifest.
2. **Composition determinism** — the same sources in any order / via flags vs index → identical
   resolved set + `dictionary_id`; workers 1-vs-N byte-identical.
3. **No-leak** — source titles / versions / file paths never appear anywhere in the manifest (canary
   strings in headers + filenames, asserted absent).
4. **Backward-compat** — a v1.42 single flat JSON loads to the identical `dictionary_id` it does today.
5. **`dictionary_id` semantics** — version bump with identical terms → same id; one term added → id
   moves.
6. **Bounds / never-crash** — oversize file, huge line count, term-before-category, malformed header,
   over-cap source count → clean load error / stderr warning, never a crash or unbounded read
   (red-verified).
7. **Integrity warning** — declared `count` ≠ parsed count → stderr warning, load still succeeds.

## 7. Non-goals / deferred

- **fo fetching / auto-updating over the network** — permanent non-goal (offline-deterministic
  charter). Distribution = fo reads local files; fetching/updating is the consumer's / a subscription
  tool's job.
- **In-list `!#include`** — deferred (traversal/cycle surface); the two explicit composition
  mechanisms cover the need.
- **Per-call MCP `lexicon_path`** — still deferred (v1.39 §6); the server-startup flag stays the
  locked-down primary. (An `--lexicon-index` at startup composes fine within that model.)
- **Source provenance in the manifest** — declined by design (§3.3).
- **Signature / source authentication** — integrity is the consumer's; fo offers `dictionary_id` for
  drift, not trust.
- **Obfuscation-resistance, per-field attribution** — separate parked lexicon backlog items,
  unchanged by this RFC.
