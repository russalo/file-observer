# v1.35.0 — AI-session per-model usage attribution (increment 3)

**Status:** Implemented (falsify-first). **Date:** 2026-07-08.
**Axes:** SCANNER 1.34.0→1.35.0 · LOGIC 1.18.0→1.19.0 · SCHEMA 1.20→1.21 · ai_session method_version 1→2.
**Measure-first:** `scratch/measure_per_model_usage_2026-07-08.md`.

## 1. Motivation
Both **trellis** (#57 — honest aggregate-by-model + exact model membership) and **recall** (by-model
demand) named per-model usage as the next pull from the AI-session arc. Today's `ai_session.usage` sums
across the WHOLE session plus a distinct `models` *set*, so a blended session (the scanner corpus itself:
opus-4-8 + opus-4-7 + opus-4-6 + fable-5) reports one indivisible number — tokens can't be attributed to a
model.

## 2. The measured basis (not assumed — the v1.33 lesson)
The load-bearing question: **is the model co-located with the usage block per turn?** If yes, per-model
attribution is a clean deterministic function; if no, it's interpretation fo shouldn't touch. Measured
**yes for all three vendors**, on the same per-turn field fo already reads:

| vendor | model | usage | co-located |
|---|---|---|---|
| Claude Code | `message.model` | `message.usage` | ✅ 100% of 25,713 turns |
| OpenAI Responses | `model` | `usage` | ✅ |
| Gemini generateContent | `modelVersion` | `usageMetadata` | ✅ |

## 3. What ships
A new provisional **`ai_session.usage_by_model`** — a deterministic list, each entry the same canonical
fields as the session `usage` block, per model:

```
usage_by_model: [
  {model: "claude-opus-4-6", turns_with_usage: N, input_tokens: …, output_tokens: …,
   cache_read_tokens: …, cache_creation_tokens: …, reasoning_tokens: …, total_tokens: …, raw_keys: […]},
  {model: "claude-opus-4-8", …},
  {model: null, …}          # usage-turns with no model / cardinality overflow
]
```

- **Invariant (load-bearing, tested):** `usage` == elementwise sum of `usage_by_model`. The tested v1.33
  session path is left UNTOUCHED (per-model is computed separately, same `token_at`/`AI_SESSION_USAGE_MAP`),
  so the session `usage` block stays byte-identical — only the new field is added.
- **Model verbatim** (Claude `message.model` / OpenAI `model` / Gemini `modelVersion`), **including
  non-model markers** like `<synthetic>` (observe-don't-interpret — fo emits the field as-is; the
  interpreter decides what's a "real" model; filtering would be interpretation).
- **Null bucket:** a usage-turn naming no model → `model: null`. A hostile per-turn-unique-model log folds
  overflow beyond `AI_SESSION_MAX_MODELS` distinct models into null (sums stay complete → invariant holds),
  bounding output (the v1.8.1 bounded-observation discipline).
- **Order:** real model strings sorted ascending, the `null` bucket last (deterministic).
- **Never priced** — sums only, per model (the bright line; the whole federation stack is fo observes →
  trellis indexes → recall scopes/cites → interpreter judges).

## 4. Consumer contract (why this shape)
- **trellis:** a list of `{model, …usage}` flattens via v0.28's recursive-flatten; **exact model membership
  (#57)** is satisfiable — each entry names one model verbatim, no substring guess.
- **recall:** `usage --by-model` folds on the entries; the null/marker buckets are visible + skippable per
  the null-skip discipline.

## 5. Versioning
- New provisional field in an existing namespace → **SCHEMA 1.20→1.21** (additive; the v1.20/v1.33 precedent).
- Values move `manifest_checksum` on ai_session corpora → **LOGIC 1.18.0→1.19.0** (the v1.29/v1.33 values-move
  precedent; no routing flag flips, is_chatlog/ai_session detection unchanged).
- **ai_session method_version 1→2** — per-model grouping is a new block rule → feeds the ai_session rules_hash.
