# File Observer v1.4.0 RFC Specification

> **Status: Specification (approved 2026-06-02; revised in implementation — see §1.3).**
> Design exploration and the three forking decisions are recorded in
> `scratch/review/v1_4_0_chatlog_signal_design.md` (internal, not committed).

## 1. Overview

### 1.1 Purpose

Add a **content-shape gate** to prose chatlog detection. The count-based prose
rule (*N distinct, M total, ≥1 recurring, minus a stop-list*) cannot tell a
recurring **data** label (`Item:`/`Price:`) from a **speaker** — any cyclic
`Key: value` block counts as a conversation. v1.4.0 asks an additional question:
*"does the text after the colon read like an **utterance**, or like a **field
value**?"* A speaker turn is a phrase (it has function words, sentence
punctuation, or length); a data value is atomic (`Apple`, `1.00`, `localhost`).
The content-shape gate rejects the cyclic-data false-positive class while
admitting terse-but-real dialogue (including short RPG turns) via the
function-word and punctuation arms.

### 1.2 What v1.4.0 is — an ADDITIVE layer, not a replacement

The content-shape gate sits **on top of** the retained v1.2.4 machinery
(non-speaker stop-list → count floor). It adds:

- **(a)** a content-shape gate (`utterance_ratio ≥ 0.6`) on the prose rule —
  rejects cyclic data tables (the motivating FP);
- **(b)** a closed FP-lexicon dominance rule — rejects `Added:`-style changelogs;
- **(c)** a density floor — rejects labels sprinkled in prose (admonitions);
- **(d)** a version/date structure vote-against — rejects multi-version release notes;
- **(e)** a FAQ complete-set exclusion (`{question,answer,q,a,faq}`);
- **(f)** provisional observed fields `utterance_ratio` / `density` (RFC §7).

### 1.3 Revised in implementation (falsification, 2026-06-02)

The approved draft claimed content-shape would **replace** the stop-list
(`utterance_ratio` "redundant-izes ~30 header/field tokens"). **Real-data
falsification overturned that claim** and the implementation was corrected with
Russell's per-decision sign-off:

- **The header stop-list is load-bearing and is RETAINED.** Doc-section labels
  (`Usage:`, `Authorization:`, `Note:`) carry sentence content, so a content-shape
  co-signal false-positived on docs with `### ` headers (6 real READMEs/CLAUDE.md
  in a 2,491-file doc corpus). Dropping the stop-list was reverted.
- **On real data v1.4.0 == v1.2.4** (0 detection diff across 3,032 real doc + chat
  files). The content-shape gate changes behavior only on *adversarial* inputs
  (cyclic data tables, `Q:/A:` FAQs, `Added:` changelogs, multi-version release
  notes) — which v1.2.4 false-positived but which are low-incidence in practice.
  The net is **adversarial-FP robustness**, not a real-world FP reduction.
- **`utterance_ratio` alone could not separate terse dialogue from data** (both
  near 0.0). A **function-word arm** was added to the utterance predicate (natural
  utterances contain function words; atomic data values do not) — this preserves
  realistic terse dialogue (incl. RPG/Sentinel) and is the genuine discriminator.
- **Recurrence is retained** (decision Q3), so the all-distinct multi-party
  roll-call remains an accepted FN — the draft's "too strict" framing does not
  apply to the shipped design.
- **Ultra-terse contentless dialogue** (`hi`/`hello`/`bye` — no function word,
  punctuation, or length) is irreducibly ambiguous with atomic data and is an
  accepted FN (§2.3, LIMITATIONS).

### 1.4 Normative Language

MUST / SHOULD / MAY per BCP 14.

## 2. The Content-Shape Gate

### 2.1 The utterance predicate

Prose detection first collects `^Label: content` lines (`CHATLOG_LABEL_CONTENT_RE`)
and **filters out non-speaker stop-list labels** (the retained v1.2.4 list — §1.3).
For each surviving line, the post-colon `content` is **utterance-like** when ANY arm holds:

```
ends in sentence punctuation (. ! ?) after a letter      # "I attack!", "Roll for it."
OR contains a function word                              # "hi *there* friend", "*how are you*"
OR words(content) >= 4
OR len(content) >= 25
```

The **function-word arm** is the discriminator that separates terse dialogue from
data: natural utterances contain function words (articles, pronouns, prepositions,
conjunctions, aux/wh-words — a closed standard-English class), while atomic data
values (`John Smith`, `1.00`, `localhost`, `admin`) contain none. `utterance_ratio`
= (utterance-like lines) / (surviving label lines). Thresholds are fixed constants,
recorded in `CHATLOG_RULES_DEFINITION` so a future tuning change is visible in the
vector identity.

### 2.2 Prose rule (count floor + content-shape gate)

A text matches the prose chatlog rule when ALL hold (labels stop-list-filtered first):

1. **Structural floor** — ≥2 distinct labels, ≥3 total label lines, **≥1
   recurring** label (recurrence retained — decision Q3).
2. **FAQ complete-set** — the distinct set is NOT a subset of `{question,answer,q,a,faq}` (§4).
3. **Content-shape** — `utterance_ratio ≥ 0.6` (rejects cyclic data tables).
4. **FP-lexicon** — the FP lexicon does NOT dominate the distinct labels (§3.3).
5. **Density** — `density ≥ 0.5` (§3.1).
6. **Structure** — fewer than 2 version/date section headers (§3.2).

### 2.3 Accepted false negatives

- **All-distinct multi-party roll-call** — recurrence retained (Q3), so 4 speakers
  each once is rejected. Real multi-party dialogue almost always recurs; dropping
  recurrence reopens the changelog FP. Accepted (LIMITATIONS.md).
- **Ultra-terse contentless dialogue** (`hi`/`hello`/`bye`) — no function word,
  punctuation, or length, so `utterance_ratio` is 0.0, identical to atomic data.
  Irreducibly ambiguous; real chat is substantive. Accepted (LIMITATIONS.md).
- **`Q:`/`A:`-labeled published interviews** — the cost of FAQ exclusion (Q2).

## 3. Prose-FP Defenses (the hard residual)

`utterance_ratio` cannot reject changelogs/admonitions (sentence content). Three
co-signals, belt-and-suspenders (decision Q1):

### 3.1 Label-line density

`density` = (label lines) / (non-blank lines). Dialogue ≈ 1.0 (turns dominate);
admonitions ≈ 0.4 and changelogs ≈ 0.75 (labels sprinkled among prose / version
headers). A density **floor** (≥ 0.5, fixed constant) rejects prose-interspersed
admonitions. Density alone is insufficient (the changelog at 0.75 overlaps
dialogue) — hence the lexicon below.

### 3.2 Structure co-signal vote-against

When the sample contains version/date section headers
(`## [1.2.0]`, `## 1.2.0 - 2026-01-01`, ISO-dated `##` headers), that is a
**vote against** chatlog (changelog / release-notes / dated journal). This
generalizes the existing v1.2.1 decision to *drop* the date-header co-signal for
the structure rules — here it is used in the opposite direction, as a negative
signal, which is correct: a dense run of dated section headers is the signature
of release notes, not a transcript.

### 3.3 Small closed FP lexicon

One small, **named and closed** lexicon for the empirically-confirmed prose-label
FP class (distinct from the retained non-speaker stop-list — §1.3):

- **Admonition words:** `note, warning, tip, caution, important, example,
  examples, todo, fixme, result, error`
- **Changelog verbs (Keep a Changelog):** `added, changed, deprecated, removed,
  fixed, security`

Rule: if the distinct label set is **dominated** by this lexicon (≥ half the
distinct labels are members), reject. The changelog verbs are NOT in the
non-speaker stop-list (so a changelog clears the count floor), which is why this
dominance rule is needed. Closed by two real specifications (admonition
conventions, Keep a Changelog), not corpus accretion.

## 4. FAQ Exclusion (decision Q2)

A FAQ (`Question:`/`Answer:` + sentence answers) is structurally identical to an
interview transcript; `utterance_ratio` is 1.0 for both. Exclude FAQs via a
**complete-set** test: if the distinct label set ⊆
`{question, answer, q, a, faq}`, reject.

This threads the needle the current code worried about
(`scanner.py:674`): `A:`/`B:` anonymized dialogue has label set `{A, B}`, and
`B` ∉ the set, so `{A, B}` is **not** a subset → survives. `Q:`/`A:` FAQ has
`{Q, A}` ⊆ the set → rejected.

**Documented cost (LIMITATIONS.md):** published Q&A interviews that label turns
with literal `Q:`/`A:` become false negatives. Accepted: the alternative
(topical-continuity analysis) crosses the observe→interpret boundary
(`project-sentinel-use-case`), and identity-labeled interviews
(`Interviewer:`/`Guest:`/names) are unaffected.

| Q2 | FAQ vs interview | **exclude** FAQ via complete-set `{question,answer,q,a,faq}`; document Q&A-interview FN |

## 6. JSON / JSONL path

**Unchanged.** The conversational-JSON detector (`_detect_conversational_json`,
v1.2.x) already keys on role+content structure, not label counting, and carries
the v1.2.1 distinct-speaker hardening. No change in v1.4. (`_string_has_speaker_dialogue`,
which applies prose Rule 1 to dialogue embedded in a JSON string, MUST adopt the
same revised predicate as §2.2 so embedded and standalone dialogue stay in parity
— this is the one JSON-adjacent edit.)

## 7. New Observed Signal (provisional)

Surface `utterance_ratio` and `density` (each rounded to 3 dp) under a
`content_shape` object in chatlog specialist metadata as **provisional** observed
fields (null in JSONL mode, where the JSON path decides). Rationale: they are
drift-visible (they explain *why* detection fired/didn't), Sentinel-relevant
(content-shape is a session-character signal alongside `alternation`), and
on-brand (report the observation; don't conclude). Additive only.

## 8. Schema & Version Constants

- `SCANNER_VERSION` 1.3.0 → **1.4.0** (detection behavior change).
- `LOGIC_VERSION` 1.2.0 → **1.3.0** (new detection routing — minor logic change).
- `SCHEMA_VERSION` 1.2 → **1.3** (additive: provisional `utterance_ratio` /
  `density` fields in chatlog metadata, §7). v1.0 contract holds — no field
  removed/renamed/retyped.
- `CHATLOG_METHOD_VERSION` 8 → **9** (detection logic change → vector identity
  change). `CHATLOG_RULES_FINGERPRINT` updated to reflect the new predicate and
  the content-shape/density thresholds.

## 9. Backward Compatibility

- **Detection changes by design** — this is the `LOGIC` bump. Files newly
  detected: all-atomic-value blocks that previously FP'd now correctly reject;
  prose changelogs/admonitions that previously FP'd now reject. Files newly
  *missed*: the documented FNs (§2.3, §4). Net: fewer FPs, two narrow accepted FNs.
- **Golden manifests MUST be regenerated**; every `is_chatlog` flip MUST be
  reviewed as either a fixed FP or an accepted FN — never an unexplained
  regression.
- **`chatlog` vector identity changes** (`method_version` 9) — expected and
  correct; consumers keying on the digest re-baseline.
- No manifest field removed/renamed/retyped. v1.0 public contract holds.

## 10. Validation Plan (falsify-first — `feedback_falsify_dont_confirm`)

Build the adversarial corpus **before** implementing. The labeled FP/TP set MUST
include, at minimum:

- **FP must-reject:** email/usenet headers (incl. ALL-CAPS), data tables, config
  blocks, tech-doc field lists, multi-version changelogs (dense + sparse),
  admonition-in-prose docs, FAQ (`Question:`/`Answer:` and `Q:`/`A:`),
  man-page sections, language/UTF-8 demo dumps.
- **TP must-accept:** Human/Assistant, named 2-party and 3-party dialogue,
  identity-labeled interviews, `A:`/`B:` anonymized dialogue, dialogue embedded
  in JSON strings, the real `corpora_chat/` set.
- **Documented FN (assert they are missed, on purpose):** all-distinct
  roll-call multi-party; `Q:`/`A:`-labeled published interview.

Gate: run the corpus harness AND the full suite (currently 595+ tests) AND the
three review layers (in-house multi-agent, Gemini cross-model, PR bots) before
merge. The reviewer is told the change is a detection-logic change and pointed at
the FP corpus — try to break it before shipping.
