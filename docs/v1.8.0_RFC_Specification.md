# File Observer v1.8.0 RFC Specification

> **Status: Specification (approved 2026-06-04).** Third and final of the post-v1.5
> three-minor arc (v1.6 provenance → v1.7 structural-anchor reader → **v1.8 the
> per-format parser fork**). v1.7 *locates* a PDF's index but cannot decode the
> compressed structures (xref streams + object streams) that **57% of the
> infra-standards corpus** uses — so those PDFs return `page_count = null`. v1.8
> decodes them.
>
> **Central fork (§4) resolved at approval: B with an A fallback** — a tiered
> cascade. Primary: an optional parser (`pypdf`) for `page_count` + `/Info`, gated
> like `olefile`. Fallback (no dep present): an in-house **stdlib** decoder (zlib +
> predictor + `/W` xref + `/ObjStm`). Then v1.7's best-effort null. So the scanner
> gains object-stream `page_count` **whether or not** the optional dep is installed
> — robust when present, still capable when absent, never worse than v1.7. The
> stdlib path is **cross-validated against pypdf as an oracle** (§6).

## 1. Overview

### 1.1 Purpose

Decide and implement how File Observer recovers `page_count` (and, where cheap, the
existing `/Info` fields) for **object-stream PDFs** — the PDF 1.5+ files whose
cross-reference table and/or page tree are compressed into streams that v1.7's
byte-level reader deliberately does not decode.

v1.7 established the structural index (`startxref` → xref → trailer → root → page
tree) and reads it for **classic** PDFs. For **xref-stream** PDFs it reads the
plaintext xref-stream *dict* (recovering `/Info`/producer when the object is
regular) but reports `page_count = null` — an honest "not observed" — because the
cross-reference offsets and often the page tree live in **compressed** streams. On
`corpora_infra`, `xref_type` measured **373 / 655 PDFs (57%) as `stream`**; a rough
probe found **~43% of sampled object-stream PDFs carry `/ObjStm`** (objects nested
inside compressed object streams — the deepest layer). v1.8 closes (some or all of)
that null population.

### 1.2 The decode layers (what "object-stream" actually requires)

To get `page_count` from an object-stream PDF, in order of depth:
1. **Inflate the xref stream** — `FlateDecode` (stdlib `zlib`), then undo the PNG
   **predictor** (`/DecodeParms /Predictor /Columns`) to recover the raw bytes.
2. **Parse the binary cross-reference table** — fixed-width records per `/W [t a b]`
   over the `/Index` subsections → object number → (type, offset|stream, index).
3. **Resolve the root catalog → `/Pages` → `/Count`.** If those objects are
   **regular** (uncompressed), v1.7's offset resolution already reaches them once we
   have the offsets from step 2. If they are inside an **object stream**
   (`/Type /ObjStm`), add:
4. **Inflate + parse the object stream** — a compressed container of N objects with
   a header table (object number → offset within the stream) → extract the target
   object → `/Count`.

Layers 1–2 are bounded binary parsing (stdlib-feasible). Layers 3–4 are where the
"regex-over-bytes ceiling" the roadmap warned about genuinely falls — this is PDF
parsing, with predictors, multiple `/W` encodings, free/compressed entry types,
and hybrid-reference files.

### 1.3 Normative Language

MUST / SHOULD / MAY per BCP 14.

## 2. Scope discipline (what v1.8 is NOT)

v1.8 fills **existing fields** (`page_count`, and `/Info`: producer/creator/title/
creation_date) for object-stream PDFs. It MUST NOT:
- extract text, layout, or rendered content (that is not the observer's lane);
- add new manifest fields beyond what's needed to report the recovered values
  (`xref_type` already exists; see §5 for an optional `pdf.parser` provenance hint);
- change any routing flag (`requires_vision`/`requires_specialist_tool`) — so
  `LOGIC_VERSION` SHOULD stay 1.4.0, like v1.6/v1.7. (Confirm during the build: if a
  decode flips `requires_vision` on a born-digital object-stream PDF that was
  mis-flagged, that *is* a routing change → LOGIC bump. Watch for it.)

Observe the index more deeply; do not become an extraction/OCR tool.

## 3. The choice of mechanism (the central decision)

### 3.1 Determinism note (applies to all options)

Today the manifest's determinism already depends on environment libraries captured
in `ScanContext` (libmagic, chardet versions). Any decode added by v1.8 must be
deterministic for a fixed `ScanContext`. An **optional dependency** (option B)
becomes such a captured dependency (its version recorded in `ScanContext`, like
libmagic) — acceptable and precedented, but it means two environments with
different parser versions may legitimately differ (explained by context, per the
v0.3 determinism pillar).

## 4. Mechanism — RESOLVED: B with an A fallback (a tiered cascade)

For each object-stream PDF whose `page_count`/`/Info` v1.7 left null, try in order;
the first tier that returns a value wins, and each tier MUST degrade (never raise)
to the next:

1. **`pypdf` (optional dependency), if importable** — the primary path. Call it for
   `page_count` + `/Info` ONLY (scope §2), wrapped and bounded (no network, no JS;
   strict=False; treat it like the `olefile`/`defusedxml` gated imports). A mature,
   hardened parser handles every encoding/predictor/hybrid-ref/malformed edge.
2. **Stdlib in-house decoder (no dependency)** — the fallback when `pypdf` is absent.
   Implement decode layers 1–4 (§1.2: `zlib` + PNG predictor + `/W`/`/Index` binary
   xref + `/ObjStm`) for the common cases; **accept null on exotic inputs** (rare
   `/W` forms, encryption, corruption) rather than chase every edge — pypdf is the
   robust path, this is "works without the dep." Cross-validated against pypdf (§6).
3. **v1.7 best-effort → null** — when neither tier yields a trustworthy value
   (honest "not observed within bounds").

### Why this over plain B or plain A
- Plain **B** would return null in any environment without `pypdf` installed — but
  the **~43% `/ObjStm` probe** says that's a large, real population we *can* serve
  with stdlib. The A-fallback makes object-stream `page_count` work **out of the box**.
- Plain **A** would carry the full edge-case burden as our bug forever. With pypdf
  as the primary path AND the validation oracle, the stdlib decoder can be **scoped
  to the common cases** and proven correct against pypdf — far lower risk than A alone.
- **C** (xref-stream-only, skip `/ObjStm`) is rejected: the probe shows it leaves
  most of the population null — worst effort:coverage.

### Costs accepted (stated, per the guardrail)
- Two code paths to build + maintain (the pypdf wrapper AND the stdlib decoder).
  Mitigated: the wrapper is tiny (two facts); the stdlib decoder is scoped to common
  cases and validated by the oracle, not held to pypdf's completeness.
- `pypdf` is a new (heavier) optional dependency — BSD-licensed (compatible),
  pure-Python, recorded in `ScanContext` (like libmagic/chardet). `pip install
  file-observer[pdf]` extra; core install stays lean.
- A PDF could resolve via pypdf in one environment and via the stdlib decoder in
  another → they MUST agree (the §6 oracle test enforces this on the corpus), so the
  observed value is stable; *which tier* produced it is recorded by `pdf.parser` (§5).

## 5. Schema & Version Constants

- `SCANNER_VERSION` 1.7.0 → **1.8.0**.
- `LOGIC_VERSION` **unchanged (1.4.0)** expected — filling `page_count`/`/Info` is
  specialist extraction (§2). Bumps only if a decode changes a routing flag (watch
  for a born-digital object-stream PDF whose `requires_vision` flips).
- `SCHEMA_VERSION` 1.6 → **1.7** — additive provisional **`pdf.parser`**
  (`"pypdf"` / `"stdlib"` / `"none"`), recording which tier produced the value. With
  a two-tier cascade this is worth surfacing: it makes the pypdf-vs-stdlib split (and
  the remaining-null population) **measurable**, and lets a consumer see whether a
  value came from the hardened parser or the in-house fallback. (`xref_type` stays
  the structural observable; `pdf.parser` is the decode observable.)
- `ScanContext` gains the `pypdf` version when present (a captured dependency like
  libmagic/chardet). The v1.7 `pdf_signal` sweep dimension gains a `page_count_present`
  jump + a per-tier (`parser`) breakdown that the empirical gate measures.
- v1.0 public contract holds — no field removed/renamed/retyped.

## 6. Validation Plan (falsify-first, and *measure the payoff first*)

The honest open question is **how much the cascade actually recovers** — the 57% is
the ceiling, not the yield. So the build's FIRST step is measurement, before
committing the full stdlib decoder:

1. **pypdf-as-oracle on `corpora_infra` (do this first).** Install `pypdf`, get its
   `page_count` for all 373 object-stream PDFs. This single pass yields: (a) the real
   payoff (how many recover, and the value to publish), (b) the **ground-truth oracle**
   the stdlib decoder must match, and (c) spot-check targets. If pypdf itself can't
   read some (encrypted/corrupt), those define the honest residual.
2. **Build the stdlib fallback decoder, validated against the oracle.** The
   falsify-first gate is **exact agreement with pypdf** on `corpora_infra`: every PDF
   the stdlib decoder returns a `page_count` for MUST equal pypdf's, or it's a bug.
   The stdlib decoder MAY return null where pypdf succeeds (scoped to common cases) —
   but MUST NEVER return a *different* value. Report the stdlib-vs-pypdf coverage gap.
3. **Falsify-first unit cases** (byte-accurate synthetic object-stream PDFs), run
   against BOTH tiers: xref stream with a PNG predictor; multiple `/W` encodings; a
   page tree inside an `/ObjStm`; a hybrid-reference PDF (classic xref + `/XRefStm`);
   a malformed/truncated stream (degrade to null, never raise); an encrypted
   object-stream PDF (stays null). Plus a **dependency-presence matrix**: each case
   with `pypdf` importable AND force-absent (monkeypatch the import) → the cascade
   picks the right tier and the values agree.
4. **Zero-regression** on the classic + xref-stream-regular paths v1.7 already
   handles — the decode is purely additive (null → value), never value → change.
   Re-validate `corpora_infra` (page_count_present rises; 0 changes to any non-null
   v1.7 value).
5. **Full suite + the four review legs** + extend the empirical sweep's `pdf_signal`
   to track the per-tier `pdf.parser` breakdown (and stay deterministic for a fixed
   `ScanContext` / pinned pypdf version).

## 7. Closing the arc

v1.8 ends the post-v1.5 three-minor arc: v1.6 added the provenance *dimension*, v1.7
built the structural *road* to the index, v1.8 *decodes* the compressed index. After
it, the PDF specialist reports `page_count` for the full corpus (under A/B) or a
measured, documented remainder (under C) — and the "regex-over-bytes ceiling" is
resolved by an explicit, reviewed choice rather than silent erosion.
