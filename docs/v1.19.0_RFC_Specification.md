## 1. Motivation

The scanner has two human-readable needs, both currently under-served:

- **"What did THIS scan find?"** — the per-scan `summary` field (`_build_summary`, v0.10). It
  is **frozen at ~v1.10 coverage**: it omits the `provenance` vector (v1.6), the entire
  capture-metadata story (v1.16/1.17/1.18 — geotagged, capture devices, video), and
  `preservation` (v1.10); it reports safety flags only as a *count*, never named. Accurate
  but blind to six minors of new observation.
- **"What CAN this tool observe?"** — `--schema` (v1.13) answers this completely, but only in
  *structured* form (JSON / a reference-table Markdown). There is **no readable, prose
  account** a person can skim to understand the full surface. The structured `--schema` is
  for machines and drift-guards; a human wants narrative.

v1.19 closes both: refresh (A) and add the prose-schema (B).

## 2. Scope

### (A) Freshen the per-scan `summary`
Surface the dimensions it currently misses, staying a short deterministic Markdown paragraph
(the v0.10 shape — not a wall of text):
- **`provenance` vector** — named in the vector line like every other vector (toolchains /
  production years / digitization). *The clearest omission — it's the only vector skipped.*
- **Capture metadata** — a line when present: e.g. "N geotagged files; captured by {devices}"
  (devices = distinct `image`/`video` make/model). Surfaces the v1.16–v1.18 story.
- **Named safety flags** — break the bare count into the actual flags present (e.g.
  "geotagged ×N, has_macros ×M"), so the disclosure is legible.
- **`preservation`** — a brief note if any obsolescence-flagged formats are present.

### (B) Human-readable `--schema` equivalent
A new **prose** rendering of the introspected surface (reusing the v1.13 introspection
registries — specialists, namespaces + fields, vectors, safety_flags, error codes,
provenance triggers, format signatures, MIME tiers, preservation tiers, subcategories). It
reads as an explanation ("File Observer can observe… For images it extracts… Safety flags it
may raise…"), not a field table. Same completeness as `--schema`, readable form.

### Out of scope
- No new *manifest* fields (the scan `summary` is an existing field; (B) is a separate
  read-and-exit surface like `--schema`).
- No change to what is *observed* — purely how it's *described*.

## 3. Design

### (A) `_build_summary`
Extend the existing builder: add `provenance` to the vector line; add a capture-metadata line
(derive geotagged count from `safety_flags`, devices from `image`/`video` make/model); expand
the safety-flag count into named flags; add a `preservation` note. Deterministic, ordered,
bounded — same discipline as the current builder.

### (B) the prose schema
A new format on the existing self-description surface — **`file-observer --schema --format
summary`** (working name; §8 Q2) — that walks the *same* introspected registries `--schema`
already builds and emits a readable narrative. Reuses the v1.13 introspection (single source
of truth — so it can't drift from the structured `--schema`). Manifest byte-identical; a
separate read-and-exit path.

## 4. Versioning

- SCANNER 1.18.0 → **1.19.0**.
- **LOGIC 1.8.0 → 1.9.0** — (A) changes the `summary` *string*, which feeds
  `manifest_checksum` (a v1.8.2-class determinism surface) → an observed-value change.
- **SCHEMA unchanged (1.12)** — no new manifest field; `summary` is an existing field (richer
  content, same type). (B) is a separate surface (the `--schema` precedent: a new format is
  not a SCHEMA change).
- `docs/SCHEMA.md` regenerated only if (B) adds an enumerable element (it doesn't — it's a
  view over existing registries).

## 5. Validation
- **(A)** falsify-first: golden summary strings for scans exercising provenance / geotagged /
  named-flags / preservation; determinism (two scans identical); workers byte-identical.
- **(B)** completeness: the prose-schema must mention **every** element the structured
  `--schema` enumerates (a test asserting no registry element is dropped — the v1.13
  completeness discipline), and be deterministic.
- Corpus sweep: the `summary` string change is expected drift (LOGIC bump) — review it, and
  re-baseline; confirm no *other* drift.

## 6. Open questions — RESOLVED at sign-off 2026-06-16 (Russell)
1. **Interpretation** → **(A)+(B), confirmed.** The per-scan summary AND a readable
   build-capability summary.
2. **(B) surface/naming** → **`--schema --format summary`** — a new format under the existing
   self-description flag, reusing the v1.13 introspection (no new top-level surface).
3. **(A) content** → **name the `provenance` vector + a geotagged/devices line; keep
   toolchain/year detail inside the vector mention**, not spelled out in the prose.
4. **(A) length** → **tight — one short line per dimension, skip absent ones** — **AND comment
   on the ambiguous.** Where a signal is uncertain or in tension, the summary SAYS so rather
   than presenting a falsely-clean count: content-vs-extension **MIME mismatches**,
   **polyglots**, **degraded** extractions (honest-null-heavy), and similar disagreements get
   a brief honest note (observe-don't-interpret: surface the uncertainty, don't paper over it).
   The summary should read honest, not marketing-clean.
5. **Ship together** → **v1.19 = (A)+(B).**
