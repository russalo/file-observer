# v1.49.0 — Chatlog detection: content shape where counting still decides

**Status:** SHIPPED as **case C only**. Cases A and B were **FALSIFIED during
implementation** and are recorded below with the measurements that killed them.
Approved 2026-08-09; Sentinel coordination cleared (§8 D3).

> **Read §3.1 and §3.2 before re-attempting either.** Both look obviously right on
> paper. Both were implemented, both broke real cases, and the evidence is preserved
> here specifically so the next person does not pay for that discovery twice.

## 1. Summary

The chatlog detector still decides three cases by **counting** — how many speaker
labels, how many recur, how many JSON objects — where the honest evidence is **what the
content looks like**. That is the "non-count signal" the v1.2.x arc identified in
2026-06 and parked as a design item rather than a patch.

v1.4.0 already introduced the content-shape gate (`utterance_ratio`) and it works. This
release does not invent a new signal; it **extends the existing one to the three paths
counting still governs**.

Scope is deliberately three measured cases. Not a rewrite.

## 2. Provenance & grounding (measure-first)

### 2.1 What v1.4 already fixed

The 2026-06 brief (`scratch/review/v1_2_2_fp_findings.md`, corroborated independently by
Gemini flash and pro) enumerated the false-positive class. **Measured against v1.48.1
today, most of it is closed:**

| Brief's FP case | v1.48.1 |
|---|---|
| FAQ `Question:`/`Answer:` | ✅ not detected |
| `Item:`/`Price:` recurring data keys | ✅ not detected |
| Embedded example dialogue in `CONTRIBUTING.md` | ✅ not detected |
| ALL-CAPS mail headers `FROM:`/`SUBJECT:` | ✅ not detected |

The function-word veto in `utterance_ratio` is doing the work it was built for. This
RFC does not touch it.

### 2.2 What is still wrong — the entire scope of this release

| # | Case | v1.48.1 | Correct | Class |
|---|---|---|---|---|
| **A** | `###`×5 + non-utterance labels — a **CLASS**, ≥3 measured instances: tech doc (`Platform:`/`Status:`), version-tag release notes (`Release:`/`Status:`), dated journal (`Mood:`/`Weather:`) | `True` | `False` | **FP** |
| **B** | Four speakers, each appearing once | `False` | `True` | **FN** |
| **C** | A two-turn JSON session | `False` | `True` | **FN** |

- **A** is the brief's "residual (a)" — Gemini pro rated it MED and was less sanguine
  than flash's "acceptable". Still live, and **larger than first scoped**: writing the
  non-regression battery before implementing (§5) revealed that release-notes and dated-
  journal shapes I had *assumed* were already rejected are in fact detected today, by the
  same mechanism. One fix closes all of them; the value of A is correspondingly higher
  than the original single case suggested. Falsify-first found this, not review.
- **B** is the recurrence rule's deliberate trade-off, flagged independently by both
  models as a real FN.
- **C** is the `≥3` message-object floor, quantified in 2026-07 against **LongMemEval**
  (a decorrelated, public corpus): detection is **99.3%** with exact turn counts, and
  the *entire* residual is this floor — crisply **0/7 at two turns, 100% at ≥3**.
  recall's 5.9% miss at 19,195-file scale is the same tail.

### 2.3 An open item from the brief, now closed

The brief flagged *"convokit = 0 flagged — possible false negative"*. Measured: the
corpus is 444 files of **ConvoKit's library source** (180 `.py`, 103 `.rst`, 74
`.ipynb`), not conversational data. **Zero is correct.** Not a miss; struck from the
residual list.

### 2.4 Why the RPG-corpus gate no longer applies

This work was gated on a tagged RPG corpus that never arrived. LongMemEval supplies what
that gate existed to provide, and arguably better: a real-world, **outside-our-own-data**
dialogue distribution, at scale, with the failure population quantified and its mechanism
known. The gate is met by a different route.

## 3. Design — extend content shape, add nothing new

The unifying claim: **where a count currently decides, require the content to look like
an utterance instead.**

### 3.1 Case A — the structure rule ignores what its labels contain

The 5+ H3 structure rule fires with a speaker co-signal of 2+ *distinct* labels.
`Platform: Linux` and `Status: Draft` satisfy it. But those values are single words with
no function word, no sentence punctuation, and no length — precisely what
`utterance_ratio` was built to reject, and it is simply **not applied on this path**.

**Proposed fix:** apply the existing utterance test to the structure rule's co-signal.

### ❌ FALSIFIED AT IMPLEMENTATION — do not re-attempt without new evidence

Implemented, it rejected the tech-doc FP **and also rejected real terse transcripts.**
`tests/test_v1_2_1.py::test_markdown_transcript_with_speakers` — a 2026-era regression
guard — caught it on a fixture of exactly this shape:

    ### Scene 1
    Alice: hi
    ### Scene 2
    Bob: hello

Measured, which is what settles it:

    _is_utterance('hi')    = False        _is_utterance('Linux') = False
    _is_utterance('hello') = False        _is_utterance('Draft') = False
    _is_utterance('more')  = False        _is_utterance('cold')  = False

The gate's discriminating power is function words, sentence punctuation, and length.
**Terse dialogue has none of those either**, so the two populations are identical to it.

v1.4.0's own docstring already said this — *"ultra-terse contentless dialogue ('hi'/
'bye') … is irreducibly ambiguous with atomic data."* We rediscovered a documented fact
by not reading it. The FP stays; it is a **documented residual, not an oversight**.

### 3.2 Case B — recurrence is the wrong proxy for dialogue

The rule needs ≥1 recurring speaker, so four people speaking once each reads as
not-dialogue. But recurrence is a proxy for **alternation**, and alternation is directly
observable.

**Proposed fix:** accept alternation as an alternative to recurrence.

### ❌ FALSIFIED AT IMPLEMENTATION — the trade runs the wrong way

Implemented, it recovered the all-distinct roll-call FN **and reopened the
i18n/multi-language FP that v1.2.2 closed**:

    English: The quick brown fox.        <- 3 distinct labels, each once
    Portuguese: A rápida raposa.         <- alternates
    Spanish: El zorro rápido.            <- and ALL are utterances (sentence punctuation)

Every downstream gate passes that — utterance ratio is **1.0**. The recurrence floor was
the only thing rejecting it.

So alternation trades a **real-corpus false positive** (tika `multi-language.txt`) for a
**synthetic false negative**. That is the wrong direction, and it is exactly the
"simultaneously too loose and too strict" tension the 2026-06 brief identified — the
brief was right that recurrence is structurally insufficient, and wrong that alternation
is the missing signal. Recurrence stays required.

### 3.3 Case C — the JSON floor counts objects instead of reading them

The `≥3` floor is an FP defence: fewer objects means weaker evidence that a
`{role, content}` array is conversation rather than configuration.

**Fix:** allow **2** objects when the evidence is stronger in kind rather than in
number — the roles must come from the conversational set *and* the content must be
utterance-shaped. A two-element config array fails on both.

The floor is not lowered; it is made **conditional on content shape**.

## 5. Falsification (falsify-first)

Written failing, before implementation. **The adversarial corpus comes first** — builder
bias applies to me, and this is a detection change, which is the exact class where a
confirming test proves nothing.

**Must flip (the scope):** the three §2.2 cases, each asserted in both directions.

**Must NOT regress — the v1.2.x hard-won FP set**, every case from §2.1 re-asserted:
FAQ, `Item:`/`Price:`, embedded example dialogue, ALL-CAPS mail headers, tech-doc
structure without utterance labels, changelog `Added:` lexicon dominance, version-tag
release notes, dated journals.

**Real-corpus sweep:** the drift must be explainable file-by-file. Any unexplained
change is a defect, not an improvement. Previous chatlog work has repeatedly found the
sweep catching what synthetic cases could not.

**Determinism:** `workers=1` vs `4` byte-identical (standing Layer-A gate).

**Scale check:** re-run the LongMemEval probe — the ≥3-floor FN population should close
without the FP rate moving.

## 6. Considered & rejected

**More stop-list words.** The brief's explicit finding, from two independent models:
whack-a-mole. The class is structural, not lexical.

**Lowering the JSON floor to 2 unconditionally.** Trades a known FN for an unknown FP
population on the most common structured shape there is. §3.3 keeps the floor and
qualifies it.

**Rewriting the detector.** Tempting and wrong. v1.4's gate works; three paths do not
consult it. Rewriting would discard four patches of hard-won FP defence to fix three
cases.

**Fixing the F2/F3 items from the brief in this release** (structure co-signal
total-vs-distinct; detection/extraction divergence producing `is_chatlog=True` with
`speaker_labels=[]`). Real, and deferred deliberately: they are a *consistency* cleanup
with their own risk surface, and bundling them would make the diff's blast radius
unreadable. Own release, after this one lands.

## 8. Decision log — OPEN

**D3 — Sentinel's answer to §7. ✅ CLEARED 2026-08-09 — ship all three.**

Sentinel verified against source (`backend/datasets.py::build_chatlog` +
`scripts/export_training_data.py`), not from memory. Their gameplay-corpus `.md` files
carry **one** `### <world> — <persona> — <sid8>` header per file (never 5+), and every
speaker label is followed by a real sentence — the player's action and the DM's prose
narrative. Attribute-style labels (`NPC:`/`Location:`/`Status:` with short tokens) live
in a **separate schema JSONL**, never in the scanned markdown.

**Their answer was more careful than my question.** I framed the risk around the `###`
branch; they correctly observed that a multi-turn session emits 3+ `---` dividers and so
*does* reach the structure-rule path via the **divider** branch — then showed the removal
still de-detects nothing of theirs, because condition (2) never holds. They are also
covered independently by the ordinary prose rule. The mirrored
`CHATLOG_SPEAKER_LABEL_RE` stays byte-identical, which they confirmed.

**D1 — Split the FP fix out? ✅ RESOLVED: no. Keep all three together.**
The conservative split existed solely for the case where Sentinel was exposed. They are
not, and explicitly declined it. Splitting would now cost two `method_version` bumps and
two consumer re-index events for what is one idea with one root cause.

**D2 — Does the RPG-corpus gate stay retired? ✅ RESOLVED: yes.**
Per §2.4 — LongMemEval supplied what that gate existed to provide, from an outside
dialogue distribution, at scale, with the failure mechanism known. Recorded as a
decision rather than left as a lapse.

**D4 — What shipped, versus what was approved. RESOLVED at implementation.**

Approved: three changes. Shipped: **one**. Cases A and B were falsified by the existing
test suite and a real-corpus fixture respectively, and reverted rather than shipped with
their tests weakened.

That asymmetry is the point of falsify-first, and it is worth stating plainly: **the
non-regression battery was written before the implementation, and it is the only reason
these were caught before merge rather than by a consumer.** Weakening
`test_markdown_transcript_with_speakers` would have made case A pass and shipped a false
negative on real terse transcripts.

Both residuals now carry a test asserting their CURRENT behaviour with the measurement
attached (`test_A_RESIDUAL_*`, `test_B_RESIDUAL_*`), so they read as known-and-priced
rather than as bugs awaiting a naive fix.
