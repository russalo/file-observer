## 1. Summary

The v1.15 cross-platform arc added a CI OS matrix but no CI runner exercises a **native NTFS
filesystem with real reparse points, the Windows MIME registry, or a legacy (cp1252) console**.
A Windows shakedown on a native NTFS box (elevated, on tailnet) surfaced three real defects. This
release fixes all three. The core determinism/never-crash/containment contract otherwise **held** on
NTFS (reserved names, emoji, ADS, long paths, locked files all degraded to error records, never
crashed; the content-derived invariants `checksum_sha256` + `extension` were byte-identical across
OS).

| # | Defect | Class | Fix |
|---|--------|-------|-----|
| **A** | `iter_files` follows NTFS **junctions/reparse-point dirs** (they are not symlinks), so the v1.8.1 `is_symlink()`-gated containment misses them → an **out-of-tree junction would escape the scan tree** on Windows (and a crafted huge/cyclic junction would hang/OOM) | security / containment (v1.8.1 red-team class) | `os.walk` that PRUNES reparse-point dirs before descent (Windows-only) + retained v1.8.1 file-symlink containment (leg-4/Codex: prune-before-descend, not a per-file post-filter) |
| **B** | On Windows (no libmagic) the platform MIME registry maps `.csv → application/vnd.ms-excel` (a **binary** MIME in `BINARY_MIME_TYPES`) → `is_binary` flips **True** → the text tier is skipped → `csv_headers` empty. A routing flag flips across OS for identical bytes. | MIME determinism (v1.15 `extension_mime` wart class) | pin `.csv → text/csv` (`mimetypes.add_type`), matching Linux |
| **C** | The `--watch` JSONL delta and `--schema` outputs write via text `sys.stdout` → `UnicodeEncodeError` on a cp1252 console with non-ASCII metadata (a never-crash hole). The main `--stdout` path is already byte-safe. | output byte-safety | route those writes through `sys.stdout.buffer` UTF-8, mirroring the main `--stdout` path |

## 2. Provenance & grounding (measure-first)

- **A grounded:** `iter_files` (scanner.py ~4096) uses `root.rglob("*")`; the containment check is
  gated `if path.is_symlink():` (~4103). Python's `rglob` does **not** descend into directory
  *symlinks* (so POSIX is safe by omission), but a Windows **junction** is a reparse point that is
  **not** a symlink — `rglob` descends into it and `Path.is_symlink()` returns False for files
  reached through it. Shakedown evidence: an in-tree junction `jlink → jtarget` produced a record for
  `jlink/inside.txt` (fo followed the junction; benign because in-tree, but the *mechanism* means an
  out-of-tree junction escapes).
- **B grounded:** `mimetypes.guess_type("x.csv")` returns `text/csv` on Linux but
  `application/vnd.ms-excel` on Windows (registry). `application/vnd.ms-excel ∈ BINARY_MIME_TYPES`
  (scanner.py ~463) and `detect_binary` (~7018) returns binary for any MIME in that set. fo pins
  `.xls`, `.yaml`, the Office formats, and the image types (v1.15/1.15.1/1.24) but **not** `.csv`.
  Shakedown evidence: `b.csv` — `is_binary` Linux False → Windows True; `csv_headers` empty on
  Windows; `test_integration.py::TestBaselineTier::test_csv_headers_extracted` FAILED on NTFS.
- **C grounded:** main `--stdout` (~9546) already does `sys.stdout.buffer.write(text.encode("utf-8"))`
  (byte-safe). `--watch` (~2421) and `--schema` (~9402–9410) use `sys.stdout.write(str)` (text →
  console-codepage-encoded). `test_v1_28`'s observed `PYTHONUTF8` need is a **test-harness decode
  artifact** (subprocess `text=True` decodes with cp1252), NOT an fo write bug — so C is only the
  watch/schema paths, not the main path.

## 3. Design

### 3.1 Bug A — reparse-aware containment

**Final design (leg-4 escalated — see §7):** enumerate with `os.walk` instead of `rglob` so
reparse-point **directories** can be PRUNED *before* descent, and retain the v1.8.1 file-symlink
containment on the resulting files:

```python
candidates: list[Path] = []
for dirpath, dirnames, filenames in os.walk(root, followlinks=False, onerror=lambda _e: None):
    base = Path(dirpath)
    if _WINDOWS and dirnames:
        # prune reparse-point subdirs (junction / dir symlink) so a junction is
        # NEVER descended into — closes the escape, the in-tree double-count, AND
        # the crafted out-of-tree / cyclic junction DoS, all before materializing
        # the subtree. Fail-closed via resolve()-containment on an inconclusive
        # attribute read. One lstat per DIRECTORY, not per file.
        dirnames[:] = [d for d in dirnames if not _should_prune_dir(base / d, root_resolved)]
    for name in filenames:
        candidates.append(base / name)

for path in sorted(candidates, key=lambda p: p.as_posix()):
    if not path.is_file():
        continue                    # skip FIFO/socket/broken symlink — as rglob's is_file() did
    if path.is_symlink():           # v1.8.1 file-symlink containment, unchanged
        try:
            if not path.resolve().is_relative_to(root_resolved):
                continue
        except OSError:
            continue
    ... skip_output_dir / hidden / ignore ... ; yield path
```

`_should_prune_dir(path, root_resolved)` returns True when `path` is a reparse point
(`os.lstat().st_file_attributes & FILE_ATTRIBUTE_REPARSE_POINT`); on an inconclusive read
(`OSError`/`AttributeError`) it FAILS CLOSED via `resolve()`-containment (prune if it resolves outside
the tree or can't be resolved). One `lstat` per directory.

**Why `os.walk` and not a per-file filter:** `sorted(root.rglob("*"))` *materializes the entire
walk first* — so a per-file post-filter runs only **after** rglob has already recursed through a
junction into a huge or cyclic out-of-tree target (hang / OOM / escape before any file is skipped —
leg-4/Codex P1). Pruning `dirnames` during `os.walk` stops the descent at the junction. **POSIX is
byte-identical:** `os.walk(followlinks=False)` omits symlinked dirs exactly as `rglob` did, and the
retained file-symlink `resolve()`-check is unchanged — empirically verified (path set + observations
identical to 1.45 on the fixtures **and** a hostile nested/hidden/in-tree-symlink/out-of-tree-symlink
tree). The Windows prune is validated by the Tailnet shakedown re-run.

### 3.2 Bug B — pin `.csv → text/csv`

Add next to the existing pins (~line 145):

```python
# v1.46: Windows's MIME registry maps .csv → application/vnd.ms-excel (a BINARY
# Office MIME), so on the no-libmagic Windows path a plain-text CSV was typed
# binary → is_binary flipped True → the text tier (csv_headers) was skipped. Pin
# the canonical text type Linux already produces so a CSV is text on every OS.
mimetypes.add_type("text/csv", ".csv")
```

`mimetypes.add_type` overwrites the registry entry for `.csv` (same mechanism as the `.xls` pin,
proven on Windows). No-op on Linux (already `text/csv`). Restores `is_binary=False` and CSV header
extraction on the Windows no-libmagic path.

### 3.3 Bug C — byte-safe watch/schema stdout

Route the `--watch` JSONL delta and `--schema` writes through `sys.stdout.buffer` UTF-8 (guarded with
`getattr(sys.stdout, "buffer", None)` so pytest's captured stdout without a `.buffer` still works),
mirroring the main `--stdout` path. Output byte-safety only.

## 4. Versioning

- **A** changes `iter_files` containment LOGIC (a file-set-affecting routing rule); **B** changes
  `is_binary`/`mime_type` on the Windows `.csv` path (a routing signal). Both are **LOGIC**, in the
  v1.15 cross-platform-LOGIC precedent (the observing logic changed even though **Linux real-corpus
  output is byte-identical** — the new behavior is Windows-only). → **LOGIC 1.23.0 → 1.24.0.**
- **C** is output routing only (the emitted bytes are unchanged on a UTF-8 console; only the encoding
  robustness on a legacy console changes) → no manifest change; folded under the same LOGIC line as
  the release, no separate bump.
- No new field / shape change → **SCHEMA 1.23 unchanged.**
- **SCANNER 1.45.0 → 1.46.0.**

**Cross-OS determinism note (Pillar 1):** as with v1.15, fo is NOT byte-identical across OS — platform
is a `ScanContext` field, and the contract is *identical bytes + identical ScanContext → identical
records*. A + B make the Windows manifest **closer** to the Linux one (CSV no longer mistyped;
junction files no longer double-counted), narrowing two OS warts.

## 7. Considered & rejected

- **A: unconditional `resolve()`-containment for every file (the first cut).** Rejected in **leg-1
  self-review** — running `resolve()` + `continue`-on-`OSError` for *every* file (not just symlinks)
  means a non-symlink file deleted mid-scan (a TOCTOU race, the v1.8.2/v1.9.1 class) would raise on
  `resolve()` and be **silently skipped** instead of becoming an `ErrorRecord` — a silent omission.
- **A: a per-file skip after `sorted(rglob("*"))` (the leg-1 refinement).** Superseded in **leg-4** —
  `rglob("*")` + `sorted()` *materializes the whole walk first*, so a per-file post-filter runs only
  after rglob has already recursed through a junction into a huge or cyclic out-of-tree target
  (hang / OOM / traversal-escape before any file is skipped — leg-4/Codex P1). Replaced with `os.walk`
  that **prunes reparse-point dirs before descent** — the containment holds before the subtree is
  ever materialized, and it's O(dirs) not O(files×depth) (leg-4/gemini), fail-closed on an
  inconclusive attribute read (leg-4/CodeRabbit).
- **A: skip ALL reparse dirs unconditionally (both OSes).** Rejected — on POSIX rglob already omits
  symlinked dirs, so an unconditional walk only adds per-file stat cost for zero behavior change.
  Gate the walk to Windows.
- **A: dedup by resolved path instead of skipping reparse ancestors.** Rejected — resolved-path
  dedup is order-dependent and would silently drop a legitimately hard-linked file; skipping the
  reparse *ancestor* matches POSIX semantics exactly.
- **C: also convert the main `--stdout` path.** Already byte-safe; no change needed.
- **Deferring A's Windows-only leg to a follow-up.** Rejected — the Tailnet re-run validates it in
  the same cycle, so shipping the security fix without the consistency fix would leave a known
  double-count for no reason.
