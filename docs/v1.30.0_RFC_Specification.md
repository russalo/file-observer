# v1.30.0 RFC — CLI robustness: fail-loud on bad input + sane default output dir

**Status: SHIPPED** — released as v1.30.0 (see `docs/HISTORY.md` for the date and the patch releases that rode on this minor). The status line below is the RFC's state at approval time, kept as written.

**Status (at approval time): APPROVED (2026-06-30) by Russell — one minor bundling #109 + #110, all §8 decisions to the recommended leans. Implementation pending.** RFC normative language per BCP 14.

| Axis | Current (v1.29.0) | Proposed (v1.30.0) |
|---|---|---|
| SCANNER | 1.29.0 | 1.30.0 |
| LOGIC | 1.15.0 | **1.15.1** (the leg-1 §3.3 discovery-skip; was frozen until leg-1) |
| SCHEMA | 1.16 | 1.16 (unchanged) |

## 1. Summary

Two CLI-robustness fixes, surfaced by **bestiary**'s operational shake-out via the new
GitHub-issues feedback model:

- **#109 — fail loud on bad input.** A nonexistent or non-directory source, `--workers 0`,
  `--preview-max < 0`, and a missing `--previous-manifest` are all silently accepted today
  (`rc=0`, usually an empty manifest). fo MUST error (`rc=2`) on inputs that are user
  mistakes — a typo'd source returning a *successful empty manifest* is the worst outcome
  for the stack fo sits under (trellis indexes nothing → recall answers "no results" → a
  silent cascade with nothing to triage anywhere).
- **#110 — stop writing into the install dir.** With no `-o`, fo writes the manifest +
  report into its own installed package directory (`<site-packages>/file_observer/manifests/`).
  That breaks on a read-only / container / system install, pollutes a pip-managed location,
  and collides across callers. fo MUST default its output to a writable, discoverable
  location outside the package.

**#109 and #110's output relocation are CLI ergonomics only** — they do not touch the
manifest contract (the v1.9 `--workers` / v1.11 `--watch` / v1.28 `--stdout` precedent: CLI
ergonomics are not under the manifest contract). SCHEMA stays frozen at 1.16. The one
exception is the **§3.3 leg-1 self-inclusion fix**: discovery skips the tool's own output
dir, which moves `manifest_checksum` for a tree containing that dir → **LOGIC 1.15.0→1.15.1**
(the v1.8.1 symlink-skip precedent). Byte-identical for every other tree (all corpora).

## 2. Motivation

fo is the **scan substrate** under trellis and recall (and bestiary, exercising it). Both
findings come from real use, filed as GitHub issues (the first batch through the new
consumer-feedback channel — the model working as intended):

- **#109** is the silent-zero class recall called "the worst outcome for fleet-wide
  discovery" (recall #40/#42), now caught at the *root* of the stack. An empty *real*
  directory is legitimately 0 files; a *nonexistent* one is a user error and must say so —
  the two MUST stop being indistinguishable.
- **#110** is a packaging anti-pattern: runtime data MUST NOT be written into the code
  directory (XDG/CLI convention — runtime output goes to the cwd or `$XDG_DATA_HOME`, never
  the install tree). The bare/interactive default invocation should not require a writable
  site-packages or root.

## 3. Design

### 3.1 #109 — input validation (fail-loud)

Validated **before scanning**; each failure prints a one-line message to stderr and exits
**`rc=2`** (the established "bad invocation" code — `--watch`/`--stdout` incompatibility
already exits 2):

| Input | Today | Proposed |
|---|---|---|
| source path does not exist | `rc=0`, empty manifest | `rc=2` — `source directory not found: <path>` |
| source path is a file, not a directory | `rc=0`, empty manifest | `rc=2` — `source is not a directory: <path>` |
| `--workers N` with `N < 1` | `rc=0` (silently 0/neg) | `rc=2` — `--workers must be >= 1` |
| `--preview-max N` with `N < 0` | `rc=0` (silently no previews) | `rc=2` — `--preview-max must be >= 0` |
| `--previous-manifest <missing>` | `rc=0`, silently no delta | **warn** to stderr, proceed (no delta), `rc=0` |

**Preserved exactly:** a legitimately-empty *real* directory still scans to `rc=0` + an
empty manifest (0 files is a valid observation; only *nonexistent/non-dir* is an error).
`--previous-manifest` is OPTIONAL, so a missing prior is a **warning, not an error** (the
scan is still valid — it just has no delta baseline).

**Out of scope:** *supporting* a single-file source (fo scans directories; a single-file
scan is a separate feature, not this fix). For now a file source is a clear error.

### 3.2 #110 — default output directory

The design decision is **where** the bare default lands. Decision: **the current working
directory, in a `file-observer-manifests/` subdirectory** (created if absent).

```
$ cd some/project && file-observer src
Manifest written to ./file-observer-manifests/manifest_v1.30.0_<ts>.json
Report written to   ./file-observer-manifests/report_v1.30.0_<ts>.md
```

Rationale (the options weighed):
- **cwd subdir `./file-observer-manifests/` (CHOSEN)** — the manifest + report ARE the
  user's deliverable, so they must be *discoverable* where the command was run; a subdir
  keeps the two files tidy without cluttering the cwd root; always writable (unlike
  site-packages); no hidden state.
- **`$XDG_DATA_HOME/file-observer/` (rejected)** — XDG-correct for app-managed data, but
  *wrong for a deliverable the user wants to consume*: writing the user's output to a hidden
  `~/.local/share/...` path is surprising and undiscoverable. XDG is for state the app
  manages, not the artifact the user asked for.
- **The source directory (rejected)** — writing into the scanned tree risks self-inclusion
  on a re-scan (the v1.28 Docker/Action self-inclusion lesson) and pollutes the input.
- **cwd root, bare files (rejected)** — two files (manifest + report) dropped loose in the
  cwd is messier than one grouped subdir.

`-o/--output` stays the explicit override (unchanged); `--stdout` (v1.28) remains the
no-file path. **trellis and recall pass `-o` explicitly → entirely unaffected.** This fixes
only the bare/interactive default. `--help` text updated to the new default.

### 3.3 #110 self-inclusion fix (leg-1 — the only LOGIC-bearing part)

leg-1 review caught that the §3.2 cwd default reintroduces self-inclusion for the most
common invocation `fo .`: the manifest + report land *inside* the scanned tree (the cwd
**is** the source when `source="."`), so a re-scan observes its own prior output (and churns
the `--previous-manifest` delta). The old package-dir default was always *outside* any scan
tree, so this never happened.

**Decision: Option A** (Russell, 2026-06-30) — the cleanest user outcome, consistent with the
v1.28 GitHub Action's adopted write-outside-the-scan-tree precedent. **Discovery (`iter_files`)
skips any directory named `DEFAULT_OUTPUT_DIRNAME` (`file-observer-manifests`)** at any level —
the tool's reserved output dirname. A `fo .` re-scan no longer observes its own output.

This is the ONLY part of v1.30 that moves a manifest: a tree containing a
`file-observer-manifests/` directory now excludes it → `manifest_checksum` moves **for such
trees only**. **LOGIC 1.15.0→1.15.1** — a discovery change that moves the checksum for some
inputs (the v1.8.1 symlink-skip precedent). The manifest is byte-identical for every tree
*without* that dir, including all corpora (leg-3 sweep confirmed NO-DRIFT). The dirname is
reserved: a user's unrelated directory of that exact name is also skipped (bounded + documented
— it is the tool's own artifact name).

## 4. Observable surface

- New: `rc=2` + a stderr message on the five #109 invalid-input cases (four error, one warn).
- Changed: the bare-invocation default output path (#110).
- **Unchanged: the manifest itself.** Every *valid* invocation (existing-dir source, valid
  flags, explicit `-o`) emits a byte-identical manifest to v1.29.0 — including the
  empty-real-dir case. `meta.config` is unaffected (output path + validation are runtime,
  excluded like `signing_key`/`--workers`).

## 5. Version-axis impact

SCANNER 1.29.0 → **1.30.0**. SCHEMA **frozen 1.16**. LOGIC **1.15.0→1.15.1** — #109 + #110's
output relocation are runtime/CLI only (manifest untouched, the v1.9/v1.11/v1.28 precedent),
but the §3.3 leg-1 discovery-skip moves `manifest_checksum` for a tree containing the
`file-observer-manifests/` dir, so LOGIC bumps (the v1.8.1 symlink-skip precedent). Byte-
identical for every tree without that dir (all corpora; leg-3 NO-DRIFT).

**Backward-compat note (v1.0 contract holds):** the v1.0 contract freezes the *manifest*,
not CLI ergonomics. #110 relocates a *documented default* (acceptable — a caller relying on
the site-packages default is relying on the anti-pattern being fixed; trellis/recall pass
`-o` and are unaffected). #109 changes exit codes from `rc=0` to `rc=2` on *user-error*
input — a script that passed a bad source and ignored `rc` now sees the error, which is the
footgun fix, not a regression of any valid use.

## 6. Falsifiable contract

`tests/test_v1_30.py` (falsify-first — written failing against v1.29.0):

- nonexistent source → `rc=2` + `source directory not found`; file source → `rc=2` +
  `not a directory`.
- `--workers 0` / `--workers -1` → `rc=2`; `--preview-max -1` → `rc=2`.
- missing `--previous-manifest` → `rc=0` + a stderr warning (NOT an error); a present one
  still produces a delta.
- **empty REAL directory → `rc=0` + empty manifest** (the preserved case — must NOT regress
  to an error).
- bare invocation writes to `./file-observer-manifests/`, creating it if absent, and
  **never** under `site-packages`.
- **§3.3 self-inclusion:** discovery skips a `file-observer-manifests/` dir (real content
  still scanned); a bare `fo .` re-scan does NOT include the prior run's output.
- **manifest equality:** a valid scan with explicit `-o` (on a tree without the output dir)
  is byte-identical (same `manifest_checksum`) to the v1.29.0 output — the contract-freeze
  proof for everything except the §3.3 LOGIC-bearing skip.

## 8. Decisions (Russell, 2026-06-30 — all to the recommended leans)

1. **#110 default location** — **DECIDED: `./file-observer-manifests/`** (cwd subdir), not
   `$XDG_DATA_HOME` (undiscoverable for a deliverable).
2. **#110 subdir vs cwd-root** — **DECIDED: a `file-observer-manifests/` subdir** (tidy over
   loose cwd files).
3. **#109 file-source** — **DECIDED: error** on a single-file source; single-file scan
   *support* deferred as a separate future feature.
4. **Bundling** — **DECIDED: one minor** bundling #109 + #110 (not split).
5. **#110 self-inclusion (leg-1, post-approval)** — leg-1 review caught that the cwd default
   self-includes on a `fo .` re-scan. **DECIDED: Option A** (Russell, 2026-06-30) — discovery
   skips the `file-observer-manifests/` dir (§3.3), accepting a LOGIC bump 1.15.0→1.15.1, over
   Option B (accept + document) or C (revisit the location). Matches the v1.28 write-outside-
   the-tree precedent.
