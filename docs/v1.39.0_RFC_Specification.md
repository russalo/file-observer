# v1.39.0 RFC — MCP front-door: lexicon + delta

**Status:** APPROVED (feature + the lexicon-delivery decision signed off)
**Author:** file-observer Claude · **Date:** 2026-07-11
**Version axes:** SCANNER 1.38.1→1.39.0 · LOGIC UNCHANGED (1.21.0) · SCHEMA UNCHANGED (1.22)

---

## 1. Motivation

The MCP server (v1.37) shipped *before* the bring-your-own-lexicon observer (v1.38), so the agent
front-door is one release behind the scanner. Two existing scanner capabilities are unreachable via MCP:

1. **`--lexicon` (v1.38)** — the guardrail-risk pre-screen. This is the gap that matters most: an agent
   using fo through MCP for "look before you touch untrusted files" *cannot* run the pre-screen that is
   the whole point of that use case.
2. **Delta scanning (`--previous-manifest`)** — an agent can't ask "what changed since last scan," the
   most useful missing capability for an agentic loop.

## 2. The privacy constraint (drives the lexicon design)

An MCP tool's arguments are **constructed by the calling LLM** — anything passed as a tool argument is,
by definition, in the agent's context. A `lexicon={…terms…}` *per-call parameter* would therefore put
the sensitive terms **into the very AI v1.38 keeps them away from** — backwards. So the lexicon must reach
fo **without the terms ever crossing the MCP wire as data**: only a *path* or *nothing* may cross.

**Decision (signed off): server-startup `--lexicon <path>` flag**, mirroring the existing `--root`
allowlist. The operator configures one lexicon at launch; every scan applies it; the agent only ever sees
the term-free results (counts + category names + `dictionary_id`). The agent cannot name a lexicon file,
cannot see the terms, and cannot pass terms inline. (A per-call `lexicon_path` — a path, not terms — was
the considered alternative; deferred, more surface + lets the agent name files.)

## 3. Design

### 3.1 Lexicon — server-startup flag
- `file-observer-mcp --lexicon <path>` (+ `python -m file_observer.mcp_server --lexicon …`). Parsed +
  validated at startup via `parse_lexicon(json.load(...))`; a bad lexicon fails fast with `ap.error(...)`
  (the `--root` is-a-dir precedent), never mid-tool-call. Stored in a module global `_LEXICON`.
- Threaded into every scan tool's `ScannerConfig(lexicon=_LEXICON)` via the shared `_scan()` helper →
  `scan_summary` / `scan_file` / `scan_directory` all apply it.
- **Surfacing:** `scan_file` already returns the full record (`specialist_metadata.lexicon_match`).
  `scan_summary`'s `notable` gains a `lexicon` block — `{lexicon_id, files_matched, category_hits}` from
  the `lexicon` vector — so the agent sees *which categories hit*, not just the aggregate `lexicon_match`
  safety_flag (already in `notable.safety_flags`). **Terms are never in any tool output** (the v1.38 line).

### 3.2 Delta — per-call `previous_manifest_path`
- New optional `previous_manifest_path: str | None = None` on `scan_directory` and `scan_summary`. A path
  (not sensitive), mirroring `--previous-manifest`. Resolved + `is_file()`-checked; threaded into
  `ScannerConfig(previous_manifest=…)`. Not `--root`-restricted (it's a read-only manifest input the agent
  names, not a scan tree); a non-manifest file degrades gracefully (fo's delta code tolerates it).
- `scan_directory` returns the full manifest → its `delta` block is populated. `scan_summary`'s `notable`
  gains a `delta` block (`added`/`modified`/`removed`/`unchanged` counts) so the agent gets the change
  summary without the full manifest.

### 3.3 What stays the same
- All tools stay read-only, bounded, in-tree, never-execute. The `_count_files_bounded` guards are
  unchanged. `--root` still applies to the scan target.
- **The manifest returned is byte-identical to a CLI scan with the same `--lexicon` / `--previous-manifest`
  settings** — this is a front-door, not a new observation.

## 4. Versioning
- **SCANNER 1.38.1→1.39.0** — a new MCP-surface capability (the v1.37 MCP-server minor precedent).
- **LOGIC + SCHEMA UNCHANGED (1.21.0 / 1.22)** — zero new observation; the manifest is byte-identical to
  `scan()` with the same settings (the v1.26 `scan()` / v1.28 `--stdout` / v1.37 MCP front-door precedent).
- `mcp` stays the optional `[mcp]` extra; runtime stays zero-required-dep.

## 5. Testing (falsify-first, `test_v1_39.py`; benign lexicon only)
- `--lexicon` applied → `scan_file` output carries `lexicon_match`; `scan_summary.notable.lexicon` carries
  per-category hits; the `lexicon_match` safety_flag appears on a hit.
- **Terms never in any tool output** (only counts + category names + the hash).
- `previous_manifest_path` → `scan_directory`'s manifest has a populated `delta` block (correct
  added/removed); `scan_summary.notable.delta` carries the counts.
- A bad/non-manifest `previous_manifest_path` degrades, never crashes.
- **Front-door contract:** MCP-with-lexicon manifest == `scan(lexicon=…)` manifest (checksum-identical).
- Bad `--lexicon` at startup fails loud.
- Version axes: SCANNER 1.39.0, LOGIC/SCHEMA unchanged.

## 6. Non-goals / deferred
- **Per-call `lexicon_path`** (agent picks the lexicon file per scan) — deferred; the server flag is the
  locked-down primary. Add later if an agent genuinely needs multiple lexicons.
- **Terms-inline lexicon param** — permanently rejected (§2, the privacy landmine).
- **Stateful "scan and remember"** for delta — no server state; the agent supplies the prior-manifest path.
- **HTTP transport** — still deferred (v1.37 §4).

## 7. Review
Proportionate to a small MCP-surface change exposing existing capability (no new observation): leg-1
in-house + static + leg-4 PR bots. Adversarial focus: the **privacy boundary** (no term reaches a tool
arg or output), the delta-path handling (bad path degrades), and byte-identity with the CLI equivalent.
