> **Status: APPROVED + IMPLEMENTED** (Scanner Claude, 2026-06-14). §8 sign-off

> HEIC fix bundled. See §9 for what the matrix/forced-fallback actually surfaced.

> fallback exists specifically for no-libmagic Windows) but CI runs **ubuntu-latest
> only**. This release adds a **CI OS matrix** (ubuntu + macOS + Windows) and fixes

> **Net (tentative — §6):** SCANNER 1.14.0 → 1.15.0; **LOGIC 1.4.3 → 1.5.0** (the
> HEIC MIME fix changes detection logic, same vintage of change as v1.3's MIME
> fallback); SCHEMA unchanged 1.9. The phone/device capture-metadata work is the

## 1. Overview

### 1.1 Purpose
We make a cross-platform promise and only test a third of it. The pure-Python MIME
sniff (v1.3) was built *for* no-libmagic environments (Windows, minimal containers),
yet no CI job ever exercises that path on those environments. This release makes the
claim **tested**, not asserted — and fixes what the test exposes.

### 1.2 Measure-first (the matrix is the instrument)
Per the project's measure-first discipline, the matrix is added **first** and its run
is the measurement of what's actually broken. We can't enumerate every cross-platform
defect from a Linux box — but we can name the ones reading the code already reveals,
and pre-validate fixes locally by simulating the failing environment (e.g. forcing the
no-libmagic path). **Known going in:**
- **HEIC/HEIF mis-detection (the iPhone default photo format).** `MAGIC_SIGNATURES`
  has png/jpeg/gif/webp/tiff but **no heic/heif**, and the fallback rule
  `(offset 4, "ftyp") → video/mp4` matches HEIC's ISO-BMFF `ftyp` box — so on a
  **no-libmagic** system an iPhone photo is reported as `video/mp4` and skips image
  handling. libmagic-present systems likely dodge it; the fallback (the Windows path)
  gets it wrong. This is a real wrong-value bug, found by code-read 2026-06-14.
- **Suspected, to confirm on the matrix:** Windows path separators / drive letters in
  the relative-posix `path` normalization; MAX_PATH (260) + reserved names
  (CON/PRN/NUL/aux); case-insensitive-fs effects on dedup/`duplicate_clusters`; CRLF
  vs LF in text/encoding/preview; file-locking semantics on the per-file read.

## 2. Scope discipline (what v1.15 is NOT)
- **NOT a happy-path behavior change.** On libmagic-present Linux/macOS the manifest
  is unchanged. The HEIC fix corrects a *wrong* value on the fallback path only.
- **NOT a claim of byte-identical-across-OS manifests.** Platform is a *ScanContext*
  field (Pillar 1: variance must be explained by context). The cross-platform contract
  is: **identical file bytes + identical ScanContext (same deps) → identical records**;
  and **no crashes / correct paths / correct fallback MIME on every OS**. (CRLF-vs-LF
  files are genuinely different bytes → different checksums; that's correct, not drift.)
- **NOT the phone/device capture-metadata feature** — that's v1.16 (§7). v1.15 only
  *fixes detection* (HEIC) so v1.16 can *extract* from correctly-typed files.
- **The observe→interpret line holds.**

## 3. The CI matrix (`.github/workflows/tests.yml`)
- Add a `strategy.matrix.os: [ubuntu-latest, macos-latest, windows-latest]`;
  `runs-on: ${{ matrix.os }}`. Keep the existing Python 3.12 job.
- **libmagic coverage is the point:** ubuntu/macos will have libmagic; **Windows will
  not** (that's the realistic no-libmagic path we most need to exercise). Optionally add
  a *second* ubuntu job with libmagic uninstalled to force the fallback deterministically
  (don't rely on Windows alone to cover it).
- Digest-pin the actions (project convention). `fail-fast: false` so one OS failing
  doesn't mask the others.
- The `[pdf]`/`[msg]`/`[watch]` extras + `python-magic` install differ per-OS — the
  matrix will surface install-time gaps too.

## 4. Known fix: HEIC/HEIF detection
- Add `heic`/`heif`/`mif1`/`avif` brand detection: HEIC is an ISO-BMFF file whose
  `ftyp` box (offset 4) carries a brand at offset 8 (`heic`, `heif`, `mif1`, `heix`,
  `avif`…). The fix is a **more-specific signature ordered before** the generic
  `ftyp → video/mp4`: match `ftyp` + an image brand at offset 8 → `image/heic` (or
  `image/avif`); leave non-image `ftyp` → `video/mp4`.
- This is a `MAGIC_SIGNATURES` + `_sniff_mime` change → **LOGIC bump** (MIME detection
  is LOGIC, the v1.3 precedent: LOGIC 1.1.4→1.2.0 for the MIME tier). Image dimension
  extraction for HEIC is **out of scope** (HEIC dimensions live in compressed
  `ispe`/`meta` boxes — that's v1.16 territory); v1.15 only stops the *mis*-classification.
- Pre-validate locally before the matrix: force the no-libmagic path and assert a HEIC
  sample sniffs to `image/heic`, not `video/mp4`.

## 5. Falsifiable contract (`tests/test_v1_15.py`)
- **CI green on ubuntu + macOS + Windows** (the headline — the matrix run is the proof).
- **HEIC fallback:** with libmagic forced off, a HEIC fixture sniffs `image/heic`
  (regression test for the wrong `video/mp4`), and `.avif` → `image/avif`. Falsify-first
  — write it failing against current `main`.
- **No-crash on path edges:** a fixture tree with a Windows-hostile name / a deep path
  produces an `ErrorRecord`-or-clean record, never an abort (extends the v1.8.1
  never-crash discipline to Windows path semantics).
- **Cross-platform determinism (controlled):** the same byte-identical fixture corpus
  scanned with the same ScanContext yields identical per-file `checksum_sha256` and
  derived fields on each OS (modulo the ScanContext platform/deps fields). Run on the
  matrix.

## 6. Version & scope decision
- **If v1.15 is CI-matrix-ONLY** (no code change): it's infrastructure — no version
  bump, ship as a workflow PR (the Node-20 PR #54 precedent), HISTORY-only.
- **If it includes the HEIC fix** (recommended — the matrix's first finding): that's a
  LOGIC change → **SCANNER 1.15.0, LOGIC 1.5.0, SCHEMA unchanged 1.9**, a real minor,
  and this RFC is warranted.
- **Recommended:** v1.15.0 = matrix **+** HEIC fix **+** any small fixes the matrix
  surfaces; defer anything large the matrix reveals to its own patch. Don't let v1.15
  balloon into "fix all of Windows" — matrix first, fix the cheap/known, scope the rest.

## 7. The phone/device capture-metadata minor — QUEUED for v1.16 (NOT this release)
Marked here so it's not lost. **v1.16.0 (planned): device/capture provenance** —
observe-only EXIF (camera make/model, capture datetime, orientation, **GPS presence**)
for images + container metadata (codec/duration/resolution/creation-date/rotation) for
video; a new `image`-namespace expansion + a `video` specialist; a `geotagged`
safety-flag (presence-as-disclosure, the v1.12 `extraction_permission_bypassed`
pattern) so GPS is *flagged* without us deciding what to do with coordinates. **Held
reason (the candidate's privacy gate) is satisfied** by the observe-with-disclosure
framing + the now-present demand signal (Russell, 2026-06-14). **Depends on v1.15's
HEIC fix** (must detect iPhone photos correctly before extracting from them). This is
the meatier, more strategic minor — extends the provenance seam (already file-observer's
strongest). RFC to follow once v1.15 ships.

## 9. What the forced-fallback measurement surfaced (implementation record)
Running the suite with `python-magic` removed (the deterministic instrument) turned up
exactly the no-libmagic defects, separated from version-bump noise:

- **HEIC/HEIF/AVIF → `video/mp4`** (the known one) — fixed via brand-specific
  `MAGIC_SIGNATURES` ordered before the generic ftyp rule. Validated on real Tika
  test files (`IMG_1034.heic`, `testHEIF.heic`, `testAVIF.avif`).
- **`.toml` → octet-stream → treated binary** — fixed by registering `.toml` as
  `text/plain` (not IANA `application/toml`, which would have made every `.toml` a
  false content-vs-extension mismatch on libmagic systems).
- **Windows `magic.Magic()` construction crash** — `Scanner.__init__` now degrades to
  `self._magic=None` instead of aborting (python-magic imports lazily; libmagic the C
  lib is what's absent).
- **Documented fallback limitations, deferred (not bugs):** signatureless text reads as
  `degraded` (extension-tier `mime_type_fallback` diagnostic) and the `.eml` email
  specialist is skipped by the MIME safety guard (no magic-byte signature to corroborate
  extension-derived `message/rfc822`). 6 tests marked `requires_libmagic` (auto-skip on
  the fallback job). Relaxing the guard for text-format specialists touches the shared
  dispatch path → its own future patch, per §6 scope discipline.

**Leg-1 (in-house review) catch — a regression the HEIC fix itself introduced:**
`scan_signatures` collects *all* matching signatures (unlike `_sniff_mime`'s first-match),
so a HEIC matched both `image/heic` AND the generic `video/mp4` ftyp rule → two formats →
`is_polyglot=True` (a **Stable** contract field) on real iPhone photos. Fixed by an
ftyp-superseding block mirroring the existing RIFF one (a recognized image brand drops the
generic `video/mp4` label). Falsify-first regression test added
(`test_heic_is_not_a_false_polyglot`). This is the v1.15 analog of the recurring lesson:
a more-specific signature must supersede the generic one in BOTH the sniff and the
signature-collection paths.
