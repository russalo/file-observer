## 1. Overview

### 1.1 Purpose
v1.10 was the first promotion pass and set the lifecycle (`candidate → provisional
→ stable`). Since then, several fields it deliberately *held* have had their pending
changes resolved: the post-v1.5 PDF arc **completed** (v1.12 closed the encrypted /
uncompressed-xref residuals), and the `provenance` / `application` extensions that
landed *in* v1.10 have been stable across v1.11–v1.13. This release graduates the
matured set and re-states the held set with current reasons. Same discipline as
v1.10; nothing about *what is observed* changes.

### 1.2 The promotion criterion (unchanged from v1.10)
**Settled producing logic + evidence of value — not age.** The load-bearing
corollary: **do not promote a field when a known, pending change will alter how it's
populated.** Two of this release's holds are exactly that case.

### 1.3 Normative language
RFC normative language (MUST/SHOULD/MAY) per BCP 14.

## 2. Scope discipline (what v1.14 is NOT)
- **NOT a LOGIC change.** `LOGIC_VERSION` stays **1.4.3**. Promotion changes only the
  *stability promise*, never how a field is computed.
- **NOT a shape change.** Promoted fields keep their exact type/semantics. The manifest
  is **byte-identical** before/after — that's the falsifiable contract (§5).
- **NOT new field creation, NOT new parsing.** No new specialist surface, no new
  bounded-read path. (So the v1.8.1 never-crash/bounded obligation has nothing new to
  cover.)
- **The observe→interpret line holds.** Nothing here scores, ranks, or infers intent.

## 3. Promotions: provisional → stable

### 3.1 Promote (RECOMMENDED — settled producing logic, validated)

| Field | Provisional since | Why it's earned stable |
|---|---|---|
| `specialist_metadata.pdf.parser` | v1.8 | **Promoted on the data, not the old note.** The v1.10 hold-reason ("a tier-2 `/Info`-via-stdlib upgrade would shift its *values*") was a **misattribution**: `parser` records *which tier ran*, not what it extracted — if stdlib ever also fills `/Info`, the value is still `"stdlib"`; only the sibling `producer`/`title`/`author` fields would gain values. So the only change that ever held it provably **cannot move `parser`'s enum**. Investigation (655 infra PDFs): a deterministic 3-value enum `{pypdf, stdlib, none}`, populated 655/655, distribution pypdf 301 / none 354 / stdlib 0 (stdlib only fires when pypdf is absent). Settled logic (arc complete at v1.12, untouched v1.13); clear value (which decode tier produced the metadata = a coverage/reliability signal). |
| `vectors_collected[].provenance` (vector) | v1.6 | Extended in v1.10 (mv 1→2, OLE2 producing-app) — held then under *never-promote-and-extend*. Shape (`toolchains` / `production_years` / `digitization`) has been **stable across v1.11–v1.13**. Note: promoting the vector fixes its **shape**, not its closed toolchain table — the table may still grow *additively* (rules-hash-tracked; `identity_digest` moves by design, per the v1.6 determinism contract). Stable means the table can't *remove/retype* existing mappings without a MAJOR. |
| `specialist_metadata.{spreadsheet,document}.application` | v1.6 | The producing-application string (OOXML `app.xml`; OLE2 `SummaryInformation` since v1.10). The v1.10 OLE2 extension is the last change; settled since. Simple observe-only string; feeds the (also-promoting) `provenance` vector. |

These move from PUBLIC_CONTRACT §2.4 (provisional, "may change in a MINOR") to the
**stable** backward-compat policy: not removable/retypable without a MAJOR.

## 4. Contract math
- **SCHEMA 1.8 → 1.9.** Promotions are a contract change (the v0.11 and v1.10
  precedent) — even with zero value change, the stability *promise* changed.
- **LOGIC unchanged 1.4.3.** No producing logic touched.
- **Manifest byte-identical.** Promotion is a designation; field values/shapes are
  untouched.
- **`PUBLIC_CONTRACT.md`** moves the three fields from §2.4 to stable; **`docs/SCHEMA.md`
  regenerated** per the v1.13 drift-guard discipline; CONVENTIONS §3.1 / §4 registry
  updated.

## 5. Falsifiable contract (`tests/test_v1_14.py`)
- **Byte-identical proof:** a corpus scan's `manifest_checksum` is **unchanged**
  pre/post-promotion (promotion ≠ shape change). The unchanged checksum *is* the
  proof the release didn't alter output — write it failing-first against the v1.13
  baseline.
- Promoted fields present + correctly typed on a real scan; the held fields still
  present + still labeled provisional.
- Workers=1-vs-N byte-identical preserved (v1.9 Layer-A gate).
- `docs/SCHEMA.md` regenerates clean (drift guard green).

## 6. Surface stability in `--schema` — FOLDED IN (resolves the v1.13 §3.3 deferral)
**Decided: fold in.** Not scope creep — it's the promotion *being honest in the
self-description surface*. v1.14's job is changing what's stable; `--schema` enumerates
the output surface; a `--schema` that doesn't reflect the stability it just changed is
incomplete about exactly this release's subject. The promotion and its visibility are
the same act.

**What it adds:** a `stability` field (`stable` / `provisional`) on the enumerated
manifest fields, specialist fields, and vectors in `--schema` + `docs/SCHEMA.md`,
populated from the v1.13 registries. Per the v1.13 discipline this is a surface element
→ registry update + a completeness test (`--schema` stability must match the field's
real PUBLIC_CONTRACT status) + SCHEMA.md regen. This is *also* the v1.13 §3.3 deferral
closed.
