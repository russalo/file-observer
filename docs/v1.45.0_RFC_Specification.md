# v1.45.0 RFC — Decouple the human summary from the determinism contract + refresh it

**Status: SHIPPED** — released as v1.45.0 (see `docs/HISTORY.md` for the date and the patch releases that rode on this minor). The status line below is the RFC's state at approval time, kept as written.

**Status (at approval time):** APPROVED (2026-07-15)
**Author:** file-observer Claude · **Date:** 2026-07-15
**Version axes:** SCANNER 1.44.0→1.45.0 · **LOGIC 1.22.0→1.23.0** (one-time: the checksum computation
changes) · SCHEMA 1.23 **FROZEN**
**Issue:** #147

---

## 1. Motivation

The per-scan human-readable `summary` (the Markdown paragraph on every manifest, `_build_summary`) is a
**derived *view*** of already-checksummed data — file counts, quality, vectors. It carries no
independent observation; it re-renders sealed facts for a human. Yet it sits **inside** the determinism
contract: `manifest_checksum` hashes it, so **every prose refresh forces a LOGIC bump** (v1.19 did, and
this #147 refresh would). That's backwards — the human rendering should not gate the machine contract.

Separately, the summary is **stale**: `_build_summary` predates the lexicon / `fact_block` / `ai_session`
work, so it doesn't mention them (#147). This RFC fixes both, in the right order.

## 2. Decision (A — approved 2026-07-15): exclude the whole `summary` from the checksum

Considered and rejected — **a non-indexed sidecar** (`summary` stays indexed, new prose goes in a second
non-checksummed field): it would **fragment the human summary**, and readability (one paragraph, one
glance) is the summary's whole purpose. So instead, the **entire `summary` field** leaves the checksum
preimage (joining `scan_id` / `generated_at`, already excluded). The summary stays **one coherent,
complete, readable field** — it's just no longer part of the sealed content.

- **One-time cost:** the checksum computation changes → **every** manifest's `manifest_checksum` moves
  once → an ungated LOGIC bump (1.22.0→1.23.0). Precedent: v1.15 (ScanContext) and v1.36 (the purexml
  dep record) both moved every checksum as a justified one-time change.
- **After this release, summary refreshes are LOGIC-free forever** — no fragmentation, no future bumps.

It's a **correction, not a loss:** the checksum should seal the *observations* (files / vectors /
quality / context); the summary is a *rendering* of those, reproducible from the sealed data given the
build (`scanner_version`).

## 3. Mechanism

`compute_manifest_checksum` already blanks the volatile fields before hashing (`d["meta"]["scan_id"] =
""`, `d["meta"]["generated_at"] = ""`, `d["manifest_signature"] = None`). Add **`d["summary"] = ""`** to
that set. That is the entire checksum change.

**Consequence to document (§6):** the `manifest_signature` is computed *from* the checksum, so a summary
outside the checksum is also **outside signature coverage**. After v1.45 the summary is a **non-sealed,
unsigned derived view** — *trust the sealed machine fields; the summary is human convenience,
reconstructible from them.* For a field that is already just-for-humans, that is the correct posture, but
it MUST be stated so no consumer treats the summary prose as tamper-evident.

## 4. The refresh (#147 — now rides free)

With the summary excluded, enriching `_build_summary` moves the checksum by **zero**. Add, each **gated
on presence** (emit only when count > 0, so corpora without these namespaces render an unchanged
summary):

- **Lexicon** (a vector) → fold into the *Vectors* line from the `lexicon` vector summary:
  `lexicon matched N files (K categories, T hits)` — **counts only** (bounded; a lexicon can have 256
  categories, and the vector itself carries names). The `lexicon_match ×N` safety-flag count already
  shows via the v1.19 named-flags line; this adds the vector shape.
- **`fact_block`** → a compact line: `Fact blocks: N files.` (count of `is_fact_block`).
- **`ai_session`** → a compact line: `AI sessions: N logs, T tokens observed.` — for each session use the
  vendor `usage.total_tokens` when present (OpenAI), else sum the canonical component counts
  (`input_tokens`/`output_tokens`/`cache_read_tokens`/`cache_creation_tokens`/`reasoning_tokens`, Anthropic); sum across
  ai_session files. **Never priced** (the federation charter's bright line).

## 5. Versioning

- **LOGIC 1.22.0→1.23.0** — the checksum computation changes (summary excluded) → every manifest's
  `manifest_checksum` moves once. Ungated, one-time; the v1.15/v1.36 precedent. The #147 prose refresh
  itself moves nothing (summary is now excluded).
- **SCHEMA 1.23 FROZEN** — the `summary` field's shape is unchanged (still a stable top-level string); only
  its role in the checksum changes. No field added/removed/retyped.
- SCANNER 1.44.0→1.45.0.

## 6. Contract-doc updates (load-bearing — the honest boundary)

- **PUBLIC_CONTRACT §1.8 (Manifest Checksum)** — the checksum now also excludes `summary` (alongside
  `scan_id`/`generated_at`); state that the summary is a **non-sealed, build-versioned derived view**,
  not part of the tamper-evident content, and reconstructible from the sealed observations.
- **§1.9 (Manifest Signature)** — note the signature does not cover the summary (it covers the checksum).
- HISTORY row; the version-history table (SCHEMA `1.23` / LOGIC `1.23.0`).

## 7. Testing (falsify-first, `test_v1_45.py`)

1. **Checksum is independent of the summary** — build a manifest, mutate `summary` to arbitrary prose,
   `compute_manifest_checksum` is **unchanged** (the load-bearing proof of decoupling).
2. **The refresh appears** — on a lexicon + fact_block + ai_session corpus, the summary contains the new
   lines; ai_session `T` equals the summed per-session total (vendor `total_tokens` when present, else the
   canonical component counts) — a count, never a price.
3. **Gated** — a corpus without those namespaces renders a summary with **no** new lines (byte-identical
   to the pre-refresh rendering of the same observations).
4. **Version axes** — LOGIC 1.23.0, SCHEMA 1.23, SCANNER 1.45.0.
5. **Signature** — a signed manifest verifies; mutating `summary` post-sign does **not** break the
   signature (documents the non-sealed consequence, so it's a conscious property, not a surprise).

## 8. Non-goals

- **A sidecar / split summary** — rejected (§2): fragments the human view.
- **Pricing ai_session tokens** — never; the charter. Counts only.
- **Restructuring the summary** — the additions are compact lines in the existing prose; the rendering
  style is unchanged.
