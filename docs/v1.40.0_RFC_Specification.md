# v1.40.0 RFC — Field trust classification + safe mode + `--schema` trust annotation

**Status:** APPROVED (§7 decisions locked 2026-07-12)
**Author:** file-observer Claude · **Date:** 2026-07-12
**Version axes (proposed):** SCANNER 1.39.0→1.40.0 · LOGIC UNCHANGED (1.21.0) · SCHEMA UNCHANGED (1.22) · schema_doc_version bump
**Issues:** #136 (feature half), and the mechanism behind Phase 2 (#136 self-sweep) and Phase 3 (#133 receipt).

---

## 1. Motivation

The r/mcp review (#136) established that the **scanner** can't be prompt-injected (no model, never reads for meaning), but the **manifest is a report about untrusted input** and echoes attacker-controllable strings verbatim (filenames, `content_preview`, metadata). A consumer — especially an LLM agent — has no machine-readable way to tell fo-generated signal from quoted attacker bytes, and no way to ask fo for *only the safe signal*.

Phase 0 (PR #137) documented the boundary. This RFC makes it **operational**: a first-class trust classification, exposed in `--schema`, and a **safe mode** output that emits only the trusted fields. The classification is also the load-bearing primitive for Phase 2 (self-sweep needs to know which fields are file-derived) and Phase 3 (the receipt is a trusted subset).

## 2. The trust line: free-text payload capacity

The axis that matters for injection is **not** "did fo compute it vs did it come from the file" — a parsed `page_count` came from the file but a `5` can't carry a prompt. The real axis is: **can this field carry attacker-controlled free text into a consumer?**

- **`fo_derived` (trusted):** numbers, booleans, hashes, timestamps, sizes, closed-vocabulary enums/labels/flags, and fo's own verdicts. Even when the value is sourced from the file (`page_count`, `width`), it cannot carry a text payload.
- **`file_derived` (untrusted / attacker-controllable):** any field that is, or directly contains, **verbatim free-text bytes from the input** — filenames, paths, `content_preview`, extracted metadata *string* values, tags, frontmatter values, chatlog speaker labels, `fact_block` keys/values, reference-token strings.

This "free-text-carrying" line is cleaner and more defensible than "fo-computed vs file-sourced," and it's exactly what the injection threat cares about.

## 3. Classification (initial pass — finalized under the completeness guard)

`FileRecord` top level:

| trusted (`fo_derived`) | untrusted (`file_derived`) |
|---|---|
| `checksum_sha256`, `size_bytes`, `directory_depth`, `created_at`, `modified_at`, `encoding`, `mime_type`, `mime_analysis`\*, `file_signature`, `format_signatures`, `is_binary`, `is_chatlog`, `is_fact_block`, `is_polyglot`, `requires_specialist_tool`, `requires_vision`, `sidecar_exists`, `safety_flags`, `preservation`, `filename_patterns`, `specialist_tool`, `signal_provenance`\* | `path`, `filename`, `extension`, `stage_folder`, `content_preview`, `tags`, `frontmatter`, `structural` (title/headings/keys), `reference_tokens`, `asset_matches` |

`specialist_metadata` is **mixed and classified per field**: numeric/boolean fields (`page_count`, `width`, `height`, `duration_s`, `bitrate`, `pair_count`, `has_*`, token counts) are trusted; **string** fields (`producer`, `creator`, `title`, `author`, `subject`, `make`, `model`, `from`, `to`, `application`, `codec`, `fact_block.pairs[].value`, …) are file-derived.

\* **Borderline (decide in review):** `mime_analysis` and `signal_provenance` are fo-structured but can embed a file-derived substring (the extension; an error `detail` that names a file). Proposal: classify the *container* trusted but mark the specific embedded string leaves file-derived, or conservatively treat the whole subtree file-derived. `errors[].detail` similarly — conservative default: **file-derived**.

**Principle when unsure: classify as `file_derived`.** A false "untrusted" only over-suppresses in safe mode; a false "trusted" leaks a payload. Fail safe.

## 4. Deliverable A — classification registry + completeness guard

A single-source-of-truth registry (like `SPECIALIST_FIELDS` / `PROVENANCE_TRIGGERS`) mapping every emitted field path to `fo_derived` | `file_derived`. A **completeness guard** test asserts every field in a real manifest is classified (mirrors the v1.13 `--schema` completeness tests) so the classification can't silently drift as fields are added. This registry is the foundation the other two deliverables consume.

## 5. Deliverable B — `--schema` trust annotation

Each field descriptor in `--schema` (json / md / summary) gains a `trust: fo_derived | file_derived` attribute, sourced from the registry. **Describes existing fields — no manifest change.** Consumers can programmatically know which fields to treat as untrusted before templating them into a prompt. Bumps `schema_doc_version` (the v1.21.2 build-time-interface precedent); the manifest contract (SCHEMA 1.22) is untouched.

## 6. Deliverable C — safe mode output

A new output mode that emits **only the `fo_derived` fields**, dropping the `file_derived` ones. This is the "is there a lexicon-only setting?" answer, and it makes the guardrail-screen safe by construction (the model only ever sees fo-generated signal). It is a **projection/filter of existing observation** — no new observation, no sanitization — so the front-door precedent (v1.26 `scan()` / v1.28 `--stdout` / v1.37 MCP) applies: **the DEFAULT manifest is byte-identical, LOGIC/SCHEMA frozen.**

### 6.1 Whole-manifest projection (post-review completion, 2026-07-12)

The projection must clean the **entire manifest**, not just `files[]` — the goal is a manifest safe to feed a model, and file-derived strings also ride in the manifest-LEVEL blocks. The first implementation projected `files[]` only; a post-commit self-review (the leg-1 adversarial pass) caught real leaks through the manifest-level blocks (a live file path survived via `quality.duplicate_clusters` on the `examples/` tree). The projection therefore also scrubs:

| Block | Field(s) | Projection |
|---|---|---|
| `meta` | `source_dir` (a filesystem path) | → `null` |
| top-level | `summary` (human prose; names authors / capture devices / paths) | → `null` |
| `delta` | `added` / `modified` / `unchanged` / `removed` / `rescan_candidates` (path lists) | → `[]` |
| `quality.duplicate_clusters[]` | `paths` (file paths) | → `[]` (checksum / size / count kept) |
| `quality.per_directory_summary[]` | `directory` (a subdir path) | → `null` (counts kept) |
| `vectors_collected[]` | `summary` (corpus rollups laced with author / producer / toolchain names as values AND file-extension dict-keys) | → `{}` (D4 fail-safe: drop the payload, keep the fo-derived vector envelope) |

Kept intact (fo/operator-derived, no attacker free text): `schema_version`, `context`, `stats`, `routing_summary`, `manifest_checksum`, `manifest_signature`, `meta.{scan_id,generated_at,config}` (`config` is operator-supplied — CLI args like `previous_manifest`/`ignore_file`/`extension_overrides` — not scanned-file-derived), and each vector's `vector_id` / `method_version` / `rules_hash` / tuning / `dictionary_id` / `identity_digest` / `applied_to_count`. The MCP `scan_summary` (which builds a compact dict outside the manifest projection) likewise nulls its `path` + `summary` in trusted-only, emitting only counts.

## 7. Decisions (locked 2026-07-12)

- **D1 = null-out + `trusted_only: true` marker.** File-derived fields are set to `null`; a top-level `trusted_only: true` marks the projection. Manifest shape stays stable; validators still pass.
- **D2 = `--trusted-only`.** CLI `--trusted-only`, `ScannerConfig(trusted_only=True)`, manifest marker `trusted_only`.
- **D3 = both.** A `trusted_only: bool` MCP tool param (default false) AND a server-startup `--trusted-only` flag that forces it on.
- **D4 = fail-safe conservative.** Unsure ⇒ file-derived; `mime_analysis`/`signal_provenance` embedded strings + `errors[].detail` ⇒ file-derived.
- **D5 = path identity via a safe handle.** `path`/`filename` are file-derived (nulled in trusted-only), but trusted-only output adds a fo-derived **`path_id = sha256(<relative-posix path>)`** — a correlation handle carrying no free text; the consumer maps it back to a real path out-of-band (it hashes the paths it asked to scan). Present ONLY in trusted-only output (default byte-identical). This is the shared identity primitive with the #133 receipt/bridge id.

**Final classification (pinned):**
- **file-derived → nulled in trusted-only:** `path`, `filename`, `extension`, `stage_folder`, `content_preview`, `tags`, `frontmatter`, `structural`, `reference_tokens`, `asset_matches`, `mime_analysis`, `signal_provenance`, `errors`, and **every string-valued leaf inside `specialist_metadata`** (recursively — this conservatively over-suppresses fo-enum strings like `codec`/`format`/`xref_type`/`parser`, which is acceptable per D4).
- **fo-derived → kept:** `checksum_sha256`, `size_bytes`, `directory_depth`, `created_at`, `modified_at`, `encoding`, `mime_type`, `file_signature`, `format_signatures`, `is_binary`, `is_chatlog`, `is_fact_block`, `is_polyglot`, `requires_specialist_tool`, `requires_vision`, `sidecar_exists`, `safety_flags`, `preservation`, `filename_patterns`, `specialist_tool`, `specialist_metadata` (non-string leaves), + the new `path_id`.
- **top-level marker:** `trusted_only: true`.

Original options considered:

- **D1 — how safe mode drops file-derived fields.**
  - (a) **Omit** the keys entirely (smallest, most token-efficient; changes record shape).
  - (b) **Null them out** + a top-level `safe_mode: true` marker (preserves manifest shape/validators; obvious what was suppressed). *Recommend (b)* — shape-stable and self-declaring, and a JSON-Schema validator still passes.
- **D2 — the name.** `--safe-mode` (matches the "safe mode" framing that named it) / `--signal-only` / `--trusted-only`. *Recommend `--safe-mode`* + `ScannerConfig(safe_mode=True)`.
- **D3 — MCP exposure.** Choosing the *safe projection* isn't sensitive (the agent is asking for LESS data, not passing a secret), so a **tool param `safe: bool`** on `scan_file`/`scan_directory` is acceptable, and/or a **server-startup `--safe-mode` default**. *Recommend both:* a `safe: bool` tool param (default false) plus a server `--safe-mode` flag that forces it on for locked-down deployments.
- **D4 — the borderline classifications (§3\*).** Confirm the fail-safe rule and the calls on `mime_analysis`, `signal_provenance`, `errors[].detail` (proposal: conservative — embedded string leaves / `detail` are file-derived).

## 8. Versioning

- **SCANNER 1.39.0 → 1.40.0** (new output mode + `--schema` surface).
- **LOGIC 1.21.0 UNCHANGED, SCHEMA 1.22 UNCHANGED** — safe mode is a projection (default manifest byte-identical); the trust annotation describes existing fields. `schema_doc_version` bumps for the annotation.
- The registry + classification are internal; they surface only through `--schema` and safe mode.

## 9. Testing (falsify-first, `test_v1_40.py`)

- **Completeness:** every field in a real manifest (specialists on/off, chatlog, lexicon, delta, signed) is classified — fail if any is unclassified.
- **Safe mode contains zero file-derived free-text:** scan a tree with a **planted attacker string** in a filename, in `content_preview`, and in a metadata field (e.g. a crafted PDF `/Producer`); assert the string appears in the normal manifest and is **absent** from safe-mode output. (This is the core falsification — safe mode must not leak the payload.)
- **Manifest-LEVEL falsification (§6.1):** a second battery plants canaries that surface ONLY at the manifest level — a duplicate-file name (`quality.duplicate_clusters[].paths`), a subdir name (`per_directory_summary[].directory`), the scan-root path (`meta.source_dir`), an author (`author_aggregate` vector summary + the `summary` prose), and an added-file name (`delta.added`) — and asserts none reach trusted-only output. Red-verified (fails against the `files[]`-only projection). Plus a shape-stability check (scrubbed blocks keep their fo-derived counts/hashes; the vector envelope survives, its summary drops) and an MCP `scan_summary` trusted-only check (path + summary nulled).
- **Default byte-identical:** safe mode off ⇒ manifest checksum unchanged vs a v1.39 baseline.
- **`--schema` annotation:** every field carries `trust`; a file-derived field is labelled `file_derived`.
- **MCP:** `scan_file(safe=true)` returns no file-derived strings; `safe=false` unchanged; server `--safe-mode` forces it.
- Version axes: SCANNER 1.40.0, LOGIC/SCHEMA unchanged.

## 10. Review
Full 4-leg (it touches the manifest surface + a new security-relevant mode): leg-1 in-house swarm (focus: any file-derived field that slips into safe-mode output — the completeness/fail-safe boundary), leg-2 cross-model, leg-3 sweep (default byte-identical, safe-mode leak scan across corpora), leg-4 PR bots. The adversarial question for every leg: **can any attacker-controlled string reach safe-mode output?**

**Leg-1 outcome (2026-07-12):** the adversarial pass found the projection was `files[]`-only, so file paths / author names / the prose summary still leaked through the manifest-LEVEL blocks (confirmed empirically: a real path via `quality.duplicate_clusters` on the `examples/` tree). Fixed by extending the projection to the whole manifest (§6.1); a follow-up MCP audit found `scan_summary` echoed the scan-root `path` in trusted-only (nulled for consistency). No scanned-file-derived string reaches trusted-only through any surface (CLI, `scan_directory`, `scan_file`, `scan_summary`) after the fix.

## 11. Non-goals / deferred
- **Self-sweep** of file-derived fields with the lexicon → **Phase 2** (#136 detection; consumes this registry).
- **Receipt projection + bridge id** → **Phase 3** (#133; the receipt is a `fo_derived` subset + an id).
- **Sanitization** — permanently rejected (§6; observe-don't-interpret).
- **Lexicon-source loader / distribution** (the uBlock model) — separate future track.
