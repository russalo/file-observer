# File Observer v1.17.0 RFC Specification — video capture metadata

> **Status: DRAFT — gated on real-`.mov`/`.mp4` validation data** (the parked iPhone-`.mov`
> path — Drive/rclone). This is the **video half** split out of the v1.16 RFC: as v1.16
> played out, only the image half was de-risked and shipped (v1.16.0, live on PyPI), and
> video adds a *new observable surface* (a `video` namespace + a `video_structure`
> specialist + new extension routing + a SCHEMA bump) — which is a **minor**, not a 1.16.x
> patch, so it gets its own RFC. The technical design carries forward from
> `docs/v1.16.0_RFC_Specification.md` §3/§5 (the prototype already walked a sample MP4 and
> confirmed the `moov`-position question). **Measure-first gate:** the QuickTime-keys /
> GPS / `moov`-at-end parse is NOT locked until a real iPhone-video corpus is measured.
>
> The second *capture-metadata* minor. Observe-only **container + per-track** metadata for
> MP4/MOV video, plus the **GPS-presence disclosure** (`geotagged`, reused from v1.16).
> Extends the scanner's strongest seam — provenance — from "what device captured this
> photo" (v1.16) to "what device captured this video, when, and was it geotagged."

> **Net (tentative — §7):** SCANNER 1.16.0 → 1.17.0; **LOGIC 1.6.0 → 1.7.0** (new routing:
> `.mp4`/`.mov`/`.m4v` now `require_specialist_tool`; new extraction logic); **SCHEMA
> 1.10 → 1.11** (additive: a new `video` namespace). `geotagged` already exists (v1.16),
> reused — no new `safety_flags` value. **Dependencies: NONE added** (§5.1) — the ISOBMFF
> walker exists in the build since v1.16; video metadata is pure stdlib + `struct`.

## 1. Motivation

Phone-captured video (iPhone `.mov`, Android/most `.mp4`) carries the same capture-provenance
signals v1.16 surfaced for photos — capture device, capture time, and location — in the
container's metadata boxes. A pipeline triaging a media dump wants the same questions
answered for video as for stills: *what device, when, geotagged?* v1.16 answered them for
HEIC/JPEG; v1.17 answers them for the ISOBMFF video family, reusing the same observe-only,
presence-not-coordinates, no-new-dependency discipline.

This was scoped *into* the v1.16 RFC and deliberately gated on real-data validation. The
image half shipped; this RFC is the video half, now correctly framed as its own minor.

## 2. Scope

**In scope (observe-only):**
- **Container-level metadata** — `codec` (from `stsd` sample entry), `duration_s` (from
  `mvhd`/`tkhd` timescale + duration), `width`/`height` (from the video `tkhd` track
  dimensions), `creation_date` (from `mvhd` creation_time, the Mac/QuickTime epoch).
- **Apple QuickTime keys** (when present) — `make` / `model` / capture `creation_date`
  from `moov`→`meta`→`keys`+`ilst` (`com.apple.quicktime.make` / `.model` / `.creationdate`).
- **GPS-presence** — the `geotagged` safety_flag (reused) + a `video.gps_present` bool,
  fired by `com.apple.quicktime.location.ISO6709` (iPhone) or `udta`→`©xyz` (Android),
  both ISO 6709. **Presence only — coordinates are not extracted.**
- **Per-track** observe (§8 Q-carried-forward: both container-level AND per-track) — the
  track table (`trak`/`tkhd`/`mdia`/`hdlr`/`stsd`) so codec/dims reflect the video track,
  not the first track.

**Out of scope (this release):**
- Coordinate extraction (privacy line — §5.3).
- Non-ISOBMFF containers: `.mkv` (Matroska), `.avi` (RIFF), `.webm` — different parsers,
  deferred (§8).
- Full MakerNote / deep per-vendor decode, full XMP depth, C2PA — the **ungated upgrade**
  (shared with v1.16 §9), not this RFC.
- Transcoding, thumbnail/keyframe extraction, any decode of the media payload.

## 3. Parse mechanism (carried from v1.16 §3, validated by the prototype)

ISOBMFF is a box tree; the build already walks it (`_iter_isobmff`, added v1.16, plus the
v1.8 ObjStm decoder). The video specialist extends that walk:

- **`moov` is NOT necessarily first.** The prototype's sample MP4 had boxes ordered
  `ftyp free mdat moov` — `moov` at the END. So the specialist needs a **head + bounded-tail
  read** (the recurring tail-read lesson: PDF trailer v1.5/v1.7, OLE2 v0.7.1), capped like
  the PDF whole-file read. **This is the load-bearing measure-first item** — the real
  iPhone-`.mov` corpus must confirm `moov` placement + size distribution before the
  read-window cap is locked.
- **`mvhd`** (inside `moov`) — version-aware (v0 = 32-bit times, v1 = 64-bit); creation_time
  is seconds since 1904-01-01 UTC (the QuickTime epoch) → ISO 8601.
- **`trak`→`tkhd`** — track dimensions (fixed-point 16.16 width/height) for the video track;
  **`mdia`→`hdlr`** identifies the `vide` handler; **`stsd`** sample entry → codec fourCC.
- **Apple keys** — `moov`→`meta`→`keys` (key list) + `ilst` (values), the standard QTFF
  metadata mechanism Apple publishes; map `com.apple.quicktime.{make,model,creationdate,
  location.ISO6709}`.
- **Android** — `moov`→`udta`→`©xyz` ISO 6709 location string (presence → `geotagged`).

All bounded, never-crash, deterministic — the v1.8.1 discipline (cap every attacker-controlled
count/size; the v1.16 leg-1 iloc DoS is the cautionary precedent — carry the bound into
every new box-count loop).

## 4. Specs (researched 2026-06-15; STANDARDS_TRACKING "Moving toward — gated")
- **ISO 14496-12 (ISOBMFF)** — the box structure, `mvhd`/`tkhd`/`stsd`/`udta`.
- **Apple QuickTime File Format** (developer docs, published) — the `meta`/`keys`/`ilst`
  metadata keys and `com.apple.quicktime.*` namespace.
- **ISO 6709** — the location string format used by both Apple and Android boxes.
- **MWG / C2PA** — awareness; C2PA is the high-value future provenance extension (shared §9).

## 5. Design decisions (carried from v1.16 §5, video-specific)

### 5.1 Dependencies: NONE added
The ISOBMFF walker ships in the build since v1.16; video metadata is pure stdlib + `struct`
(the "PNG IHDR / JPEG SOF / ISOBMFF via struct, not Pillow" ethos). **ExifTool is the
dev-time oracle only** (§6), never shipped — exactly as `pypdf` was the v1.8 oracle and EXIF
extraction was validated against `exiftool` in v1.16. A future full-MakerNote decode could
revisit an optional extra; this release has no stdlib gap.

### 5.2 Observe, don't reconcile (report per-source)
Same as v1.16 §5.2: a video may carry a container `mvhd` creation_time AND a QuickTime
`creationdate` key AND track times. **Surface each as observed; never pick a winner.**
Reconciliation is the consumer's job. (Avoids the "which date is real" bug class met with
PDF `/Info`.)

### 5.3 GPS: presence, not coordinates (observe-with-disclosure)
The existing `geotagged` `safety_flag` (v1.16) fires when a video carries an ISO-6709
location box (`com.apple.quicktime.location.ISO6709` or `udta`/`©xyz`). **Coordinates are
not extracted or stored.** Reuses the v1.16 `_safety_extras` channel (already generalized
to all specialists), so the disclosure path is unchanged.

### 5.4 New specialist + extension routing
- **`video_structure`** specialist (the v1.16 §7.6 decision), namespace **`video`**.
- `.mp4` / `.mov` / `.m4v` added to `SUPPORTED_EXTENSIONS`, `SPECIALIST_TOOLS`,
  `SPECIALIST_NAMESPACE`, `SPECIALIST_MIME_GUARD` (`video/mp4`, `video/quicktime`). MIME
  detection already recognizes the ISOBMFF `ftyp` brands (v1.15) — the brand→MIME map may
  need `.mov`/`.m4v` brand rows confirmed.
- **Head + bounded-tail read** (§3), capped like the PDF whole-file read.

### 5.5 New fields (all provisional)
- `specialist_metadata.video`: `codec`, `duration_s`, `width`/`height`, `creation_date`,
  `make` / `model` (QuickTime keys), `gps_present` (bool). All provisional on intake
  ([[feedback_candidates_need_a_reason]] — provisional is the data-gathering tier).
- New registries to update (the §13 discipline): `SPECIALIST_FIELDS["video"]`,
  `SPECIALIST_MIME_GUARD["video"]`, and `docs/SCHEMA.md` regenerated. `geotagged` already
  in `SAFETY_FLAGS` (v1.16) — reused.

## 6. Validation (falsify-first + ExifTool oracle + measure-first)
- **Measure-first (THE GATE):** survey a real iPhone-`.mov` + Android-`.mp4` corpus —
  `moov` position + size distribution (sizes the read window), QuickTime-key prevalence,
  GPS-box prevalence. The video specialist is NOT locked until this runs. (The v1.16
  prototype already confirmed `moov`-at-end on one sample; the corpus confirms the
  distribution.)
- **ExifTool oracle (dev-only):** the hand-parser's extracted fields are gated by agreement
  with `exiftool` on the measurement corpus — exactly as `pypdf` gated the v1.8 stdlib
  decoder and `exiftool` gated v1.16 EXIF. Never wrong; honest-null on the exotic.
- **Falsify-first:** `tests/test_v1_17.py` written failing first — moov-at-end, version-1
  `mvhd`, missing QuickTime keys, GPS-present vs absent, truncated/adversarial box counts
  (the iloc-DoS lesson), determinism (workers byte-identical), corpus sweep no-drift.
- **Fixtures:** self-authored minimal ISOBMFF (ftyp + moov{mvhd,trak,udta} + a tiny mdat),
  license-clean + committable (the v1.16 `tests/fixtures/generated/` pattern); real iPhone
  video stays local-gitignored per the privacy line.

## 7. Versioning
- SCANNER 1.16.0 → **1.17.0**.
- **LOGIC 1.6.0 → 1.7.0** — `.mp4`/`.mov`/`.m4v` now `require_specialist_tool` (routing
  change) + new extraction logic.
- **SCHEMA 1.10 → 1.11** — additive: the new `video` namespace + its fields. `geotagged`
  already shipped (v1.16) — reused, no new `safety_flags` value.

## 8. Open questions (to resolve at design sign-off / on the real corpus)
1. **Read window** — head + bounded-tail cap value (sized by the corpus `moov` distribution).
   Locked by measure-first.
2. **Container vs per-track precedence** — report both (per §5.2); confirm the field shape
   (e.g. top-level `codec`/`width` reflect the `vide` track; a `tracks[]` list is a possible
   richer shape — decide at sign-off).
3. **Extension set** — `.mp4`/`.mov`/`.m4v` confirmed; `.mkv`/`.avi`/`.webm` deferred (Q5
   from v1.16) — confirm still deferred.
4. **`duration_s` type** — float seconds vs raw timescale units (lean: float seconds,
   derived = `duration / timescale`).
5. **Brand→MIME** — confirm `.mov`/`.m4v` ftyp brands map cleanly to `video/quicktime` /
   `video/mp4` on the no-libmagic path.

## 9. Ungated upgrade — flagged for later (shared with v1.16 §9)
Not part of this release: **full XMP depth**, **C2PA / Content Credentials** (signed
authenticity manifests from cameras + AI generators — the strategic provenance extension),
deep per-vendor MakerNote decode, and non-ISOBMFF video containers. Tracked in
`STANDARDS_TRACKING.md` Awareness. Picked up on its own when chosen, not blocked behind this.
