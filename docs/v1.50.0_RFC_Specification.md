## 2. What ships

All ten. Each code/packaging item carries a guard in `tests/test_packaging.py` so the class
cannot silently recur; repository settings (ruleset, Dependabot alerts) are prepared in-repo
for Russell to apply and recorded here.

- **README links absolute** (`github.com/russalo/file-observer/blob|tree/main/…`); guard
  `test_readme_has_no_relative_links`.
- **`py.typed`** shipped + declared as package-data; guard `test_py_typed_marker_shipped`.
- **`LICENSE` = verbatim AGPL-3.0** (sha256-pinned to gnu.org's text); the dual-licensing
  terms move to **`LICENSING.md`**; pyproject: `license = "AGPL-3.0-or-later"` +
  `license-files = ["LICENSE", "LICENSING.md"]`, `License ::` classifier dropped
  (setuptools ≥ 77 rejects the mix); guard
  `test_license_metadata_is_spdx_and_license_file_is_verbatim_agpl`.
- **CI matrix** gains 3.13 + 3.14 (Linux legs; the OS matrix stays on 3.12); classifier
  3.14 added; guard `test_ci_matrix_covers_every_claimed_python_version` (a claimed minor
  must be tested somewhere).
- **`MANIFEST.in` prunes `tests/`** — the sdist is the installable source, not the dev
  checkout (the suite runs from git; CONTRIBUTING already says so); guard
  `test_sdist_excludes_tests_tree`. Alternative rejected: including fixtures would take the
  sdist from 470 KB to ~18 MB for every `pip install --no-binary`.
- **`scanner` shim removed** (`src/scanner/` deleted). The import path is outside the
  manifest contract (v1.0.1 precedent) so this is a MINOR; PUBLIC_CONTRACT §3 calls it out
  anyway so no consumer is surprised. Guard `test_legacy_scanner_shim_is_gone`. Six
  `test_unit.py` sites that imported `scanner.scanner as mod` now import
  `file_observer.scanner` — those tests were monkeypatching the *shim's* re-exported
  `olefile` name, not the real module's, and they still pass against the real module.
- **MCP tests: skip only on the absent optional SDK, and never silently in CI.** All 9 sites route
  through `tests/conftest.py::import_mcp_server()`: it `importorskip`s the `mcp` package itself and then
  imports `file_observer.mcp_server` normally — so a fault INSIDE the integration fails rather than
  skipping (Codex P1 on this PR: `exc_type=ImportError` would have let a broken `mcp_server` skip past the
  `test-mcp-majors` jobs). And because a skip is invisible in a green run, `tests.yml` sets
  `FO_REQUIRE_MCP=1` workflow-wide (every job installs `[dev]` ⊇ `[mcp]`): with it, a missing SDK is a
  hard FAILURE, not a skip (Russell: "make sure it doesn't fail silently"); CI pytest runs add `-rs` so
  any remaining skip is at least visible. Verified in all three modes (SDK present → runs; absent → skips;
  absent + FO_REQUIRE_MCP → fails) and guarded by `test_ci_makes_mcp_skips_fail_loudly`.
- **`python -m file_observer`** (`__main__.py` → `scanner.main`); guard
  `test_python_dash_m_entry_point`.
- `CITATION.cff`, root `CHANGELOG.md` (pointer to `docs/HISTORY.md`),
  `.github/dependabot.yml` (pip / actions / docker, weekly, grouped).
- **Repository settings** (out-of-tree; PREPARED, not applied — my session's permission mode blocked the
  repo-settings API calls, so these are Russell's to run; the RFC records what and why): a `main`
  ruleset — PR required, the `tests` workflow checks required, no force-push/deletion, no
  review-count requirement (a solo-maintainer repo — the checks are the gate). The exact ruleset is
  committed at `.github/rulesets/main-pr-and-green-tests.json` (importable via Settings → Rules →
  Rulesets → Import, or `gh api -X POST repos/russalo/file-observer/rulesets --input <file>`).
  Dependabot vulnerability alerts + security updates: `gh api -X PUT repos/russalo/file-observer/vulnerability-alerts`
  and `…/automated-security-fixes`. `.github/dependabot.yml` (version updates) IS in this PR.
- **Docs**: CLAUDE.md refreshed to 1.50.0; every shipped 1.x RFC lacking a SHIPPED status
  gets a status callout under its title (the original status line is kept as written —
  historical docs are not rewritten); HISTORY index re-sorted ascending and split into
  Pre-1.0 / 1.x tables; SECURITY supported-versions rolled.
