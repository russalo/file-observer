# File Observer v1.5.0 RFC Specification

> **Status: Specification (approved 2026-06-02).** Surfaced by the
> infrastructure-standards corpus scan: on 655 real PDFs the PDF specialist
> returned `page_count=None`/`producer=None` for ~all of them and
> `requires_vision=True` for 310 born-digital spec books. See
> `scanner-corpora/harvest/FINDINGS.md`.
>
> **Validated (post-implementation re-scan of the 964-file corpus):**
> `requires_vision` **310 → 12** (the 12 are genuinely scanned), `page_count`
> populated **9 → 341**, `producer` **9 → 308**. Object-stream PDFs correctly
> return `page_count=None` (honest null, never a wrong value — §1.2).

## 1. Overview

### 1.1 Purpose

Fix the PDF specialist's **bounded-observation blind spot** — the same bug class
the OLE2 specialists (msg/doc/xls) had before v0.7.1. Both `_extract_pdf_metadata`
and `detect_requires_vision` read only the **8 KB head sample**, but:

- a PDF's page tree (`/Count`) and `/Info` dict (producer/title) live in the
  **trailer at the file END** → `page_count`/`producer` null for nearly all PDFs;
- born-digital PDFs **compress their content streams** (FlateDecode), so the head
  has no plaintext `BT`/`/Font` text markers → `detect_requires_vision` wrongly
  flags them as needing vision (310/655 in the corpus, all multi-hundred-page
  vector spec books).

The specialist already **receives `path` + a 128 KB `budget`** (like the OLE2
specialists) and the whole file is already read for the checksum — it just
ignores them. v1.5 reads the **head + a bounded tail** and regexes both. Stdlib
only, no new dependency (decision 2026-06-02).

### 1.2 Honest scope / residual

Reading head+tail by regex populates metadata and fixes the misroute for the
large class of PDFs with **uncompressed** xref/Info (older, linearized, many
government PDFs). It does NOT solve **PDF 1.5+ object-stream** PDFs, which
compress the page tree / xref / Info / `/Font` refs into streams invisible to
regex — for those, `page_count`/`producer`/`text_detected` are **null/false**
(never a *wrong* value: the page tree compresses all-or-nothing, so a partial
leaf `/Count` is not surfaced as the total — confirmed on the corpus, where the
big object-stream spec books return `page_count=None`, not an undercount).
Resolving them would need a real PDF parser; explicitly out of scope per the
stdlib decision. An improvement, not a perfect fix, and LIMITATIONS says so.

### 1.3 Normative Language

MUST / SHOULD / MAY per BCP 14.

## 2. PDF metadata via head + bounded tail

`_extract_pdf_metadata(path, sample, budget)` (was `(sample)`) MUST read the
head sample AND a bounded tail (the last `budget` bytes via `seek`, default
128 KB — the existing specialist deviation budget) and regex over both regions:

- **`page_count`** = the **maximum** of all `/Count\s+(\d+)` matches over
  head∪tail. The root `/Pages` object carries the largest `/Count` (intermediate
  page-tree nodes carry partial counts), so max is the total. Null if none found.
- **`/Info` fields** (`title`, `author`, `producer`, `creator`) = regex over
  head∪tail, matching BOTH literal `(...)` and hex `<...>` string forms.
- `creation_date`, `encrypted` (`/Encrypt`), `pdf_version` (`%PDF-x.y` header),
  `has_text_streams` — unchanged (head suffices; version is at offset 0).
- **NEW provisional field `text_detected`** (bool): `/Font` or a text operator
  (`BT`) present anywhere in head∪tail → the PDF has extractable text. This is
  the honest born-digital-vs-image signal (with the §1.2 object-stream caveat).
- `sample_text_marker_density` — RETAINED but documented head-only/limited (it is
  ~0.0 for all real PDFs; kept for continuity, no longer the vision signal).

Bounded-observation deviation is declared (head + 128 KB tail), exactly as
XLSX/DOCX declare their 128 KB budget. Deterministic.

## 3. `requires_vision` fix (LOGIC change)

`detect_requires_vision` MUST take `path` and, for `.pdf` + binary, decide on
head + bounded tail rather than the head alone:

- `requires_vision = True` only when **no text markers** (`/Font`, `BT`) are found
  in head∪tail **AND** image-only markers are present (`/Image`, `/XObject`,
  `/DCTDecode`, `/CCITTFax`) — i.e., the PDF looks scanned/image-only.
- Any `/Font`/text marker anywhere in the read → `requires_vision = False`
  (it has extractable text). New provenance triggers
  `pdf_text_in_tail` / `pdf_image_only` / `pdf_no_markers` replace the old
  head-only `pdf_no_text_markers`.
- The whole file is already read for the checksum, so the bounded tail read adds
  negligible I/O to the universal tier.

Residual (§1.2): an object-stream PDF that compresses its `/Font` refs may still
mis-flag; documented, conservative (errs toward `requires_vision` when genuinely
unsure — null-means-not-seen discipline).

## 4. Schema & Version Constants

- `SCANNER_VERSION` 1.4.0 → **1.5.0**.
- `LOGIC_VERSION` 1.3.0 → **1.4.0** (`requires_vision` routing changes — fewer
  PDFs flagged; some `requires_vision` true→false).
- `SCHEMA_VERSION` 1.3 → **1.4** (additive: provisional `specialist_metadata.pdf.text_detected`).
  `page_count`/`producer` are existing fields now better-populated — not a schema change.
- No chatlog method_version change (PDF is a specialist, not a vector).
- v1.0 public contract holds — no field removed/renamed/retyped.

## 5. Backward Compatibility

- **`requires_vision` values change** for PDFs (the intended LOGIC bump) — many
  born-digital PDFs flip true→false. `routing_summary.requires_vision` drops.
  Golden manifests MUST be regenerated; every flip reviewed as a correct fix.
- `page_count`/`producer`/`text_detected` newly populated where the head missed
  them — additive enrichment, tracked by LOGIC.
- No manifest field removed/renamed/retyped.

## 6. Validation Plan (falsify-first; the infra corpus is the ground truth)

The `corpora_infra/` corpus IS the adversarial test bed:
- **born-digital spec books** (Caltrans 17 MB, TxDOT 7 MB, the 50 state books,
  DC Water, Mesa) MUST get `page_count != None`, `text_detected = True`,
  `requires_vision = False`.
- **scanned/image drawings** (Washoe County details, scanned WSDOT plans) SHOULD
  get `requires_vision = True`, `text_detected = False`.
- **synthetic minimal PDFs** (vector text; image-only) — falsify-first unit cases
  asserting the boundary, written before the fix.
- **documented residual** (asserted): an object-stream PDF may still miss
  metadata / mis-flag — pinned so the boundary move is deliberate.
- Re-scan `corpora_infra/` after the fix: confirm `requires_vision` count drops
  toward the genuinely-scanned subset and `page_count`/`producer` populate.
- Full suite + golden regen + three review layers (in-house multi-agent + Gemini
  cross-model + PR bots).
