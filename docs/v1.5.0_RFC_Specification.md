## 1. Overview

### 1.1 Purpose

Fix the PDF specialist's **bounded-observation blind spot** — the same bug class
the OLE2 specialists (msg/doc/xls) had before v0.7.1. Both `_extract_pdf_metadata`
and `detect_requires_vision` read only the **8 KB head sample**, but:

- a PDF's page tree (`/Count`) and `/Info` dict (producer/title) live in the
  **trailer at the file END** → `page_count`/`producer` null for nearly all PDFs;
- born-digital PDFs **compress their content streams** (FlateDecode), so the head
  has no plaintext `BT`/`/Font` text markers → `detect_requires_vision` wrongly
  flags them as needing vision (310/655 in the corpus, all multi-hundred-page
  vector spec books).

The specialist already **receives `path`** (like the OLE2 specialists) and the
whole file is already read for the checksum — it just ignored it. v1.5 reads:
**(a)** a fixed head+tail window (`PDF_MARKER_BUDGET`, 128 KB) for the text/image
markers (`text_detected` AND `requires_vision` use the *same* window so they
cannot contradict), and **(b)** the **whole file** (capped at 64 MB) for
`page_count` + `/Info`, so the root page tree and trailer Info are found wherever
they sit. Stdlib only, no new dependency (decision 2026-06-02).

`page_count` is anchored to `/Type /Pages` dicts — `/Count` is NOT unique to the
page tree (`/Outlines`/annotations/AcroForms use it), so an un-anchored max
mis-reported bookmark counts as pages (caught in review). `/Info` strings honor
PDF backslash escapes (so `Title (… \(x\) …)` isn't truncated) and are gated on
`/Encrypt` (encrypted strings → null, not ciphertext garbage). `%PDF-` is found
within the first 1 KB (tolerates a leading BOM).

### 1.2 Honest scope / residual

The whole-file read + `/Pages` anchoring make `page_count`/`producer` reliable
for PDFs whose page tree / Info are **uncompressed** (the common case). Residuals:
- **PDF 1.5+ object-stream** PDFs compress the page tree / Info / `/Font` refs
  into streams invisible to regex → `page_count`/`producer`/`text_detected` are
  **null/false** (an honest "not observed" — the page tree compresses
  all-or-nothing, so a partial leaf `/Count` is never surfaced as the total).
- **PDFs larger than 64 MB** fall back to the head+tail window for page_count/Info
  (the root tree could be in the unread middle → null).
Resolving the object-stream case would need a real PDF parser; explicitly out of
scope per the stdlib decision. An improvement, not a perfect fix; LIMITATIONS
says so. **The "never wrong" framing in the approved draft was an over-claim** —
review showed an un-anchored `/Count` max *could* be wrong (bookmark over-count);
anchoring to `/Type /Pages` + the whole-file read fixed it, and the residual is
now honest *null*, not a wrong value.

### 1.3 Normative Language

MUST / SHOULD / MAY per BCP 14.

## 2. PDF metadata (markers: head+tail; page_count/Info: whole file)

`_extract_pdf_metadata(path, sample, budget)` (was `(sample)`) uses TWO read
windows (the `budget` param is accepted for caller uniformity but not used to
size PDF reads — see below):

- **Markers** — `has_text_streams`, `text_detected` — over a fixed head + tail
  window (`PDF_MARKER_BUDGET`, 128 KB), the SAME window `detect_requires_vision`
  uses, so they cannot contradict.
- **`page_count` + `/Info`** — over the **whole file** (read up to
  `PDF_FULL_READ_CAP`, 64 MB; larger files fall back to head+tail). This finds
  the root page tree and trailer Info wherever they sit, not just in a tail window.

Fields:
- **`page_count`** = the max `/Count` belonging to a **`/Type /Pages`** dict.
  `/Count` is NOT unique to the page tree (`/Outlines`, annotations, AcroForms use
  it), so it MUST be anchored to `/Type /Pages` (an un-anchored max reported a
  bookmark count as pages — review). The search spans the enclosing object
  (forward to `endobj`, capped) so a flat tree's large `/Kids` array or a nested
  `/Resources<<…>>` doesn't hide `/Count`. Null if no `/Type /Pages` is plaintext.
- **`/Info` fields** (`title`, `author`, `producer`, `creator`) — literal `(…)`
  (depth-aware: balanced + backslash-escaped parens) AND hex `<…>` (FEFF/UTF-16BE
  aware; odd-length pads a trailing 0 per ISO 32000 §7.3.4.3). **Gated on
  `/Encrypt`** — encrypted PDFs encrypt their /Info strings, so emit null rather
  than ciphertext garbage.
- `pdf_version` — `%PDF-x.y` searched in the first 1 KB (tolerates a leading BOM).
- **NEW provisional `text_detected`** (bool): `/Font`/`BT` in the marker window →
  extractable text (the born-digital-vs-image signal; §1.2 object-stream caveat).
- `sample_text_marker_density` — RETAINED, head-only/limited (~0.0 for real PDFs;
  no longer the vision signal — `text_detected` is).

## 3. `requires_vision` fix (LOGIC change)

`detect_requires_vision(path, …)` decides over the same head+tail marker window
(`PDF_MARKER_BUDGET`), not the head alone:

- `/Font` / `BT` / `/Text` present → `requires_vision = False`, trigger
  **`pdf_text_detected`** (has extractable text).
- else image markers present (`/Image`, `/XObject`, `/DCTDecode`, `/CCITTFax`,
  `/JPXDecode`, `/JBIG2Decode`) → `requires_vision = True`, trigger
  **`pdf_image_only`**.
- else (no markers — e.g. an object-stream PDF compressing both) →
  `requires_vision = False`, trigger **`pdf_no_markers`** — conservatively NOT
  vision (a likely-compressed-but-textual PDF; err away from a false "needs OCR").

The whole file is already read for the checksum, so the bounded marker read adds
negligible I/O. Residual (§1.2): an object-stream PDF compressing its `/Font`
refs with no image marker falls to `pdf_no_markers` (not flagged) — documented.

## 4. Schema & Version Constants

- `SCANNER_VERSION` 1.4.0 → **1.5.0**.
- `LOGIC_VERSION` 1.3.0 → **1.4.0** (`requires_vision` routing changes — fewer
  PDFs flagged; some `requires_vision` true→false).
- `SCHEMA_VERSION` 1.3 → **1.4** (additive: provisional `specialist_metadata.pdf.text_detected`).
  `page_count`/`producer` are existing fields now better-populated — not a schema change.
- No chatlog method_version change (PDF is a specialist, not a vector).
- v1.0 public contract holds — no field removed/renamed/retyped.

## 5. Backward Compatibility

- **`requires_vision` values change** for PDFs (the intended LOGIC bump) — many
  born-digital PDFs flip true→false. `routing_summary.requires_vision` drops.
  Golden manifests MUST be regenerated; every flip reviewed as a correct fix.
- `page_count`/`producer`/`text_detected` newly populated where the head missed
  them — additive enrichment, tracked by LOGIC.
- No manifest field removed/renamed/retyped.

## 6. Validation Plan (falsify-first; the infra corpus is the ground truth)

The `corpora_infra/` corpus IS the adversarial test bed:
- **born-digital spec books** (Caltrans 17 MB, TxDOT 7 MB, the 50 state books,
  DC Water, Mesa) MUST get `page_count != None`, `text_detected = True`,
  `requires_vision = False`.
- **scanned/image drawings** (Washoe County details, scanned WSDOT plans) SHOULD
  get `requires_vision = True`, `text_detected = False`.
- **synthetic minimal PDFs** (vector text; image-only) — falsify-first unit cases
  asserting the boundary, written before the fix.
- **documented residual** (asserted): an object-stream PDF may still miss
  metadata / mis-flag — pinned so the boundary move is deliberate.
- Re-scan `corpora_infra/` after the fix: confirm `requires_vision` count drops
  toward the genuinely-scanned subset and `page_count`/`producer` populate.
- Full suite + golden regen + three review layers (in-house multi-agent + Gemini
  cross-model + PR bots).
