## 1. Motivation

v1.38 counts a consumer's lexicon terms in a file's **body text**. But a risk term can hide where the body scan structurally never looks — a **filename**, an **EXIF make/model**, a **PDF producer/title/author**, an **email subject**, an office **application** string. The body scan reads text; it never sees the binary metadata or the path. So a term sitting in metadata is invisible today.

This is the *detection* half of the r/mcp finding that drove v1.40: v1.40 keeps attacker-controlled strings out of the model (prevention); this flags a lexicon term when it's hiding in the metadata (detection). It **reuses v1.40's `FIELD_TRUST` classification** to know exactly which fields are file-derived, and reuses the v1.38 matcher unchanged.

## 2. Measure-first (the gate — PASSED)

`scratch/measure_self_sweep_2026-07-12.py`, a benign values-neutral lexicon (device makers / software / common doc words), **307 real files**:

- **122 files (40%)** had a metadata hit; **57 files (19%) had a metadata-ONLY hit** — a term the body scan missed entirely. That is the coverage gap this feature fills.
- The gap is exactly the hiding-in-metadata surface: a **scanned** PDF's producer (`20250718.pdf`: 3 software hits, body 0 — no body text at all); office `application` metadata on binary `.docx`/`.xlsx` (body not text-scanned); filename words ("notes", "Excel", "Bid Form").
- The metadata surface is **bounded** (short strings) → no untrusted-size concern, unlike the 64 MiB body read.
- **Dedup confirmed:** `content_preview` is excluded (it's a body slice, already counted by the v1.38 body scan) — body-covered terms are not double-counted.

**Verdict: not redundant with the body scan; it covers a surface the body scan can't reach. Proceed.**

## 3. Design

Reuse the pure `_lexicon_scan(text)` matcher (scanner.py:7680) over the **collected file-derived metadata strings**, separately from the body scan.

- **Target fields** (file_derived per `FIELD_TRUST`, minus the body): `filename`, `tags`, `frontmatter`, `structural` (title/headings/keys), and the **string leaves inside `specialist_metadata`** (image.make/model, pdf.producer/title/author, document.title/author, email.subject/from, video.make/model, audio.artist/title, …). **Excluded:** `content_preview` (body-covered), the `lexicon_match` namespace itself (fo-generated), and pure fo-derived enums are harmless to include but add no signal.
- **Bounded:** cap the collected metadata text (e.g. `LEXICON_METADATA_MAX_CHARS`, generous but finite) — metadata is short, but a hostile PDF could carry a huge producer string; cap it (declared).
- **Dormant without a lexicon** → existing manifests byte-identical (the v1.38/v1.30 gated pattern).

## 4. Output (additive, provisional)

Extend the existing `lexicon_match` namespace so body and metadata stay **separate and comparable**:

```jsonc
"lexicon_match": {
  "lexicon_id": "...",
  "categories": {cat: {count, density}},   # BODY (unchanged, v1.38)
  "total_hits": N, "total_tokens": T,      # BODY (unchanged)
  "metadata": {                            # NEW (v1.41, provisional)
    "categories": {cat: {count, density}},
    "total_hits": M, "total_tokens": U
  }
}
```

The existing `lexicon_match` safety_flag fires on a body OR metadata hit (a hit is a hit; presence, not verdict). The body path stays byte-identical for a body-only file (the `metadata` block is additive).

## 5. Versioning

- **SCHEMA 1.22→1.23** — new provisional `lexicon_match.metadata` field (additive contract-shape change; the v1.35 new-field-in-existing-namespace precedent).
- **LOGIC 1.21.0→1.22.0** — new derived values move `manifest_checksum` **only on lexicon scans** (the v1.29/v1.33 values-move + v1.38 gated precedent); no routing flag flips; no-lexicon scans byte-identical.
- **lexicon method_version 1→2** — sweeping metadata is a new rule → feeds the `lexicon` vector `rules_hash`.

## 6. Bounded/never-crash

Metadata strings come from already-parsed, already-bounded specialist output + the (bounded) filename/frontmatter/structural. The matcher is the v1.38 streaming/length-keyed tokenizer (ReDoS-safe, O(bounded) memory). Add the metadata-text cap (§3). No new untrusted-binary parsing.

## 7. Decisions (LOCKED 2026-07-12, Russell)

- **D1 — output shape = category-level (a): the `lexicon_match.metadata` sub-block with per-category counts.** NOT per-field attribution. Rationale (Russell): the consumer's question is "**is this file safe?**", a routing decision — category + where (body/metadata) answers it; *which* field tripped is detail nobody acts on. Per-field is a deferred non-goal (§10).
- **D2 — target fields = all of them:** `filename` (NOT the full path — the dir tree is the operator's, not the file's metadata) + `tags` + `frontmatter` + `structural` + the string leaves in `specialist_metadata` (minus the `lexicon_match` namespace). `content_preview` excluded (body-covered).
- **D3 — one flag.** Reuse the existing `lexicon_match` safety_flag for a body OR metadata hit — a hit is a hit, the file tripped the lexicon (follows directly from D1's "is this file safe" framing). No distinct metadata flag.
- **D4 — density base = metadata tokens** (self-consistent within the `metadata` block).

## 8. Testing (falsify-first, `test_v1_41.py`)

- **Coverage:** a file with a benign term ONLY in a metadata field (filename / a crafted PDF producer / EXIF make) and NOT in the body → `metadata.total_hits > 0` while body `total_hits == 0`.
- **Dedup:** a term in the body only → body counts it, `metadata.total_hits == 0` (content_preview not swept).
- **Dormant:** no lexicon → no `metadata` block, manifest byte-identical.
- **Bounded:** a hostile huge metadata string is capped, never hangs.
- **Determinism:** workers 1-vs-N byte-identical; values move only on lexicon scans.
- Version axes: SCANNER 1.41.0, LOGIC 1.22.0, SCHEMA 1.23.
