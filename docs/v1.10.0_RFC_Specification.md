# File Observer v1.10.0 RFC Specification

**Status: SHIPPED** — released as v1.10.0 (see `docs/HISTORY.md` for the date and the patch releases that rode on this minor). The status line below is the RFC's state at approval time, kept as written.

> **Status (at approval time): Specification (approved 2026-06-05).** A **provisional-lifecycle** release: the first
> deliberate promotion pass since v0.11 — graduate the provisional fields whose
> producing logic is *settled* to **stable**, and (under a deliberately **liberal
> intake stance**) admit several cheap observe-only signals as new provisional fields.
> The principles: **promote only when producing logic is settled; never
> promote-and-extend the same vector in one release; and be liberal admitting *cheap,
> observe-only* provisional fields** — provisional is the low-commitment data-gathering
> tier (v0.9 intent), so "no confirmed consumer yet" is what it *probes*, not a reason
> to withhold. The bar that doesn't relax: observe-only, deterministic, and
> never-crash/bounded for any new parser path (so a *heavy new parser* still gets the
> measured treatment, §4.4).
>
> **Recommended cut (§3, §4):** promote 5 settled fields (`duplicate_clusters`
> family, `specialist_stats`, `errors[].detail`, `pdf.text_detected`,
> `pdf.xref_type`); add **3 cheap provisional fields** — OLE2 producing-app →
> `provenance` (§4.1), a `preservation` format-obsolescence block (§4.2), summary
> top-N (§4.3); **hold from promotion** the chatlog family + `pdf.parser` + `provenance`
> (the latter because §4.1 *extends* it). One open fork (§7): provenance
> promote-vs-hold (coupled to §4.1).
>
> **Also introduces the `candidate` tier (§4.4)** — a watch-and-measure tier *below*
> provisional for held observations (CAD, EXIF, word-twisting): tracked with a
> held-reason + a cheap **sweep-side** harvest + a promotion trigger, but **never in
> the public manifest**. The ladder is now **candidate → provisional → stable**, so the
> decision to promote a candidate up becomes evidence-backed at zero contract cost.

## 1. Overview

### 1.1 Purpose

v1.0 froze the schema and made the pitch: *a deterministic, stable contract for
pipelines.* But provisional fields have accumulated across v1.1→v1.8 — consumers
can't safely build on them, which leaves that pitch half-kept. This release runs the
provisional **lifecycle** in both directions: graduate the matured fields to stable
(harvesting work already validated across many releases + the sweep + the
49,879-file shakedown), and admit the next recommended provisional input. No
detection or routing behavior changes; **`LOGIC_VERSION` is unchanged**.

### 1.2 The promotion criterion (the non-obvious part)

The right cut is **not age** — it is whether a field's *producing logic is settled*.
You don't promote a field to "rely on this" when a known, pending change is about to
alter how it's populated. Two fields are old enough but **held** for exactly that
reason: the chatlog family (the non-count-signal redesign reworks content-shape) and
`pdf.parser` (the tier-2 `/Info`-via-stdlib upgrade changes which tier fills things).

### 1.3 Normative Language

MUST / MUST NOT / SHOULD / MAY per BCP 14.

## 2. Scope discipline (what v1.10 is NOT)

- **NOT a detection/routing change.** No field's *value* changes for any file;
  promotion changes only the **stability promise**. `LOGIC_VERSION` stays `1.4.3`.
  (The one value-affecting item is the additive OLE2 producing-app input to
  `provenance` — and `provenance` is held provisional precisely so that's safe.)
- **NOT a shape change to promoted fields.** Promotion is a contract designation; the
  fields already exist and already populate identically.
- **NOT speculative field-creation.** New provisional fields are admitted only where a
  need *pulls* (§4). The preservation probe (§7 fork) is the one judgment call.
- **The observe→interpret line holds, hard.** Nothing introduced here scores,
  classifies, or judges. Preservation "obsolescence" is a *closed-table lookup on the
  observed format*, not a risk verdict — same discipline as `safety_flags`
  ("structure observed," never "dangerous") and the `provenance` toolchain table.

## 4. New provisional intake

**Stance (decided): be liberal here.** Provisional is the low-commitment
data-gathering tier (the v0.9 intent) — surfacing a deterministic, observe-only
signal and marking it "may change" is *how* we learn whether it's worth promoting;
"no confirmed consumer yet" is what provisional *probes*, not a reason to withhold.
The bar that does **not** relax: observe-only (no scoring/classifying), deterministic
(+ a `rules_hash` fingerprint if rule-driven), and **never-crash/bounded if it opens
a new parser/IO path** (the v1.8.1 lesson — every new extraction surface is a new
untrusted-input attack surface). So: seat the **cheap** observe-only additions
(lookup / aggregation / extend-existing), stay measured only on a **heavy new parser**
surface (§4.4). Soft cost — manifest clutter — is mitigated by the clear provisional
marking + the v1.9.1 specialist-maturity tiers.

### 4.1 OLE2 producing-app → `provenance` (cheap — extends existing)
The `provenance` vector's `toolchains` are fed by PDF producer/creator + OOXML
`docProps/app.xml` `<Application>` — but **legacy OLE2 `.doc`/`.xls` contribute
nothing** (LIMITATIONS documents this as the deferred gap; an Office-heavy corpus
under-counts toolchains). This is a *concrete, already-identified* gap — not
speculation. Fill it: read the **creating application** from the OLE2
`SummaryInformation` stream (`olefile.get_metadata().creating_application`, which the
`.doc`/`.xls` specialists already open for title/author), surface it as the additive
provisional `specialist_metadata.{document,spreadsheet}.application` field (mirroring
docx/xlsx), and feed it into `provenance` via the **same closed toolchain table**.
`provenance` `method_version` 1→2 (new input source); it stays provisional (§3.2).
Pure extraction → `LOGIC_VERSION` unchanged.

### 4.2 Preservation / format-obsolescence signals (SEATED — cheap, new)
A per-file provisional `preservation` block (`format_obsolescence`:
`current`/`at_risk`/`obsolete`, `migration_recommended`: bool) driven by a **closed,
versioned obsolescence table** keyed on the v1.3 format id — the `provenance`
toolchain pattern exactly (deterministic; the table feeds a `rules_hash`/identity
fingerprint so an edit moves the digest). Conceptual basis: **PREMIS**
(STANDARDS_TRACKING; `standards_roadmap.md` §3). **Lookup-only — no new dependency,
no new parser path.** No active consumer pulls it yet, and under the liberal stance
**that is exactly what its provisional status is for**: surface it, gather
archival/governance-market data, promote (or drop) on evidence rather than guess.

### 4.3 Richer summary top-N (SEATED — cheap, new)
Surface top-N in the human summary: top authors (from `author_aggregate`) and top
reference domains (from `reference_tokens`) — **aggregation of data already
collected**, no new extraction. Deterministic via a total-order sort (count desc,
then key asc — the `duplicate_clusters` tiebreak pattern). New provisional summary
fields; pure aggregation → `LOGIC_VERSION` unchanged.

### 4.4 The candidate tier (below provisional) — track + harvest, don't surface
Some observations are held from even *provisional* for a substantive reason — but
"held" shouldn't mean "forgotten" or "decided later by guess." v1.10 introduces a
**candidate tier below provisional**: a tracked registry of held observations, each
with **(a)** the *reason held*, **(b)** a *safe, cheap harvest* — a minimal proxy
gathered in the **empirical sweep's instrumentation** (`corpus_sweep.py`), **never a
manifest field, never a new scanner parser surface, never sensitive values** — that
tells us whether the full field is worth building, and **(c)** the *promotion
trigger* (what would move it up to provisional). The ladder is now **candidate →
provisional → stable**. The defining line: **candidates are NOT in the public
manifest** — provisional is the first manifest tier; candidate is the watch-and-measure
tier beneath it. A candidate therefore costs nothing in the contract and opens no new
untrusted-input surface in the scanner; the harvest lives entirely in the measurement
apparatus, which is the data-gathering harness anyway.

**Initial candidate registry:**
| Candidate | Held because | Safe harvest (in the sweep, NOT the manifest) | Promotion trigger → provisional |
|---|---|---|---|
| **CAD (DGN/DWG)** | a heavy new parser on untrusted binary (+ likely a new dep) — a real never-crash/bounded surface (v1.8.1) | **prevalence**, already visible in the sweep's `format_sig_dist` (we *detect* the format via signature without parsing it) | enough CAD in real corpora to justify a red-teamed bounded reader |
| **Image EXIF / GPS** | location/privacy sensitivity | an **EXIF-presence** count the sweep computes by reading the image header for the marker — *presence only, never the GPS/camera values* | demand + a settled "observe-presence, you-decide-values" framing (likely opt-in) |
| **Word-twisting provenance** (first-appearance speaker / cross-speaker uptake) | data-gated on the tagged RPG corpus | none code-side — the "harvest" is the corpus tagging itself (external, your call) | the tagged corpus exists **and** the hypothesis (speaker-attribution predicts canon) validates |

Promotion **candidate → provisional** requires both: the held reason resolved *and*
the harvest showing the signal is worth surfacing. This makes the roadmap decision
evidence-backed (the measure-first / Wayne-K instinct applied one tier down), at zero
manifest/contract cost. The registry's home is `CONVENTIONS.md` (the tracking
inventory) + the sweep's harvest code.

No existing field changed/removed/retyped. The promoted fields keep identical
shape + values; the new fields are additive and null/absent where not applicable.

## 6. Validation Plan (falsify-first)

1. **Promotions — zero-diff proof.** The empirical sweep + a golden manifest MUST be
   **byte-identical** before/after the promotion commits (promotion changes only docs
   + the contract table — *if any manifest value changes, the "designation-only" claim
   is false*). This is the falsifiable guard.
2. **OLE2 producing-app — additive, never overwrites.** On the corpus, `provenance`
   toolchain counts may only **rise** (legacy Office now contributes); no existing
   producer value changes. A `.doc`/`.xls` fixture with a known creating-app asserts
   the new `application` field + its toolchain normalization; the `provenance`
   identity digest moves with `method_version` 2 (determinism contract).
3. **Preservation (if seated) — closed-table determinism.** The obsolescence table
   feeds the `rules_hash`; a table edit MUST move the identity digest (the recurring
   "rule data that gates output must be in the hash" bug class). Lookup-only; no I/O.
4. **All four review legs** per `decorrelated-code-review` — the in-house swarm angle
   that matters: "does any promoted field's value actually change?" (it must not).
