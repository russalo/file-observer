## 1. Summary

The chatlog specialist emits three new **flat top-level scalars** in the `chatlog` block:
`first_timestamp` / `last_timestamp` — the **min/max of the turn timestamps**, each normalized to
canonical ISO-8601 UTC (`…Z`, fixed precision) — and `cwd` — the session's working directory,
observed verbatim (first-seen). Each is null when the log doesn't carry it. A deterministic pure
function of the file — textbook observe-charter, the same family as the `ai_session` usage pass
(a bounded walk collecting recognized fields; read, don't derive/interpret).

## 2. Motivation

**recall FR (their #62 — two axes on the session node).** A SESSION node carries neither a
timestamp nor a source path — *turns* carry the timestamp, and session nodes are **sourceless**
(synthetic, no `@source`, trellis-verified) — yet token-usage aggregates live on the session node.
So recall can bucket usage neither by **time** (per week/month) nor by **project** (path-scope).
Both facts must become **attrs on the session node**. Surfacing them gives recall a `$gte/$lt`
time bucket AND a `$prefix` project filter. recall correctly rejected the alternatives (a meta-record
in its read-only corpus = forbidden; recall-side bucketing/scoping = engine-creep) and came to the
seam — both are fo's charter shape (observe a fact in the file; recall owns the cwd→project semantics
via its PROJECTS.txt).

**Cleared across all three stakeholders (2026-07-07):**
- **recall (requester):** FR accepted; **flat scalar** shape spec locked (a nested
  `timestamps:{…}` would bury as one opaque non-queryable attr; flat = zero trellis change).
- **trellis (downstream):** flat top-level chatlog scalars auto-surface as range-queryable
  `observed.chatlog.first_timestamp` with **zero trellis change**; will verify surface+query at ship.
- **Sentinel (soft-contract holder):** **concurs with `chatlog` placement.** Grep-verified: reads
  none of the chatlog-namespace fields at runtime; its golden test asserts only
  `CHATLOG_SPEAKER_LABEL_RE` (untouched); no fo-checksum golden test exists → the LOGIC bump is
  invisible to it; its speaker-labeled-markdown corpora are the null case. No RFC-open input needed
  unless scope touches speaker labels / `is_chatlog` detection (it does not).

## 3. Measure-first (DONE — grounded on real corpora, 2026-07-07)

Probed real chatlog corpora for per-turn timestamp keys + formats (`scratch/measure_chatlog_timestamps_2026-07-07.md`):

| corpus | key | format | result |
|---|---|---|---|
| federation Claude Code (`.jsonl`) | `timestamp` (top-level) | `2026-07-04T06:09:38.131Z` — ISO, **Z**, **ms** | populated |
| oasst1 | `created_date` (nested, per message node) | `2023-02-05T14:23:50.983374+00:00` — ISO, **+00:00**, **µs** | populated |
| ChatGPT export (documented, not in corpus) | `create_time` | **float epoch seconds** | populated |
| sharegpt · hh-rlhf · movie-corpus · convokit · polyai | — | none | **null** |

**What it settled (design was grounded, not guessed — the ai_session lesson):**
- **Q1 (which keys):** the recognized set is `timestamp`, `created_date`, `create_time`, `created_at`
  — the observed two (`timestamp`/`created_date`) + the documented ChatGPT `create_time` + the common
  `created_at`. **Generic `date`/`time`/`created` are EXCLUDED** (FP risk — a `date` field is often a
  referenced date, not the turn time; the recognized-key gate discipline from ai_session).
- **Q2 (format variance — the load-bearing finding):** two populated corpora, **two different formats**
  (`Z` vs `+00:00`; ms vs µs; plus epoch-float for ChatGPT). Raw lexical min/max across these is WRONG,
  and `+00:00`/`Z` are the same instant with different bytes. → **normalization is mandatory**: parse
  each recognized value (ISO string OR numeric epoch) → aware UTC datetime → min/max → emit **canonical
  ISO-8601 UTC (`…Z`, fixed precision)**. This is precisely what makes recall's flat scalar `$gte/$lt`
  correct (canonical ISO-UTC is lexically == chronologically ordered).
- **Q3 (location):** timestamps appear **nested** (oasst message tree), not only top-level (Claude Code)
  → the extraction must **walk** the objects, not just read the line root — same shape as the ai_session pass.
- **Q4 (null case):** confirmed on 5 corpora with no per-turn timestamps → `null`. Honest: the time axis
  exists only where turns are timestamped, which is exactly the agentic logs recall wants to bucket.

**cwd (widened ask):** `cwd` is a top-level string on Claude Code records (×997 present), and
**single-valued per session** (per-file distinct = 1 on every file) → recall's "first-seen is fine" is
*exact* in practice (first-seen = the only value); the multi-cwd edge is confirmed rare/nonexistent.
Null on non-agentic corpora (oasst/sharegpt: 0). e.g. `/srv/projects/pkplab/bestiary`.

## 4. The change

### 4.1 Extraction (a bounded walk, the ai_session shape)
On an `is_chatlog`-detected log, over the same parsed turn objects the chatlog metadata already walks:
- collect every value under a **recognized timestamp key** (`AI …` closed set: `timestamp`,
  `created_date`, `create_time`, `created_at`) at any depth (bounded node walk, the ai_session cap);
- **normalize each** to an aware UTC datetime: an ISO-8601 string → parsed (tz-aware; naive → assume
  UTC, matching fo's existing capture-metadata UTC stance); a numeric (int/float) → epoch seconds → UTC.
  A value that doesn't parse is **skipped** (never crash, never poison min/max — the bounded/never-crash bar);
- `first_timestamp` = min, `last_timestamp` = max, **emitted as canonical ISO-8601 UTC** (`YYYY-MM-DDTHH:MM:SS.sssZ`,
  fixed precision). **Null** when no recognized/parseable timestamp is present.
- `cwd`: the **first-seen** value under a top-level `cwd` string (deterministic file order; single-valued per
  session in practice), emitted **verbatim** (bounded — capped length, the ai_session `MAX_STR` bar). Read,
  don't derive — recall maps cwd→project on its side. **Null** when absent (non-agentic corpora).

### 4.2 Shape (flat — recall/trellis spec)
Three **flat top-level scalars** in the `chatlog` block: `chatlog.first_timestamp`,
`chatlog.last_timestamp`, `chatlog.cwd`. NOT nested. (The chatlog block is already flat — `turn_count`,
`speaker_labels`, … are top-level — so flat is the native shape; trellis's flat pass surfaces them
range-/prefix-queryable with zero change.)

### 4.3 Determinism & bounds
Pure function of the file; canonical ISO-UTC → byte-identical + lexically sortable + stable across
rebuilds. Bounded node walk (the ai_session cap); non-parseable/hostile values skipped, not crashed.
Workers=1-vs-N byte-identical (the standing Layer-A gate). The recognized-key set + the normalization
rule feed the **chatlog `rules_hash`** (an edit moves the digest — the determinism contract).

### 4.4 Non-goals / held lines
- No per-turn timestamp array, no duration/elapsed derivation, no cadence interpretation (min/max only —
  observe, don't interpret). A `duration_s = last − first` would be a derived convenience a consumer can
  compute; fo emits the two endpoints, not the interpretation.
- No new timestamp keys beyond the measured/documented set without a fresh measurement (FP-hygiene).

## 9. Four-leg review outcome (2026-07-07)
Decorrelated legs, and the load-bearing bug was caught by **real-data measurement**, not fixtures (again):
- **leg-1 (in-house swarm):** angle-D 6 findings; the headline — **`last_timestamp` silently truncated on
  >64 MiB sessions** (the full-file read stopped at 64 MiB; the tail, where the last turns live, was never
  read) → **verified on real logs** (a 67 MB session read 3 days short, a 141 MB one 18 days short). Also
  flagged nested-payload timestamp/cwd pollution. (angle-A stalled at 30 min → stopped per the
  never-idle-wait rule; its last output confirmed it was converging on the same year<1000/epoch findings.)
- **leg-2 (Gemini via `gem-pro.sh`, flat AI Pro):** **converged** with leg-1 on the nested-payload pollution
  (decorrelated confirmation), and added the **year<1000 `%Y` zero-pad** sort break. (`gpt.sh`/OpenAI was
  quota-burned 429 → vote missing, not clean; the Gemini leg supplied the cross-model vote.)
- **leg-2b (`static.sh`, non-LLM/semgrep):** clean for the diff (2 pre-existing `globals()` findings flagged
  for later — assessed false positive, logged in scratch).
- **leg-3 (corpus sweep):** ✓ workers byte-identical · ✓ no drift — re-run after the head+tail change.
- **leg-4 (PR bots):** on the PR.

**Fixes applied + tested:** (1) **head+tail read** for the timestamp axes — first from the head, last from
the tail (the v1.5 PDF precedent), so `last_timestamp` is correct at any file size (verified: the 67 MB /
141 MB logs now match ground truth); (2) **skip tool_use/tool_result blocks** when collecting timestamps/cwd
(FP defense, 2-leg-confirmed); (3) **year<1000 zero-pad** in the canonical format; (4) comment fix + the
epoch-seconds-only / naive-UTC assumptions documented in LIMITATIONS. Suite: 1322 passed.
