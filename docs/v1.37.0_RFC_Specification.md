# v1.37.0 — MCP server (agent-native adoption front-door)

**Status:** APPROVED (Russell's build GO, 2026-07-10); shipping. Prototype-validated + finalized.
**Date:** 2026-07-10.
**Proposed axes:** SCANNER 1.36.0→1.37.0 · **LOGIC unchanged (1.20.0)** · **SCHEMA unchanged (1.21)**.
The manifest it returns is checksum-identical to `scan()` (byte-identical modulo the volatile
`scan_id`/`generated_at`, exactly like any two scans) — this is a NEW SURFACE, not a manifest change
(the v1.26 `scan()` / v1.28 `--stdout` / GitHub-Action precedent: additive front-door, contract frozen).
**Prototype-validated (2026-07-10):** all 4 tools work; `scan_summary` on a 218-file folder = ~293 tokens
(the progressive-disclosure design does its job); `scan_directory`'s manifest is checksum-identical to
`scan()`; the size guard fires.

## 1. Motivation
The adoption-by-lowering-barriers track (v1.26–1.28.1) covered produce / pipe / consume / run-anywhere /
CI — but not **agent-native**. MCP is the established protocol for AI agents to call tools, and fo is an
unusually clean fit: **a safe, read-only, deterministic "look before you touch" primitive.** An agent
facing an unknown file tree (a download, an upload, a cloned repo) scans it FIRST — gets a manifest of
what's there — before ingesting or opening anything. fo's whole safety model (read-only, never-executes
content, stays-in-tree, never-crashes, bounded) is exactly what makes it safe to point at UNTRUSTED files
from an agent, where most filesystem MCP tools are a write/exec risk.

## 2. Design principles (the non-negotiables)
- **Universal front-door, NOT a per-consumer connector.** MCP is a standard protocol → any MCP client
  (Claude Code, Claude Desktop, other agents) uses the same server. Consistent with recipes-not-connectors
  (it's the most universal front-door there is, like Docker/the Action — not bespoke glue).
- **Observe-only, mission-clean.** The tools return OBSERVATIONS (manifest / summary); the agent
  interprets. No tool named or described as "is this file safe/malicious" — the descriptions anchor
  "here's what's observable," never a verdict. (This is also a positioning fix — AIs keep misreading fo
  as a watcher; a well-worded tool description puts the correct framing directly in front of them.)
- **Context-size aware (the load-bearing agent-shaping constraint).** fo's manifest is comprehensive —
  a big folder → a huge JSON — and MCP results land in the AGENT'S context. So the tools do PROGRESSIVE
  DISCLOSURE: a compact overview by default, targeted drill-down, and a guarded full dump — never a
  10k-file manifest dumped into a context window by accident.
- **Deterministic.** Same bytes → same manifest → same tool result. An agent gets reproducible answers.

## 3. The tool surface (4 tools, progressive disclosure)
1. **`scan_summary(path, specialists=false)`** — the DEFAULT. Returns the compact human-readable summary +
   key stats: file count, type/MIME breakdown, and NOTABLE observations (chatlogs, geotagged, macros/JS,
   polyglots, MIME-vs-extension mismatches, preservation-at-risk). Context-friendly; answers "what's here."
2. **`scan_file(path, specialists=true)`** — the full `FileRecord` for ONE file. Targeted drill-down after
   the summary flags something. (Runs specialists by default — a single file is cheap + the agent asked.)
3. **`scan_directory(path, specialists=false, max_files=N)`** — the full manifest JSON, GUARDED: if the
   tree exceeds `max_files` (a sane default, e.g. 200), it returns the summary + a "too large — narrow the
   path or raise max_files" note instead of blowing the context. The escape hatch for a real full manifest.
4. **`describe_surface(format="md")`** — the `--schema` output (every field / specialist / vector / flag /
   error code fo can emit). The reference for an agent writing a consumer or reasoning about the shape.

(All read-only. `scan_summary` is the one an agent reaches for first; the others are deliberate.)

## 4. Transport
- **stdio FIRST** — the natural local fit. fo scans the LOCAL filesystem (the agent's machine), so a local
  stdio server is the right primary. The agent's MCP client (Claude Code / Desktop) already grants the
  filesystem scope; fo runs under it.
- **HTTP / streamable-HTTP DEFERRED** — a remote fo scanning remote/uploaded files is a different
  deployment (hosted service), lower priority; scope it only if a hosted use-case shows up.

## 5. Packaging & how it runs
- New optional extra **`file-observer[mcp]`** (pulls the official MCP Python SDK, `mcp`).
- Entry point **`file-observer-mcp`** (stdio server) + `python -m file_observer.mcp`. Runnable zero-install:
  `uvx --from "file-observer[mcp]" file-observer-mcp`.
- Client config: a one-block snippet for `claude_desktop_config.json` / Claude Code's MCP config (stdio
  command + args), documented in the README + a new `examples/08-mcp-server/`.
- `[all]` re-derives to include `[mcp]` (self-referencing, drift-guarded — the v1.28.1 pattern).

## 6. Safety
- fo's read-only / never-execute / in-tree / bounded model IS the safety story — make it explicit in the
  README + the tool descriptions (an agent can scan untrusted files without triggering a macro, escaping
  the tree, or hanging).
- **Optional `--root <dir>` allowlist** (defense-in-depth): the server refuses to scan outside a configured
  root, so a mis-prompted agent can't walk it to `/`. Off by default (the client already scopes fs access);
  on for a locked-down deployment. Uses the existing `resolve()`-containment (v1.8.1).

## 7. Versioning
- New surface (entry point + extra) → **SCANNER 1.36.0→1.37.0**; **LOGIC + SCHEMA UNCHANGED** — the
  manifest returned is byte-identical to `scan()` (the v1.26/v1.28 precedent: a front-door, not a contract
  change). `mcp` is a dev+optional dep; the runtime stays zero-required-dep.

## 8. Validation (measure-first / prototype-first)
- Prototype the stdio server + the 4 tools; wire it into a REAL MCP client (Claude Code / Desktop) and
  confirm end-to-end: `scan_summary` on a real folder fits comfortably in context; `scan_file` drills in;
  `scan_directory`'s guard fires on a big tree; `describe_surface` returns the schema.
- **Measure the context cost** — the load-bearing check: `scan_summary` output size on a realistic folder
  (does it stay well under a sane token budget?). If the summary is too big, tighten it before shipping.
- Falsify-first `test_v1_37.py`: each tool returns the expected shape; `scan_directory` guard fires past
  `max_files`; the returned manifest is byte-identical to `scan()` (the front-door contract); `--root`
  refuses an out-of-root path.

## 9. Out of scope / notes
- NOT a watcher-over-MCP (each call is a one-shot scan; `--watch` stays a separate CLI mode).
- NOT remote/hosted by default (stdio/local first).
- NOT new observations — this exposes the EXISTING manifest/summary/schema through a new protocol; zero new
  parsing, zero manifest change.
- Complements (doesn't overlap) recall's MCP wrapper (chatlog SEARCH) — fo's is file OBSERVATION.
