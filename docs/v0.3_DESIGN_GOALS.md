# Scanner v0.3: Operational Fidelity & Expanded Reach

## Core Philosophy: "Report the News"
Scanner is an observation layer. It does not imply intent, classify content, or mutate sources. It provides high-fidelity, deterministic signals so downstream orchestration engines can make informed decisions.

## v0.3 Expansion Goals
1. **Operational Metadata & Auditing**:
   - Introduce `scan_context` (environment finger-printing).
   - Detailed `process_log` per file to track tier-traversal (Universal -> Baseline -> Specialist).
   - Enhance `manifest_checksum` to support multi-stage pipeline validation.

2. **Expanded Surface for Rescanning**:
   - Store state-specific routing flags (`routing_logic_version`).
   - Improve Delta Scan logic to support "Partial Rescans" based on specialist failure codes.

3. **Format Reach (Specialist Tier)**:
   - **.msg**: Extract header-level metadata (Subject, From, To, Date) without body parsing.
   - **.pdf**: Deepen metadata (Page count, encrypted status, text-stream density).
   - **.png**: Extract dimensions, bit-depth, and color-space signals.

## Orchestration Surface
The manifest must be "Rescan-Ready," meaning a downstream program can read a v0.3 manifest and know exactly why a file was routed, skipped, or failed, allowing for targeted remediation.
