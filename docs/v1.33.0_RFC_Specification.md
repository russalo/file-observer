## 1. Summary

An AI session log (Claude Code `.jsonl`, a raw Anthropic/OpenAI/Gemini API dump, a ChatGPT
export) carries two deterministic observables fo currently walks past:

1. **Token usage** — the `usage` block each assistant turn stamps (`input_tokens`,
   `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, and vendor
   equivalents). fo's chatlog walker (`_extract_json_conversation`) keeps only `(role, text)`
   pairs and drops this sibling.
2. **Producer-schema fingerprint** — the log's schema shape identifies which vendor API / tool
   produced it (Claude vs GPT vs Gemini), *deterministically*, from disjoint structural tells —
   most sharply the usage-key vocabulary itself.

fo **observes** both verbatim; the consumer decides what they *mean*. This is the same family as
`is_chatlog` / `fact_block` / `provenance`: structural observation, not per-consumer interpretation.
The two are **one coherent increment** because they share bytes and reinforce each other — the
usage vocabulary is simultaneously the value a consumer wants and the strongest producer tell.

## 2. Motivation

**Ecosystem, bottom-up.** This is fo setting the foundation so the federation builds interpretation
on top, each lane deterministic: **fo observes verbatim → trellis indexes (numeric usage fields
queryable; reuses its `jsonl:` field-config) → recall scopes + cites (may SUM, may not price) →
interpreter judges (cost, budgets, linguistic reads — initially Russell reading recall's honest
aggregates; not its own tool yet).** Judgment concentrates at the top; fo eats only the mechanical,
no-external-knowledge stages.

**The value is real and multi-consumer** — token usage is a *linguistic* signal (verbosity from
output tokens, reasoning depth from the thinking-token share, context reuse from cache tokens) as
much as an operational one; and the producer fingerprint is provenance (whose log is this, and does
its self-claimed `model` agree with its structure). "No external consumer has filed a request" is
**not** the gate here — with essentially one adopter, demand-gating means building nothing; every fo
namespace exists by charter-fit, not by request. Charter-fit is the test, and both observations pass
it cleanly (deterministic, in-the-bytes, verbatim-passthrough — the EXIF/producer precedent).

## 4. The change

### 4.1 Scope & gate
Increment 1 layers on **proven detection**: the observations fire only when the file is already
`is_chatlog` (v1.29 detection) **AND** carries a recognized producer fingerprint or usage block.
Broader "detect an AI log even when chatlog-detection missed it" is **out of scope** (a later
increment). Runs in the baseline tier like chatlog detection (fires even with
`enable_specialists=False`; extraction of the values respects the specialist gate as today).

### 4.2 Token-usage sub-block (verbatim + deterministic aggregates)
Per-session aggregates — each a **pure sum/count of stated values**, no external knowledge:
- `turns_with_usage` (int) — turns carrying a usage block.
- Summed token kinds the log emits, under their **canonical fo names**, mapped from the
  vendor key (§4.3): `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`,
  `reasoning_tokens` (neutral name — Anthropic folds it into output → null there; OpenAI
  `*_details.reasoning_tokens`; Gemini `thoughtsTokenCount`), `total_tokens`. Absent kinds → null
  (not 0 — "not observed" ≠ "zero").
- Vendor-verbatim escape: the raw per-vendor key names are recorded in the producer fingerprint
  (§4.3) so the mapping is auditable and never lossy.

**Full-file read (four-leg review decision, Russell 2026-07-05):** session logs far exceed the 64 KB
baseline window (a real 1.6 MB session = **268** usage turns, of which only ~7 fit in 64 KB → a
windowed sum is a silently-partial ~2.6%). So the usage pass reads the **FULL file bounded to
`AI_SESSION_MAX_FILE_BYTES` (64 MiB)** — a **declared `bounded_deviation`** (`signal_provenance`
trigger `ai_session_full_file`, reason `ai_session_full_file_required`), the OLE2/PDF full-file
precedent (v1.25.1 / v1.5). `usage.truncated` (bool) flags the near-never >cap case so partial sums
stay honest. A read failure falls back to the window (`truncated=true`). Determinism preserved
(pure function of file content; sweep workers byte-identical).

**Reconstructibility guarantee (the bright line):** these are derived-deterministic aggregates whose
parts are always recoverable — the manifest cites the source file (fo does not embed per-turn arrays;
the manifest is a fingerprint, not a re-serialization). fo emits sums; **fo never prices, never flags
"expensive", never labels.** Arithmetic on stated numbers = observation; anything needing a pricing
table or a judgment threshold = the consumer's.

### 4.3 Producer-schema fingerprint (closed table → rules_hash)
A closed, ordered, first-match table (the `MAGIC_SIGNATURES` / provenance-toolchain precedent),
ranked so the **most durable persisted convention wins** over incidental keys:

1. object-id prefix (`msg_`, `chatcmpl-`) + object-type enum (`chat.completion`) — documented,
   vendor-owned, ~never-changing, usually persisted;
2. dated model snapshot (`claude-*`, `gpt-*-YYYY-MM-DD`, `gemini-*-NNN`) — durable, self-versioning
   (a change is a new *value*, not a silent mutation);
3. envelope shape (`content[]` blocks / `choices[]` / `output[]` / `candidates[]`), role vocab
   (Gemini `"model"`), casing (Google camelCase) — architectural, slow, but not contractually pinned.

> **⚠ Measure-first correction (2026-07-05 real log):** the usage-key vocabulary is **NOT** a reliable
> vendor tell — the OpenAI **Responses API** (codex) uses `input_tokens`/`output_tokens`, **identical to
> Anthropic**. The table therefore anchors on **id-prefix + object-type** (tier-1), never usage keys.
> Confirmed on-disk id prefixes: `msg_` (Anthropic), `chatcmpl-` + `object:"chat.completion"` (OpenAI
> Chat), `resp_` + `object:"response"` (OpenAI Responses/codex), `responseId` (Gemini). OpenAI thus has
> **three** distinct surfaces — the `surface` field (decision A) is load-bearing. Evidence:
> `scratch/measure_ai_session_2026-07-05.md` §"Leg 2".

Emits: `vendor` (anthropic/openai/google/`unknown`), `surface` (e.g. `claude_code` vs raw API, when a
wrapper tell is present), `model` (**raw self-claim, verbatim, untrusted**), and any persisted vendor
version token (`system_fingerprint`, `anthropic-version`) **raw**. Ambiguous/absent tells → `unknown`
(honest null, never a guess). The table is **live-derived into `rules_hash`** so a vendor-driven table
edit forces a **dated method_version bump** — drift becomes a visible event, never silent
misclassification ([[project_rules_fingerprint_lens]] — falsifies both fabrication and silent drift).

**Self-check by corroboration:** `model` (a persisted but spoofable self-claim) vs the independent
structural fingerprint. Agreement = high confidence; disagreement (`model` says `claude-*`, envelope
is OpenAI-shaped) = a **mismatch signal**, surfaced — the MIME-vs-extension pattern. fo reports the
pair; it does not adjudicate.

### 4.4 Namespace placement — LOCKED: a new provisional `ai_session` namespace (decision A)
**Approved 2026-07-05.** A new provisional `ai_session` namespace (sibling to `fact_block`/`audio`),
NOT sub-blocks on the alpha-locked `chatlog` surface. Rationale: keeps Sentinel's soft-contract
`chatlog` surface untouched (free for the pending non-count redesign); the data is *operational*, not
conversational; the producer fingerprint applies to AI logs specifically, a subset of chatlogs.
Consequence: `ai_session` carries its **own vector** (its own `vector_id`/`method_version`/`rules_hash`),
so §4.6's fingerprint feeds the `ai_session` vector, not `CHATLOG_RULES_DEFINITION`; chatlog
method_version stays **10** (revise the §-top axis line accordingly at implementation).

### 4.5 Non-goals (held lines — [[project_ai_session_observation_arc]])
- **No pricing / cost / budget / "expensive" labels** — external knowledge, consumer's job.
- **No content semantics** — topic, sentiment, "what was discussed" (not deterministic, not ours).
- **No tool arguments** — the tool-use *inventory* (names + counts) is a **later increment**, and
  even then it emits **names only, never args** (args carry paths/cwd/secrets/MCP infra → sensitive
  surface leak; same reason fo bounds preview). Flagged here so the boundary is set arc-wide.
- **No model inference** — the fingerprint identifies the *schema/tool*, never asserts the model ran.

### 4.6 Determinism
New detection/fingerprint rules (the producer table, the usage-key mapping, the gate constants) feed
`CHATLOG_RULES_DEFINITION` → `rules_hash`, and `CHATLOG_METHOD_VERSION` 10 → 11 (or the `ai_session`
vector's own fingerprint under decision A). Untrusted-log integers are **validated/bounded** at the
capture-metadata hardening bar (non-int/negative/overflow usage values → skipped, never crash, never
poison a sum). Workers=1-vs-N byte-identical (the standing Layer-A gate).

## 5. Version axes & why
- **LOGIC 1.16.0 → 1.17.0** — new observed values move `manifest_checksum` on agent-log corpora
  (the v1.29 precedent: a chatlog/AI-log observation change bumps LOGIC even when additive).
- **SCHEMA 1.18 → 1.19** — a new namespace / new fields = an additive contract change (the
  v1.24/v1.25 precedent), all fields **provisional** (season first).
- **chatlog method_version 10 → 11** — the rules set grows (or a new `ai_session` vector id/mv under A).

## 6. Reconstructibility & safety recap (the contract fo commits to)
1. Every derived aggregate is a pure function of observed bytes, with the source cited → parts
   recoverable; no aggregate hides a judgment.
2. fo surfaces vendor self-claims (`model`, version tokens) **raw and untrusted**; fo's own
   classification is **rules_hash-versioned** so its drift is dated and visible.
3. fo never crosses into the semantic layer (price/label/topic) — that is the consumer's whole lane.
4. Untrusted-log parsing is bounded/never-crash/validated (the capture-metadata bar).
