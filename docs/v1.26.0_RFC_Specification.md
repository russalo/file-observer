# v1.26.0 RFC — One-call public API (`scan` / `scan_to_json`)

**Status: APPROVED (Russell, 2026-06-26).** RFC normative language per BCP 14.

| Axis | Current (v1.25.1) | Proposed (v1.26.0) |
|---|---|---|
| SCANNER | 1.25.1 | 1.26.0 |
| LOGIC | 1.14.1 | 1.14.1 (unchanged) |
| SCHEMA | 1.16 | 1.16 (unchanged) |

## 1. Summary

Add a top-level convenience API so the front door for the common case is one call:

```python
from file_observer import scan, scan_to_json, manifest_to_json

m = scan("./folder")                          # -> ScanManifest, sane defaults
m = scan("./folder", specialists=True, workers=4)
text = scan_to_json("./folder")               # -> str (manifest_to_json(scan(...)))
```

Today the only entry point is `Scanner(source_dir=Path(p), config=ScannerConfig(...)).scan()`
— too much ceremony for "just give me the manifest." `scan()` is a thin wrapper over
exactly that; the explicit form stays for full control.

## 2. Motivation

First aim of the adoption-by-lowering-barriers track. The import/Python API is **not**
under the manifest contract (the v1.0.1 precedent — the *manifest* is frozen, the import
path is not), so this is the cheapest, lowest-risk, broadest-serving move: it helps the
largest single audience (Python pipeline/script authors) and is the ergonomic base every
later integration (a RAG router, an Airflow/Dagster operator, the examples, a GitHub
Action's Python path) sits on. It carries **no positioning risk** — it doesn't touch what
FO observes, only how you call it.

## 3. Design

- **`scan(path, *, specialists=False, workers=1, **config_kwargs) -> ScanManifest`** —
  builds `ScannerConfig(enable_specialists=specialists, workers=workers, **config_kwargs)`
  and returns `Scanner(Path(path), cfg).scan()`. `specialists`/`workers` are the friendly
  aliases for the two most common opts (`enable_specialists` is the verbose internal name);
  `**config_kwargs` passes through to `ScannerConfig` for power users (a bad/duplicate key
  raises the dataclass's own clear `TypeError`).
- **`scan_to_json(path, **kwargs) -> str`** — `manifest_to_json(scan(path, **kwargs))`, for
  the "one call → JSON string" want. (jsonl/markdown stay available via the existing
  `manifest_to_jsonl`/`manifest_to_markdown` on the returned manifest.)
- Defined in `scanner.py` (so the legacy `scanner` shim re-exports them too) and added to
  `file_observer.__init__.__all__`.

## 4. Observable surface

**None.** This is a Python-API addition only — no manifest field, vector, namespace,
specialist, or `--schema` surface changes. The CLI is unchanged.

## 5. Version-axis impact

- **SCANNER 1.25.1 → 1.26.0** — a new public API surface = a minor (the v1.9 `--workers` /
  v1.11 `--watch` precedent: a feature with no manifest change).
- **LOGIC 1.14.1 unchanged** — no routing logic changes.
- **SCHEMA 1.16 unchanged** — the manifest is byte-identical; `scan(p)` MUST produce the same
  manifest as the explicit `Scanner` path (the falsifiable contract).

## 6. Falsifiable contract

`tests/test_v1_26.py`, written failing-first: `scan(p)` and
`Scanner(Path(p), ScannerConfig()).scan()` produce **byte-identical** manifests
(`manifest_checksum` equal); `specialists=`/`workers=` map to the right config;
`scan_to_json(p) == manifest_to_json(scan(p))`; `scan` and `scan_to_json` are importable
from `file_observer` and `__all__`; a passthrough kwarg reaches `ScannerConfig`.

## 7. Review plan

Lighter than an extraction minor — the manifest is provably unchanged. Leg-1 in-house
swarm + leg-4 PR bots; falsify-first throughout. A corpus sweep is redundant (no manifest
change; the byte-identical test *is* the determinism proof) but the standing Layer-A gate
still runs in CI. No new untrusted-input parser → no red-team leg needed.
