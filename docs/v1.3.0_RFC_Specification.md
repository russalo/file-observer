# File Observer v1.3.0 RFC Specification

## 1. Overview

### 1.1 Purpose

Give File Observer a **content-based MIME fallback that needs no system library**, so it produces useful content-derived MIME types even when `libmagic` (the C library behind `python-magic`) is absent — common on Windows and in minimal containers. Today such environments drop straight to **extension-only** inference, which misreads renamed files and yields `application/octet-stream` for extensionless ones. This is an adoption win: `pip install file-observer` "just works" with meaningful MIME detection, no system dependency.

The fallback is **pure-Python and in-tree** — it reuses the magic-byte sniffer the scanner already runs (`MAGIC_SIGNATURES` → `file_signature`/`format_signatures`), extended with common signatures, rather than adding a dependency (`puremagic`/`filetype`). This is the altitude-correct move: generalize an existing mechanism.

### 1.2 What v1.3 does

- **(a)** Inserts a content-based magic-signature tier into `detect_mime`, between `libmagic` and the extension fallback.
- **(b)** Expands `MAGIC_SIGNATURES` with ~24 common formats (archives, images, data, executables, media).
- **(c)** Generalizes the signature matcher to support **multi-constraint** signatures, disambiguating the RIFF container into `image/webp` / `audio/wav` / `video/x-msvideo`.
- **(d)** Adds a distinct provenance trigger (`magic_signature_fallback`) so consumers can tell content-sniffed MIME from extension-guessed MIME.

Because `MAGIC_SIGNATURES` also feeds `file_signature`/`format_signatures`/polyglot detection, (b)+(c) **also enrich those signals** — a deliberate, beneficial side effect (see §6, §7).

### 1.3 Normative Language

MUST / SHOULD / MAY per BCP 14.

## 2. MIME Detection Cascade (a, d)

`detect_mime(path)` MUST resolve MIME in this order, recording the tier in `signal_provenance`:

1. **libmagic** (`self._magic.from_file`) — unchanged. trigger `libmagic`.
2. **magic-signature sniff** (NEW) — read the head sample, test it against `MAGIC_SIGNATURES`; the first signature whose constraints match AND whose label is a valid MIME type (contains `/`) wins. trigger `magic_signature_fallback`.
3. **extension** (`mimetypes.guess_type`) — unchanged. trigger `extension_fallback`.
4. **`application/octet-stream`** — unchanged.

The sniff tier MUST run both when `libmagic` is unavailable AND when `libmagic` raises (today both go straight to extension). It MUST operate on the already-read head sample (no extra I/O). It MUST be deterministic (fixed in-tree table). Non-MIME signature labels (e.g. `riff_container`, a generic RIFF with no recognized sub-marker) MUST be skipped by the MIME cascade (they remain available to `format_signatures`).

### 2.1 Text-gate (added in multi-agent review)

A content MIME from magic bytes is only trustworthy for NON-text content. Short ASCII magic prefixes (`MZ`/`BM`/`ID3`/`BZh`) otherwise misclassify ordinary prose (`"BM25 is a ranking function…"` → `image/bmp`) on the libmagic-absent path. Therefore `_sniff_mime` MUST return `None` for samples that `looks_like_text()`, deferring to the extension tier. Consequences: (1) `%!PS` PostScript (a text format) is `format_signatures`-only — not MIME-sniffed for real text content; (2) the `reason` detail distinguishes `libmagic_unavailable` / `libmagic_empty` / `libmagic_exception`; (3) `_signature_matches` returns `None` for empty constraints (never a spurious match at offset 0).

## 3. Multi-Constraint Signature Matcher (c)

`MAGIC_SIGNATURES` entries are generalized from `(bytes, offset, fmt)` to `(constraints, label)` where `constraints` is a tuple of `(offset, pattern)`; ALL constraints MUST match for the signature to fire. `offset` is an `int` (anchored) or `None` (pattern occurs anywhere in the head sample). Single-pattern formats become one-constraint entries; this is behavior-preserving for every existing entry. Signatures MUST be tested in list order, so **more specific signatures precede more general ones** (RIFF sub-types before the generic RIFF entry). `scan_signatures` is updated to the new structure; `file_signature.magic_bytes` (head hex) is unchanged.

## 4. Expanded Signature Table (b, c)

All entries below are added/retained. ⚠️ marks short (2–3 byte) signatures with moderate false-positive risk — acceptable because the sniff is a **fallback** (libmagic wins when present) and is anchored at offset 0.

**Retained:** `image/png`, `image/jpeg`, `application/pdf`, `application/zip`, `application/x-ole-storage`, `application/rtf`, `image/gif` (×2).

**RIFF (multi-constraint; specific before generic):**
- `RIFF`@0 + `WEBP`@8 → `image/webp`
- `RIFF`@0 + `WAVE`@8 → `audio/wav`
- `RIFF`@0 + `AVI `@8 → `video/x-msvideo`
- `RIFF`@0 → `riff_container` *(non-MIME; format_signatures only)*

**Archives / compression:** `\x1f\x8b`→`application/gzip`; `BZh`⚠️→`application/x-bzip2`; `\xfd7zXZ\x00`→`application/x-xz`; `7z\xbc\xaf\x27\x1c`→`application/x-7z-compressed`; `\x28\xb5\x2f\xfd`→`application/zstd`; `Rar!\x1a\x07`→`application/vnd.rar`.

**Images / data:** `II*\x00` & `MM\x00*`→`image/tiff`; `BM`⚠️→`image/bmp`; `SQLite format 3\x00`→`application/vnd.sqlite3`; `PAR1`→`application/vnd.apache.parquet`.

**Executables / docs:** `\x7fELF`→`application/x-elf`; `MZ`⚠️→`application/vnd.microsoft.portable-executable`; `%!PS`→`application/postscript`.

**Media:** `ftyp`@4→`video/mp4`; `\x1aE\xdf\xa3`→`video/x-matroska`; `ID3`⚠️→`audio/mpeg`; `fLaC`→`audio/flac`; `OggS`→`audio/ogg`.

## 5. Schema & Version Constants

- `SCANNER_VERSION` 1.2.4 → **1.3.0** (new capability).
- `LOGIC_VERSION` 1.1.4 → **1.2.0** (new MIME-detection routing + enriched signature detection — minor logic change).
- `SCHEMA_VERSION` **1.2 (unchanged)** — no new manifest fields. The new `signal_provenance.trigger` value `magic_signature_fallback` is a new value of an existing free-string field, not a schema change.
- `mime_analysis` comparison logic unchanged (still detected-vs-extension).

## 6. Backward Compatibility

- **libmagic environments: NO behavior change** — libmagic remains the primary path; the sniff tier is reached only on its absence/failure.
- **No-libmagic environments: behavior improves** — content MIME for ~24 formats instead of extension-only. This is the intended `LOGIC` change; `ScanContext.dependencies.magic.available=false` already explains the variance per the determinism pillar.
- **`format_signatures` / `file_signature` / `is_polyglot` are enriched** — files matching new signatures now report them. `format_signatures` is a **stable** field; this is an additive content change (more true signatures detected), tracked by `LOGIC_VERSION`. Golden manifests MUST be regenerated; the diffs MUST be reviewed to confirm every change is a correct new detection, not a regression.
- No manifest field is removed, renamed, or retyped. v1.0 public contract holds.

## 7. Validation Plan

- **No-libmagic simulation:** force `self._magic = None`; assert content MIME for one fixture per new format (png-renamed-`.dat` → `image/png`, extensionless gzip → `application/gzip`, etc.), and that text files still route via extension.
- **RIFF disambiguation:** WAV/AVI/WebP fixtures → correct specific MIME; a bare-RIFF/unknown-subtype → falls through to extension (not `riff_container` as MIME).
- **libmagic unchanged:** with libmagic present, MIME and provenance trigger are identical to v1.2.4 (regression guard).
- **Determinism:** same bytes → same MIME + same `format_signatures` across hash seeds.
- **False-positive guard:** a corpus sweep (`scratch/review/`) confirms no spurious flips on the real library; golden regen reviewed.
- **Empirical:** run against a no-libmagic venv over the corpora; compare MIME coverage vs the v1.2.4 extension-only fallback.

## 8. Acceptance Criteria

1. `detect_mime` yields content-based MIME for every §4 format with libmagic disabled; trigger `magic_signature_fallback`.
2. RIFF resolves to webp/wav/avi; unknown RIFF does not surface a non-MIME MIME.
3. libmagic-present behavior byte-identical to v1.2.4.
4. `format_signatures` enrichment verified correct; goldens regenerated and reviewed.
5. Determinism property holds; full suite green; corpus sweep clean (no FN regressions).
6. Versions bumped per §5; HISTORY/CONVENTIONS/CLAUDE.md/PUBLIC_CONTRACT updated; COMPLIANCE-v1.3 written.
