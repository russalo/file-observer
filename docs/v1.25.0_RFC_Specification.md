## 1. Summary

Two formats, the lone net-new parser surface from Candidate B:

- **`.mp3` → new `audio` namespace** — `format`, `bitrate`, `duration_s`, and ID3
  tags `title`/`artist`/`album`/`year`. ID3v2 (size-prefixed head) + a **bounded
  MPEG frame-header** read. This is the **only genuinely new untrusted-binary
  parser** in Candidate B — it carries the never-crash/bounded bar from commit
  one and is the priority red-team target.
- **`.ppt` → extends the `presentation` namespace** — `title`/`author`/
  `application`/`slide_count` via the OLE2 `SummaryInformation` /
  `DocumentSummaryInformation` streams. Reuses the proven `olefile` path
  (`.doc`/`.xls`/`.msg`), so it carries near-zero new parser risk.

## 2. Motivation

Completes the Candidate B family — the same **readiness + consumer-positioning**
rationale as v1.24 (RFC §2): build what's ready, position FO's surface for a
future consumer; honestly additive (recognition already works). `.ppt` is the
last office sibling FO recognizes-but-doesn't-extract; `.mp3` adds the audio
family. Phased here (not in v1.24) precisely so the one net-new parser lands on
its own minor with its own focused hardening.

## 4. Design

### 4.1 `.mp3` — the `audio` namespace (new)

- **ID3v2** (`ID3` at offset 0, size-prefixed synchsafe length): read `TIT2`
  (title), `TPE1` (artist), `TALB` (album), `TYER`/`TDRC` (year). Frames are
  size-declared → bounded by the declared sizes, capped to the read window.
- **MPEG audio frame header** (first valid `0xFFE` sync past any ID3v2 tag):
  decode version/layer → `format` (e.g. `mp3` / `mp2`), `bitrate`,
  `sample_rate`. `duration_s`: from a `Xing`/`Info` VBR header if present (frame
  count × samples-per-frame ÷ sample_rate); else a CBR estimate
  (`(file_size − tag_bytes) × 8 / bitrate`). Best-effort, honest-null when the
  header is absent/ambiguous.
- **Bounds (MUST):** read a bounded head (the existing image-metadata 1 MiB head
  pattern or a dedicated audio cap); reject implausible bitrate/sample-rate;
  never trust a declared ID3/frame size past the buffer; cap the
  sync-search/frame-walk window; the whole path inside the per-file try →
  `ErrorRecord`, never a raise. No wall-clock / nondeterministic value emitted.

### 4.2 `.ppt` — extend `presentation` (OLE2)

- `olefile` (optional dep, already gated for `.doc`/`.xls`/`.msg`). Read
  `\x05SummaryInformation` → `title` (PIDSI 0x02), `author` (0x04), `application`
  (PIDSI_APPNAME 0x12); `\x05DocumentSummaryInformation` → `slide_count`
  (PID_SLIDECOUNT 0x07). Honest-null per field when absent. No new parser — the
  OLE2 property path is the v0.7/v1.10 machinery.

## 5. Observable surface

- **`audio`** *(new namespace, SCHEMA 1.15→1.16)* — `format`, `bitrate`,
  `duration_s`, `title`, `artist`, `album`, `year`. All **provisional** on
  arrival.
- **`presentation`** *(extend)* — `.ppt` populates the existing `slide_count`/
  `title`/`author`/`application` fields (no new field; a new *source* + the
  `.ppt` extension routes to the namespace).

`application` (mp3 has none; ppt's producing app) feeds the `provenance` vector
where present — **same deferral as v1.24**: presentation→provenance harvest stays
deferred (would move the provenance `rules_hash` for every manifest); not in this
RFC.

## 6. Version-axis impact

- **SCHEMA 1.15 → 1.16** — the new `audio` namespace + fields (contract-shape
  change). Regenerate `docs/SCHEMA.md`; the completeness tests enforce it.
- **LOGIC 1.13.0 → 1.14.0** — `requires_specialist_tool` flips `False→True` for
  `.mp3` and `.ppt` (routing change, the v1.16/v1.24 precedent).
- **SCANNER 1.24.0 → 1.25.0.** New `audio` fields provisional; not byte-identical
  on corpora containing `.mp3`/`.ppt`. No existing field changed/removed/retyped.

## 7. Safety — the `.mp3` parser is the priority target (MUST)

The `.mp3` frame/ID3 parser is the only net-new untrusted-binary surface since the
v1.16–1.20 capture-metadata arc. It MUST carry the full v1.8.1 discipline from the
first commit (bounded reads, capped loops/allocations, reject hostile sizes,
fail-closed → `ErrorRecord`, deterministic). The capture-metadata hardening guard
(`tests/test_capture_metadata_hardening.py`) SHOULD be extended to cover it, and
**the bestiary decorrelated-fuzz leg SHOULD run on `.mp3` before promotion past
provisional** (the v1.24 RFC flagged this as the gating step). `.ppt` reuses the
hardened `olefile` path — no new bound to establish.

## 8. Falsifiable contract

`tests/test_v1_25.py`, written failing-first: ID3 tags + frame-derived
format/bitrate/duration extracted to known values on built `.mp3` fixtures; OLE2
`.ppt` title/author/application/slide_count on a built fixture;
`requires_specialist_tool == True` for both; honest-null (not a guess) on
headerless/garbled audio and on absent OLE2 properties; never-crash on a corrupt
`.mp3` (truncated sync, lying ID3 size) and `.ppt`; determinism (workers 1-vs-N
byte-identical) on a corpus with both.

## 9. Resolved decisions (Russell, 2026-06-26 — all at the draft leans)

1. **Audio depth = INCLUDE** frame-derived `format`/`bitrate`/`duration_s` (bounded
   first-frame-header read) alongside the ID3 tags.
2. **`.ppt` slide_count = best-effort INCLUDE** (from `DocumentSummaryInformation`).
3. **Audio MIME guard = TIGHT** (`audio/mpeg` only; the headerless mp3 stays
   honest-null, not extracted).
