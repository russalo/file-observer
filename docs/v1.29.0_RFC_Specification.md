# RFC: v1.29.0 — Chatlog detection recognizes agentic (tool-turn) sessions

**Date:** 2026-06-27
**Version axes:** SCANNER 1.28.1 → 1.29.0 · LOGIC 1.14.1 → **1.15.0** · SCHEMA unchanged **1.16** · chatlog method_version 9 → **10**

## 1. Summary

Chatlog content-detection (`is_chatlog`) currently counts a turn as a "message"
only if it yields extractable **prose text**. In agentic Claude Code session logs
the turns are dominated by non-prose content blocks — `thinking`, `tool_use`,
`tool_result` — which carry no top-level `text`, so they go **uncounted**. A
tool-heavy session can fall below the `≥3 messages, ≥2 speakers` threshold and be
**false-negatived**, even though it is unmistakably a conversation.

This RFC relaxes the turn-recognition gate to count a turn when it has a
conversational **role** AND content that is either a string OR carries a
**recognized content-block type**. This recovers agentic sessions while staying
false-positive-clean on structured JSON that merely has conversational-looking
roles (telemetry, RBAC data, function-call logs). The same recognition is applied
to **extraction** (§4): the chatlog turn-counting signals now count tool turns too,
so the vector reflects the full agentic rhythm — not only the prose turns.

Detection + signal-extraction change → **LOGIC 1.15.0** (the v1.2 / v1.4 precedent:
a chatlog-detection change bumps LOGIC + chatlog method_version). No new field →
**SCHEMA unchanged**. Note (§5): because extraction extends, the chatlog signal
*values* (and the vector `identity_digest`) move for already-detected agentic logs,
not only the newly-detected ones.

## 2. Motivation — measured on the real federation corpus (measure-first)

Driver: item #1 (chatlog non-count work) now serves **two** consumers — Sentinel
and **recall** (which searches the federation chatlog corpus). A measure-first
pass on that real corpus (`scratch/chatlog_corpus_findings_2026-06-27.md`) found:

- **FN: 5/28 `.jsonl` session logs missed** by `is_chatlog` (18%). 2 are tiny stub
  sessions (≤1–2 turns — correct non-detection); **3 are substantial real dev-session
  logs (2.6 / 25.6 / 139 MB)** — genuine false negatives.
- **FP: 0/31** real corpus/project docs.

**Root cause (grounded; two false leads ruled out):** not the read window (detection
reads the first 64 KB via `baseline_max_bytes`, and the misses have 8 `user` + 5
`assistant` records in that window), but **text-centric turn counting**. On the
25.6 MB miss, only **2 of 13** turns in the first 64 KB were counted (one opening
user prompt + one assistant text reply); the rest were `thinking` / `tool_use` /
`tool_result` turns with no `text` block. 2 < 3 → `is_chatlog=False`. The more
agentic the session, the more it's missed — a **widening** gap, since agentic
sessions are now the norm.

## 3. Design

### 3.1 The change

Today (`_message_role_content`) a turn counts only if a content field yields a text
string (directly, or via content blocks carrying a top-level `text` key). Change:
add a **detection-recognition predicate** that counts a turn when BOTH hold:

1. **Conversational role** — a role field (`type`/`role`/`from`/`speaker`/`author`)
   whose value is conversational (for `type`, ∈ `CHATLOG_CONVERSATIONAL_TYPE_VALUES`;
   the existing v1.2.1 gate, unchanged).
2. **Recognized content** — a content field (`text`/`value`/`content`/`message`/`body`)
   present and EITHER (a) a non-empty string, OR (b) a list of content blocks
   recognized by either of two arms:
   - **text-bearing** — any block with a string `text` value (any/no type). The
     pre-v1.28 behaviour; yields prose. **(backward-compat)**
   - **distinctive agentic** — a block of a closed set `CHATLOG_AGENTIC_BLOCK_TYPES
     = {thinking, tool_use, tool_result}` — the Anthropic-distinctive types that
     essentially never appear in non-dialogue JSON. Recovers tool-heavy turns.

The distinctive-agentic arm is the new surface. The string + text-bearing arms are
today's behaviour (ConvoKit / ShareGPT / oasst / untyped text blocks), preserved —
so the gate is a **strict superset** of v1.28 and `is_chatlog` never flips True→False.

> **Reversed at review (leg-1, §8.1):** the first cut included the GENERIC block
> types `image`/`document`/`text` in one recognition set. Leg-1 found `image`/
> `document` **false-fire** on non-dialogue JSON (image galleries, document stores,
> typed telemetry) for **zero** agentic-recovery value (the 3 real misses recover
> via `thinking`/`tool_use`/`tool_result`), and that keying prose on `type=="text"`
> **regressed** untyped text blocks (True→False). The fix: the distinctive set above
> + a text-bearing arm (any string `text`, restoring backward-compat). `image`/
> `document` are NOT recognition triggers.

### 3.2 Why a recognized-block-type set, not "any content present"

A falsify-first probe (`scratch/falsify_toolturn_gate.py`) tested two candidates:

| Candidate | 3 real misses | adversarial (telemetry/RBAC/func-call/metrics) | 31 real docs | 28-log regressions |
|---|---|---|---|---|
| LOOSE (role + any content) | ✅ recover | ❌ **false-fires on all 4** | 0 | — |
| **TIGHT** (role + string OR recognized block type) | ✅ recover all 3 | ✅ **clean on all 4** | 0 | **0** |

The naive "any content present" relaxation **false-fires** on structured JSON that
has conversational-looking roles (`type:system/tool/function` telemetry, `role`-keyed
RBAC/permissions data, function-call logs) — exactly the FP class falsify-first exists
to catch. Gating on a recognized content-block vocabulary rejects all of them
(their content is config dicts / scalar arrays, not typed blocks) while recovering
every real agentic session. TIGHT is a **strict superset** of the current gate
(it only ever counts MORE), so it cannot regress a currently-firing log — confirmed
**0 regressions** across all 28 logs (current 23/28 → TIGHT 26/28; the 2 remaining
misses are the tiny stubs).

### 3.2a Detection requires ≥1 prose turn (leg-2 hardening)

Leg-2 (Gemini cross-model) found that a **pure tool-execution / RPA / workflow log**
— role-keyed records whose turns are all `tool_use`/`tool_result` blocks (zero
prose) — false-fired (≥3 records, ≥2 distinct roles, but no language). Fix:
`_detect_conversational_json` additionally requires **≥1 recognized turn with
actual prose**. A real conversation always opens with a human prose prompt, so this
never drops a genuine session (corpus-verified 26/28 unchanged); a pure tool log has
no prose and is rejected. Also from leg-2: generic `image`/`document` **captions**
are excluded from the text-bearing arm (`CHATLOG_GENERIC_BLOCK_TYPES`), and an
empty-prose agentic turn no longer hides a sibling prose string (recognition scans
all content keys before returning empty).

### 3.3 Determinism — the block-type sets are fingerprinted

`CHATLOG_AGENTIC_BLOCK_TYPES` (and `CHATLOG_GENERIC_BLOCK_TYPES`) are closed
rule-data sets that gate output, so they MUST feed the chatlog vector's `rules_hash`
(the v1.6 provenance-table / chatlog-`fp_lexicon` precedent —
[[project_rules_fingerprint_lens]]): a live-derived fingerprint that falsifies both
fabrication AND silent edits to the sets. Bump chatlog **method_version 9 → 10**.

## 4. Scope — detection AND extraction (review §8.2: extend)

Both the `is_chatlog` recognition gate AND the chatlog signal extraction adopt the
TIGHT predicate, so the vector reflects the full agentic conversation, not only its
prose turns. The **turn-counting** vs **prose-text** split is the principle:

- **Turn-counting signals — count ALL recognized turns** (text + tool):
  `turn_count`, `speaker_turn_counts`, `alternation`. A `tool_use` / `tool_result` /
  `thinking` / `image` / `document` turn is a real conversational turn and is counted.
- **Prose-text signals — extract authored language only:** `speaker_turn_chars` /
  char stats, `vocabulary_size_estimate`, `top_capitalized_tokens` draw text from
  **string content + `text` blocks + `thinking` blocks** (the human/model prose,
  thinking-reasoning included). Structured/binary blocks contribute the **turn** but
  **no prose**: `tool_use` input (serialized args — not authored language),
  `tool_result` output (tool output, can be huge logs — excluded to keep
  vocabulary/char drift meaningful), `image` / `document` (no text). **Decision:**
  `tool_result` text is excluded from prose signals (it's tool output, not
  conversation) — flagged here so review can override if a consumer wants it counted.

So a tool-heavy turn increments `turn_count` (+1) and `speaker_turn_counts`, but
adds 0 to char/vocabulary unless it carries a `text`/`thinking` block.

Non-goals (unchanged):

- **(B) prose / markdown non-count discrimination is OUT** — the original #1 thesis
  (terse dialogue vs data tables, adversarial inputs) stays **RPG-corpus-gated**;
  this federation corpus is ~all one format and can't size it.
- **Tiny stub sessions stay un-detected** — ≤1–2-turn logs (e.g. a 237 B
  `last-prompt`+`permission-mode` stub) are correctly below threshold.

## 5. Consumer impact

- **recall (v0.2.0)** — unaffected at runtime: it uses `trellis index --mode jsonl`,
  which keys turns off the `type` field directly and never inherited fo's
  text-centric counting. But fo's now-correct `is_chatlog` is the bridge to the
  NON-jsonl transcripts `--mode jsonl` skips — the original "#1 helps recall" thesis.
- **Sentinel** — `CHATLOG_SPEAKER_LABEL_RE` (the soft external contract, mirrored in
  `backend/datasets.py`) is **untouched** — this RFC changes only JSON turn-counting,
  not the prose speaker-label regex. No coordination needed for this change.
- **Any `is_chatlog` consumer** — more agentic logs now correctly flagged; strictly
  additive (null/False → True), no file flips True → False.
- **Chatlog-signal / vector consumers (extraction extended)** — `turn_count` and the
  speaker signals **increase** for already-detected agentic logs (tool turns now
  counted), and the chatlog vector `identity_digest` moves on agentic corpora. This
  is the larger surface of this release: not just 3 newly-detected files, but the
  signal *values* of every agentic session. `manifest_checksum` moves for any corpus
  containing agentic chatlogs. Method_version 9→10 signals the recount to consumers.
