# v1.48.0 — Download-origin observation (xattr / ADS)

**Status: SHIPPED** — released as v1.48.0 (see `docs/HISTORY.md` for the date and the patch releases that rode on this minor). The status line below is the RFC's state at approval time, kept as written.

**Status (at approval time):** APPROVED 2026-08-05. All four §8 decisions resolved.

## 1. Summary

Observe whether a file **arrived from outside the machine**, by reading the
filesystem's download markers: macOS `com.apple.quarantine`, Windows
`Zone.Identifier` ADS, and (best-effort) Linux `user.xdg.origin.url`.

This is the signal the file's *content* cannot carry. A PDF rewritten by a
document-management pipeline loses its producer, its CAD provenance, and any
embedded origin — but the filesystem still records that it came off the internet,
and which agent fetched it.

New provisional `origin` block on `FileRecord`. Surfaces the **flag and the class,
never the URL** — the same line fo already draws at `gps_present`.

## 2. Provenance & grounding (measure-first)

Measured 2026-07-16 by Tailnet on a real macOS host (MacBook Neo, APFS), **5,000
real files** across `~/Downloads`, `~/Documents`, `~/Desktop`:

| Attribute | Coverage | Verdict |
|---|---|---|
| `com.apple.quarantine` | **4952 / 5000 (99%)** — flag + downloading agent (Chrome 4935, Messages, Safari…) | **Rich and near-universal. Build on this.** |
| `com.apple.metadata:kMDItemWhereFroms` (origin URL) | **18 / 5000 (0.36%)** | **Too sparse to design around.** Do not depend on it. |
| `com.apple.provenance` | 54 | Newer, thin. Out of scope. |
| `com.apple.macl` | 35 | Access-control, not origin. Out of scope. |

The 0.36% figure is load-bearing: it retires the obvious design ("record where it
was downloaded from") before any code is written. macOS writes the *flag* almost
always and the *URL* almost never.

**Consumer demand (2026-08-05).** TrenchIQ ingests construction documents that
arrive from owners, engineers, and agency portals. Its I8 invariant requires
document lineage, and §10.2 already specifies content hashing for chain of custody.
A measurement on real CP plan PDFs found the document's own provenance **destroyed
upstream** — no CAD producer survives, only whatever last rewrote the file. The
filesystem marker survives that rewrite. The same tree also carries `~BROMIUM/`
download-isolation folders throughout, which is the Windows analog's population.

This satisfies the candidate's recorded promotion trigger verbatim: *"Russell
greenlights opening the arc, OR a consumer asks for download-provenance to gate
trust."* Both.

## 3. Design

### 3.1 Allowlist, never enumerate — the load-bearing constraint

fo reads **only a fixed allowlist** of known origin attributes. It does not
enumerate a file's extended attributes and report what it finds.

This is not an optimisation. Enumerating would pour arbitrary third-party metadata
— Finder tags, app-private state, whatever any tool chose to attach — into a
manifest that consumers feed to models. It is unbounded in size, unbounded in
content, and impossible to trust-classify ahead of time. A three-key allowlist is
bounded, classifiable, and reviewable.

An extended-attribute namespace is the **first open channel fo has ever read** —
every other source (the data fork, POSIX stat, platform FS attributes, tree
position) has fixed, closed semantics, while any application may write any xattr
key. The allowlist exists precisely to close that openness back down.

#### The admission rule

The allowlist will come under permanent pressure — every future consumer wants one
more key. An attribute is admissible **only if all four hold**:

1. **Documented, fixed semantics** — a published meaning, not a free-form field.
2. **Bounded** — small and of known shape.
3. **About origin or integrity** — not a user's annotation.
4. **Named, never enumerated** — fo reads specific keys; it never lists what is present.

This admits `com.apple.quarantine`, `Zone.Identifier`, and `user.xdg.origin.url`.
It excludes Finder tags, `user.comment`, SELinux labels, and arbitrary app state.

Note criterion 1 is *documented semantics*, deliberately **not** *"written by the
OS"* — `user.xdg.origin.url` is written by Firefox/wget rather than the kernel, and
an OS-authorship test would have excluded it while admitting nothing safer. The
property that matters is whether the meaning is fixed, not who wrote it.

### 3.2 The `origin` block

Named `origin`, **not** `provenance` — that word is already taken twice in this
codebase (`signal_provenance` per-field derivation records, and the corpus-scoped
`provenance` vector). A third meaning would be a documentation hazard.

```
origin: {
  downloaded:   bool          # came from outside this machine
  zone:         str | None    # internet | intranet | trusted | restricted | local
  agent:        str | None    # the fetching application, when recorded
  acquired_at:  str | None    # ISO-8601 UTC, when the marker was written
  source:       str           # macos_quarantine | windows_zone_identifier | xdg_origin
}
```

**Always present; `null` when no marker was read.** This reverses the first draft
of this RFC (see §8 D5) — and the reversal came from implementation.

`null` is fo's established idiom for absence. Pillar 4 states it outright: *"Null
means 'not observed within bounds,' not 'not present in the file.'"* Omitting the
key would invent a second absence-idiom fo has never used at top level, and a
consumer writing `record["origin"]` would get a `KeyError` where every other fo
field yields `None`. Uniformity of shape is worth more than the drift it costs.

### 3.3 What is deliberately NOT surfaced

The origin **URL**, in every form: `kMDItemWhereFroms`, `ReferrerUrl`, `HostUrl`.

Two independent reasons, either sufficient:

1. **Empirically sparse** — 0.36%. A field that is null 99.6% of the time is not a
   contract worth freezing.
2. **It is exactly the payload class v1.40–v1.42 exists to contain.** A URL is
   attacker-controllable free text arriving from outside, which is the definition
   of `file_derived`. fo already declined to surface GPS *coordinates* while
   surfacing `gps_present`; this is the same call on the same principle.

A consumer that genuinely needs the URL can read the attribute itself. fo's job is
to say *that the file came from outside*, which is the routing-relevant part.

### 3.4 Platform paths

Three distinct code paths. There is no portable API.

| OS | Mechanism | Note |
|---|---|---|
| **macOS** | `libSystem` `getxattr` via **ctypes**, `XATTR_NOFOLLOW` | `os.getxattr` is **Linux-only in CPython** and raises `AttributeError` here — the portability fact that sizes this work. Tailnet's `scratch/xattr_measure_macos.py` is the reference adaptation. |
| **Windows** | Open the `<path>:Zone.Identifier` alternate data stream, parse the `[ZoneTransfer]` INI | `ZoneId` 0=local 1=intranet 2=trusted 3=internet 4=restricted |
| **Linux** | `os.getxattr(path, "user.xdg.origin.url")` — **presence only** | Non-standard; Firefox/wget/curl set it inconsistently. Best-effort. See D2. |

`XATTR_NOFOLLOW` / symlink handling: read the link's own marker, never the
target's. fo's v1.8.1 containment already refuses out-of-tree symlinks; this must
not become a way around that.

### 3.5 Quarantine value parsing

`com.apple.quarantine` is `flags;timestamp;agent;event-uuid` (hex;hex;str;uuid).
fo extracts the flag bit, the timestamp (→ ISO-8601 UTC), and the agent. The
event UUID is a machine-local identifier with no cross-machine meaning — dropped.

### 3.6 Trust classification (v1.40)

| Field | Class | Why |
|---|---|---|
| `downloaded` | **fo_derived** | boolean, cannot carry a payload |
| `zone` | **fo_derived** | closed enum fo assigns |
| `acquired_at` | **fo_derived** | normalized timestamp |
| `source` | **fo_derived** | closed enum |
| `agent` | **file_derived** | free text written by whatever fetched the file; an attacker who controls the download influences it |

Under `--trusted-only`, `agent` nulls and the rest survive — which is the useful
outcome: a safe-mode consumer still learns *the file came from the internet*
without ingesting an attacker-influenced string.

`FIELD_TRUST`'s completeness guard will fail the build until all five are
classified, so this cannot be forgotten.

### 3.7 Bounded observation & never-crash

- Cap every attribute read (**4 KiB**); a marker is tens of bytes and anything
  larger is hostile or broken.
- A malformed quarantine string, a truncated ADS, or a filesystem that does not
  support xattrs degrades to **no block**, never an exception.
- `ENOTSUP` / `ENODATA` are the *normal* case on most filesystems and must not
  produce `ErrorRecord` spray — silence, not diagnostics.
- A genuine read failure (permission denied on a file we could otherwise stat)
  earns one `ErrorRecord`, per the v1.8.1 per-file-degradation rule.

## 4. Versioning & contract impact

| Axis | Change |
|---|---|
| **SCANNER** | 1.47.1 → **1.48.0** |
| **LOGIC** | 1.24.6 → **1.25.0** — a new observation; values appear where none did |
| **SCHEMA** | 1.24 → **1.25** — new provisional block, additive |

**Blast radius — every manifest's checksum moves, once.** Because `origin` is
always present (§3.2), the key enters every `FileRecord` and therefore every
checksum preimage, on every platform, even where the value is `null`.

This is an **ungated one-time bump**, and fo has precedent with a name: the v1.15
`ScanContext` / v1.36 purexml-dep-record / v1.45 summary-exclusion class. It is
accepted here for the same reason — the alternative buys drift-avoidance by
breaking a stated pillar.

- **Values** are unchanged everywhere no marker exists; only the key is added.
- **macOS / Windows** additionally gain real values on the ~99% of files carrying a
  marker.
- **leg-3's job changes accordingly:** the sweep will drift on every corpus. The
  check is no longer "NO-DRIFT" but **"the diff is exactly the added `origin` key
  and nothing else"** — a weaker but still falsifiable claim, and the one that
  actually matches the design.

**Downstream note.** recall pins `file-observer>=1.46,<2`. A SCHEMA minor is
additive and inside that range, so this does not break the pin — but it is the
first release since that pin existed, and the omit-when-absent design means
recall's Linux corpora see no change at all.

### 4.1 A subtler determinism story — LIMITATIONS entry required

Pillar 1 still holds literally: identical inputs + identical `ScanContext` →
identical outputs. But **"identical inputs" quietly acquires a new component**, and
that must be written down rather than discovered.

Extended attributes and alternate data streams are **lost by ordinary file
operations**: `cp` without `-p`/`--preserve=xattr`, `rsync` without `-X`, `tar`
without `--xattrs`, and every `zip`. So the same bytes in two locations can
legitimately produce different `origin` blocks — and a tree that is archived and
restored may lose its origin markers entirely.

`mtime` already has this property, so the *class* is not new. What is new is the
**visibility**: an mtime change is expected and obvious, whereas a quarantine flag
silently vanishing because someone rsynced a directory is a surprise, and a
surprise in a determinism contract is a defect in the documentation.

`LIMITATIONS.md` gains an explicit entry: **origin markers describe the file *as it
exists on this filesystem*, not the file's history. Absence is not evidence the
file was not downloaded.** That asymmetry — present is meaningful, absent is not —
is the honest reading and consumers must be told it plainly.

### 4.2 Charter statement (PUBLIC_CONTRACT)

Investigating §8 D4 revealed that fo's read-channel boundary has **never been
written down**. The charter says *"observation layer only… not responsible for
ingestion, OCR, embeddings, or classification"* — which constrains
**interpretation**, and says nothing about which channels fo may read.

Meanwhile fo has read POSIX `stat` since v0.3 and platform-specific filesystem
attributes (`st_file_attributes`, `st_reparse_tag`) since **v1.46.0/v1.46.8**. So
this release does not widen the charter; it states a boundary already exercised.

`PUBLIC_CONTRACT.md` gains:

> **What fo reads.** The file's data fork; POSIX `stat`; platform-specific
> filesystem attributes where they are load-bearing for observation or containment;
> and a **named allowlist** of documented origin attributes (§3.1's admission rule).
> fo does not enumerate open metadata namespaces, and does not read a channel
> merely because it is readable.

## 5. Falsification (falsify-first)

Written failing, before implementation.

**Correctness**
- Synthesize known markers on Linux (`setfattr`) and assert the exact parse.
- A real quarantine string → exact flag/timestamp/agent extraction.
- A `[ZoneTransfer] ZoneId=3` stream → `zone: internet`, `downloaded: true`.

**Shape** — a file with no marker produces `origin: null`, present and null, never
absent. And a v1.47.1-vs-v1.48.0 diff over a marker-free corpus must contain
**exactly one change per record**: the added key. Any other delta is a defect.

**Hostile / bounded**
- A 10 MB xattr value → capped, no OOM.
- Malformed quarantine (wrong field count, non-hex, embedded NULs) → no block, no
  crash, no traceback.
- A marker on a symlink → the link's, never the target's.
- A filesystem without xattr support → silence, not `ErrorRecord` spray.

**Determinism**
- Same file + same markers → identical output across runs.
- `workers=1` vs `workers=4` byte-identical (the standing Layer-A gate).

**Trust**
- `--trusted-only` nulls `agent`, retains `downloaded` / `zone` / `acquired_at` /
  `source`.
- A distinctive marker string planted in `agent` must not survive safe mode — the
  v1.40 canary pattern.

**Cross-platform** — the CI OS matrix is the reviewer here, per the v1.15 lesson
that a native host finds what the Linux suite structurally cannot. macOS and
Windows legs are not optional for this release.

## 6. Review plan

Full four legs; this is a minor with a new read surface on untrusted input.

- **leg-1** in-house swarm — the allowlist boundary and the parse routines.
- **leg-2** cross-model — a different family on the hostile-input paths.
- **leg-3** corpus sweep — will drift on every corpus by construction (§4). The
  claim to falsify is that the drift is **exactly the added `origin` key**: no
  value changes, no routing flips, no other field touched.
- **leg-4** PR bots.
- **Native-host validation** — macOS and Windows behaviour verified on real
  hardware, not only in CI. Tailnet has both.

## 7. Considered & rejected

**Enumerate all extended attributes.** Rejected — unbounded content of unknown
provenance into a manifest consumers feed to models, and un-trust-classifiable in
advance. The allowlist is the design, not a limitation of it.

**Surface the origin URL** (`WhereFroms` / `ReferrerUrl` / `HostUrl`). Rejected on
two independent grounds (§3.3): 0.36% coverage, and it is the attacker-controllable
free-text class fo spent three releases learning to contain.

**Name it `provenance`.** Rejected — collides with `signal_provenance` and the
`provenance` vector.

**Use the `xattr` PyPI package for macOS.** Rejected — a new runtime dependency for
one syscall, against a project that has been *removing* dependencies (defusedxml →
purexml). ctypes is stdlib and the adaptation already exists.

**Read `com.apple.provenance` / `com.apple.macl`.** Rejected for now — 54 and 35
occurrences respectively, and `macl` is access-control rather than origin.

**Enumerate all Windows alternate data streams.** Rejected — and decided **now,
deliberately, while nobody is asking**, because the request is predictable and
would arrive with a good argument attached.

Once fo opens `path:Zone.Identifier`, *"list every ADS"* is the natural follow-up:
alternate data streams are a classic malware-hiding channel, and fo has a
forensics-adjacent audience (it was posted to r/computerforensics). The argument
will be reasonable. It is still refused, on the §3.1 admission rule — enumeration
fails criterion 4 outright, and a discovered stream's contents fail 1 and 2, being
of unknown semantics and unbounded size.

The deeper reason: that request asks fo to become a **forensic acquisition tool**,
which is a different product with a different threat model and a different duty of
care. fo screens files so a consumer can decide what to trust. Deciding *whether a
hidden stream is malicious* is interpretation, and interpretation is the one thing
the charter actually disclaims. A consumer needing full ADS enumeration should use
a forensics tool; fo will tell them the zone the file came from.

## 8. Decision log — RESOLVED 2026-08-05

**D1 — Default-on, or opt-in? → DEFAULT-ON.**
The omit-when-absent gate (§3.2) means every existing corpus stays byte-identical,
so the usual reason to gate — don't move everyone's checksum — does not apply. A
security-relevant signal that ships off-by-default is a signal nobody receives.

**D2 — Include Linux `user.xdg.origin.url`? → YES, presence-only.**
Flagged best-effort in `LIMITATIONS.md`, not a contract: the attribute is
non-standard and set inconsistently by Firefox/wget/curl. The URL itself is not
surfaced, per §3.3. See §3.1 for why the admission rule was reworded to
*documented semantics* rather than *OS-written* — an OS-authorship test would have
excluded this while admitting nothing safer.

**D3 — Keep `agent`? → KEEP**, classified `file_derived`.
It is the only untrusted field in the block. Under `--trusted-only` it nulls while
`downloaded`/`zone`/`acquired_at`/`source` survive, which is the useful outcome: a
safe-mode consumer still learns the file came from the internet without ingesting
an attacker-influenced string.

**D4 — Does this change fo's charter? → NO. It states a boundary already exercised.**

Investigated rather than assumed, and the investigation **corrected an error in
this RFC's own first draft**, which had asserted *"fo has always read the data fork
only."* Both halves of that were wrong:

- fo has read platform-specific filesystem attributes since **v1.46.0/v1.46.8**
  (`st_file_attributes`, `st_reparse_tag`, `scanner.py:229`/`:232`) — reads that
  change what appears in `files[]`. The boundary was crossed nine releases ago.
- The charter never said it. *"Observation layer only… not responsible for
  ingestion, OCR, embeddings, or classification"* constrains **interpretation**,
  not read-channel. Reading an OS-written origin marker is none of those four.

What *is* genuinely new is narrower than first framed: an xattr namespace is the
first **open** channel fo has read — any application may write any key, where every
prior channel has closed semantics. §3.1's allowlist and admission rule exist to
close exactly that, which is some evidence the design is aimed correctly.

So the deliverable is not a charter change but a **charter statement** (§4.2), plus
the admission rule (§3.1) and a pre-decided refusal of ADS enumeration (§7) — the
boundary drawn while nobody is pushing on it, which is the only good time.

**D5 — `origin` shape: always-present-null, NOT omit-when-absent. RESOLVED at
implementation time, reversing this RFC's own §3.2 first draft.**

Implementation found the gate unreachable as designed: fo serializes via `asdict()`
at both output sites and does **not** strip `None` — verified, `specialist_metadata`
emits as `null`. Omission would have required popping the key at two sites plus the
checksum preimage.

More importantly it would have **broken Pillar 4**, which names `null` as fo's
meaning-of-absence. The first draft optimised for a clean NO-DRIFT story and, in
doing so, would have introduced fo's first conditionally-absent top-level key and a
`KeyError` where consumers expect `None`.

Cost accepted: every manifest's checksum moves once (§4). This is the second time
in this RFC that checking a claim overturned it — the first being D4's data-fork
error. Both are recorded rather than edited away, because the RFC is the approval
artifact and a silent correction destroys its value as one.

**Consequential follow-ups accepted with D4:**
- `PUBLIC_CONTRACT.md` gains the "What fo reads" statement (§4.2).
- `LIMITATIONS.md` gains the origin-markers-are-lost-by-copy entry (§4.1), including
  the asymmetry that **present is meaningful, absent is not evidence**.
- `CLAUDE.md`'s one-line charter is left alone; it is about interpretation and
  remains accurate.
