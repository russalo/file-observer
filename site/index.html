Deterministic file observation for pipelines

One read-only pass over a directory, and you get back a single JSON manifest of every file: type, metadata, structure, and provenance.

Same bytes in, same manifest out — byte-identical no matter how many workers you scan with. So you can cache on it, diff it, and trust it as a stable step before ingestion.

pip install file-observer
GitHub PyPI Tutorial

What it is

Deterministic

The same bytes always produce the same manifest, down to a checksum — and it stays byte-identical across parallel workers. An enforced, tested contract, not a hope.

Content-detected

File type, MIME, and structure come from the actual bytes, not the extension. Rename a PNG to .txt and it's still reported as a PNG.

Self-describing

file-observer --schema makes the installed build print its complete output surface, so you can write a consumer without reading the source.

Observe, don't touch

Read-only. It never executes file content, opens a network connection, or modifies anything. It looks, it describes, and it changes nothing. Not a file watcher.

One pass, one manifest

$ file-observer ./your-project --specialists

Scanned 4,366 files (3,526 text, 840 binary) in 31 directories.
1,163 supported (336 with specialist metadata).
Quality: 676 clean, 3,690 degraded. 4 safety flags, 2 polyglots.

Manifest written to out/manifest_v<version>_<timestamp>.json
  → one FileRecord per file: checksum, content-MIME, routing flags,
    signal_provenance (how each derived field was derived), specialist metadata
  → a top-level manifest_checksum: scan the same bytes again, get the same value
